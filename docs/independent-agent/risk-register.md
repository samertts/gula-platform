# Risk register

Risks, not defects: things that make defects likely or hard to see.

| # | Risk | Why it matters | Mitigation |
|---|---|---|---|
| R-1 | **A route's signature does not tell you its authorization.** Router-level `dependencies=[...]` are the effective guard, and FastAPI binds a dependency's `citizen_id` parameter to the *path* id. | A signature scan reported 17 correctly-guarded PHI routes as unguarded. The same error in the other direction would report a live IDOR as safe. | Measure the served OpenAPI surface plus router-level dependencies; read the dependency body. Never conclude from the decorator. |
| R-2 | **Route existence is not capability.** `/reference/*` has 4 tenant-broken handlers and serves 0 paths; `/ehr/*` serves 54 paths over tables no migration creates. | Any count of endpoints, or of "features", overstates the platform. | Count served paths, and check the tables behind them exist. |
| R-3 | **Local suite counts are corruptible by the environment.** PostgreSQL is reclaimed mid-run and the failure presents as dozens of plausible test errors. | An 18-error environment failure was nearly committed as a regression. | Assert database reachability before collection; re-check `pg_isready` after any surprising error count. |
| R-4 | **Generated code is verified by generating it, not by reading it.** A repair to the capability generator was valid in its output and a `SyntaxError` in the template; the capability tests passed because they never import the generator. | A generator can be broken while everything downstream of its last run is green. | Generate into a temp directory and compile every emitted file. |
| R-5 | **Two lanes share one finding-number space.** 80 ids exist in both registers and 66 mean *different* findings; the fork is at NR-008. | A bare `NR-nnn` above NR-015 is ambiguous in both directions, including inside open PR bodies. | Cite the branch with the number. See `docs/architecture/CROSS_LANE_FINDING_ID_COLLISIONS.md`. |
| R-6 | **A self-certifying test is worse than no test.** Ten generated capabilities asserted their own hard-coded `{"success": True}`. | A passing suite counted them. | A test must be able to fail for the reason it exists; pin the honest state. |
| R-7 | **A missing schema masks every defect above it.** The `/ehr` surface fails at the first table lookup, so nothing downstream is ever reached: IA-005 breaks 59 of its 86 operations and was invisible until the tables were created in a throwaway database. | Fixing the schema will not make the surface work, and the defects it uncovers will appear to be *new* — introduced by the migration — when they have been latent all along. | When a surface fails closed on a missing table, probe the layers above it separately before estimating the remaining work. Never read "one migration away" off a `500`. |
| R-8 | **A weakly-typed probe database buys reachability and sells correctness.** The SQLite code-path run reached the serialisation layer that PostgreSQL never gets to — and would have silently accepted a ULID in `AuditLog.resource_id`, an `INTEGER` column, where PostgreSQL rejects it. | A green code-path run reads as a working feature. Two of the eight `200`s in that run were empty result sets, which is a vacuous pass, not a success. | State the dialect with the result. Never let a SQLite pass stand as PostgreSQL evidence, and mark empty-result `200`s as vacuous. |
| R-9 | **A probe run in the wrong worktree answers a question nobody asked.** The first RB-3 probe ran against the RB-1 proof checkout, which lacks this lane's 51 `@audit_log` decorators. | The conclusion happened to be identical, so the error would have gone unnoticed and the next such error would not. | Record the worktree and commit with every runtime result, and re-run in the lane under audit. |
| R-10 | **An accepted ADR can forbid the fix the code implies.** 18 `ehr_*` ORM models plus 86 served operations read as "18 migrations missing"; ADR-016 (Accepted, not superseded) says *"No new EHR tables"*. | Authoring the obvious migrations would have implemented the data silo an architecture committee explicitly rejected, and it would have looked like progress. | Before authoring schema for models that exist, read the ADRs and the release scope. An absent table is not automatically a missing migration. |
| R-11 | **The backend suite never touches PostgreSQL.** `tests/conftest.py:28` overwrites `DATABASE_URL` with `sqlite:///:memory:` unconditionally, whatever the caller passes. | Every local suite count — including this lane's baselines — is SQLite evidence. Type strictness, enum handling and NOT NULL behaviour that PostgreSQL enforces are untested there, so a green suite cannot support a PostgreSQL claim. Passing a real `DATABASE_URL` does not override it; it hung the run instead. | Say "SQLite" whenever quoting a suite count. PostgreSQL claims need the CI migration/test jobs or a direct probe. |
| R-12 | **`col.key` looks like the mapped attribute and is not.** For `metadata_ = Column("metadata", ...)` SQLAlchemy leaves `col.name == col.key == "metadata"`; only the mapper carries `metadata_`. | A guard written against `col.name` alone passed four defective sites, and this register recorded one of them as *immune*. The wrong conclusion survived a commit. | Resolve values through `mapper.columns`, never through `col.name` or `col.key`. Guards must match both spellings. |
| R-13 | **Fixing a base class is not fixing the defect.** The first IA-005 pass repaired 12 ORM bases and declared the serializer sound; five hand-rolled serializers elsewhere carried the same pattern, four of them on tables that exist. | The declared blast radius was wrong in the direction that matters — latent instead of live. | After fixing a shared helper, sweep for hand-rolled copies of what it replaced, and pin the sweep as an empty set. |
| R-14 | **The audit lane and the database under test come from different lineages.** `gula_agent2` was migrated from `ce097a0c`; this worktree is 176 commits behind it, with every clinical domain diverging. | A pharmacy measurement in this lane produced a textbook P0 — 216 missing columns, 27 unwritable tables, an ORM/DB identity contradiction — that is entirely a cross-lane artefact. It would have been written up as a platform defect. | Before measuring ORM against schema, diff the worktree against the lineage that built the database, and run the measurement on the matched pair. Quote the lineage with every conformance number. |
| R-15 | **A finding that reproduces is not thereby real.** The retracted pharmacy defect reproduced perfectly and repeatedly — the ORM really does disagree with the database, in this lane. | Reproducibility feels like proof. It only establishes the combination tested, not that the combination is one the programme ships. | State the exact (code lineage, database lineage) pair with every runtime claim, and check whether that pair is one anybody deploys. |
| R-16 | **A module can look canonical without being reached.** `FHIRObservationMapper` sits beside the ten wired-up mappers in `app/national/fhir/` and is exported from two packages, but nothing calls it — and it is the one that reports abnormal lab results as Normal. | Severity assessed from location and appearance would have made it P0; assessed from reachability it is P2. The reverse error is worse: whoever wires it up inherits the inversion silently. | Establish reachability before assigning severity, and say plainly when a defect is latent. Then check whether the unreached thing looks canonical, because that is how it gets adopted. |
| R-17 | **An unconstrained free-text status column drifts into incompatible vocabularies.** `lab_results.flag` has four writers producing `H`/`L`/`N`, `unknown`, `normal`, `critical` and `""`, with no enum or validation. | Both IA-011 defects follow from it, and any consumer — FHIR, statistics, alerting — has to guess. `stats.py` already greps for `critical`/`crit`/`c`. | A column that drives clinical interpretation needs a closed vocabulary at the write boundary, not per-reader heuristics. |
| R-18 | **An independent lane can rediscover a decision the programme has already named.** This lane derived the `national_patients` clinical-subject problem from the physical schema; `20260914_0001`'s docstring had already stated it and deferred it to NR-022. | Reporting it as a new finding would have inflated the open set and implied nobody had noticed. The convergence is worth more than the finding: two independent derivations agreeing raises confidence in the decision's framing. | Before opening an architectural finding, grep the migrations' own prose. Authors who defer deliberately usually say so, and citing them is stronger than restating them. |

| R-19 | **A dead guard is worse than no guard, because it reads as deliberate care.** `kernel.event_bus if hasattr(kernel, "event_bus") else ...` appears in 14 files and expresses a clear preference for the kernel's bus. `Kernel` stores subsystems in `_components`, so the condition is unsatisfiable and the preferred branch has never run. | Fourteen modules look like they handle the kernel-bus case and none of them do. A reviewer reading any one of them sees a sensible fallback, not a defect, which is why this survived to 227 served operations. | When a guard chooses between two implementations, assert at runtime that **both** branches are reachable. An `if` whose true-branch never executes is dead code wearing the costume of a safety check. |
| R-20 | **The obvious fix to a dead guard can be the regression.** Repairing `hasattr(kernel, "event_bus")` was correct in 6 modules and breaks 8 others: their fallback is `None`, their services call `event_bus.emit(...)`, and the kernel bus has no `emit`. Injecting a working bus raises `AttributeError` on blood bank, critical care, EMS and public-health routes. | The two variants are one grep apart and look interchangeable. A batch fix across all 14 — the natural response to a lint finding — converts silent event loss into runtime errors on clinical write paths. | Before applying one repair across a pattern, execute the fixed path in **each** variant. And never write a guard that demands a change you have not proven safe: pin the known-unsafe set with a pointer to the finding instead. |
| R-21 | **The container's default interpreter cannot import the codebase.** `python3` is 3.11.15; `app/identity/repositories/base.py:11` uses PEP 695 generics, a `SyntaxError` before 3.12. Affected test modules **error at collection**, so they are absent from the count rather than failing in it. | Every suite total this lane quoted under `python3` silently excluded the identity-repository tree. A collection error reads as an environment hiccup, not as missing coverage. | Run the suite under `python3.13`. Quote the interpreter next to the dialect (R-11) with every count, and treat a collection error as missing evidence, never as a pass. |
| R-22 | **An unwritten component read by a monitoring endpoint manufactures good news.** `publish()` never enqueues to `outbox` or `dead_letter_queue`, and `/kernel/events/outbox` and `/kernel/events/dlq` report exactly those two. Both return zero for the life of the process under `system:admin`. | The operator's only view of the event pipeline cannot express trouble. This is the false-green pattern on the surface specifically built to detect it. | An observability endpoint must be able to return a bad value. Prove it by making the underlying condition true and re-reading the endpoint; if you cannot, the endpoint is decoration. |
| R-23 | **Sophistication and location read as canonical; only importers do.** Four classes are named `OfflineSyncEngine`. The one in `app/services/` — the documented business-logic layer — has vector clocks, four resolution strategies, per-operation signatures and the only dedicated test file, and **zero production importers**. The served engine is a much cruder one in `app/integration/`. | I analysed the wrong module first and had five defects written up before checking reachability. Severity read off sophistication would have been badly wrong in both directions: P0 for dead code, and P2 for the surface that actually answers requests. | Resolve the importer graph **before** reading the implementation. A dedicated test file is evidence the code is exercised, not that it is reached. When one name has several classes, enumerate all of them and mark which is served. |
| R-24 | **A test suite on dead code makes it look load-bearing.** `tests/test_offline_sync.py` exercises the unreachable engine, so the suite is green and the module appears maintained and validated. | A green test next to a sophisticated implementation is the strongest possible adoption signal. The next engineer needing offline sync picks it up and inherits an unauthenticated default "signature", a non-converging resolver and a `CRDT_MERGE` that diverges across replicas. | Tests prove behaviour, never reachability. Where a tested module has no production importer, say so in the module itself, so the adoption decision is informed rather than implied. |
| R-25 | **A brief's premise about a closed finding can be false in the lane you are standing in.** The task stated `LabResult.test_type_id` cannot be NULL after NR-164. Measured: nullable in all three worktrees, nullable in the migrated database, no CHECK constraint, and NR-164 is not in this lane's register at all. | Auditing forward from "that hole is closed" would have skipped the three write paths that were writing NULL, and the silent clinical-history omission behind them. | Re-measure the invariant a premise asserts, in the lane and the database you are actually testing, before building on it. Cite the lineage. A finding closed in a sibling lane is not closed here. |
| R-26 | **One correct write path makes a broken one invisible.** Four paths construct a `LabResult`; only the manually-driven route resolved the test catalog. Its tests pass, so the workflow looked covered, while the analyzer — the path a real laboratory actually uses — wrote no test-type link and no reference range. | The defect lived specifically on the highest-volume, least-hand-tested path, and the presence of a well-behaved sibling was the reason nobody looked. | Enumerate **every** construction site of a clinical row and diff their keyword sets against each other. Where they differ, the majority is not automatically right — compare each against the one that resolves the catalog. |
| R-27 | **A reader can filter on a vocabulary no writer emits, and report zero forever.** The MoH DHIS2 export buckets `lab_results.flag` on `"high"`/`"critical_high"`/`"low"`/`"critical_low"`; `get_flag` only ever emits `normal`/`H`/`L`/`critical`/`unknown`. So the abnormal counts are structurally zero and 4 of 6 stored rows land in no bucket. | Zero abnormalities reads as a clean laboratory, not as a broken query, and it is submitted to a ministry. `flag IS NULL` is additionally counted as `normal`. | For any categorising query, enumerate the writers' actual value set and assert the reader's cases cover it exhaustively, with an explicit bucket for the remainder. Never treat NULL as the healthy case. |
| R-28 | **A documented security model can be fully implemented and never invoked.** `lab_device_gateway.py` carries a four-layer analyzer trust boundary in its module docstring — whitelist, HMAC, replay window, range validation — and has zero importers, while the served `POST /device/results` has none of the four. `device_trust_service.py` likewise. | Reading the repository for "how does GULA authenticate analyzers" finds a convincing answer that is not in force. A design document that exists as code is more persuasive than one that does not, and equally inert. | Treat a security control as absent until an importer chain reaches it from a served route. Grep for callers before quoting a module's own security claims, including in certification reports. |
| R-29 | **Randomly generated per-row uniques look like idempotency and are the opposite.** `lab_results` has two unique constraints, `token` and `token_hash`, both filled from `secrets.token_urlsafe(32)` inside the insert loop. A constraint list therefore shows three uniques on the table while nothing keys on submission identity, so a retried analyzer submission duplicates clinical results without violating anything. | The constraint count reads as protection. An instrument that retries on timeout — ordinary middleware behaviour — silently duplicates results, and after the IA-020 fix duplicates the critical flag with them. | Judge idempotency by whether a constraint keys on *caller-supplied* identity, not by how many uniques exist. A unique on a server-generated random value constrains nothing. |
