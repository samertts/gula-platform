# Risk register

Risks, not defects: things that make defects likely or hard to see.

| # | Risk | Why it matters | Mitigation |
|---|---|---|---|
| R-1 | **A route's signature does not tell you its authorization.** Router-level `dependencies=[...]` are the effective guard, and FastAPI binds a dependency's `citizen_id` parameter to the *path* id. | A signature scan reported 17 correctly-guarded PHI routes as unguarded. The same error in the other direction would report a live IDOR as safe. | Measure the served OpenAPI surface plus router-level dependencies; read the dependency body. Never conclude from the decorator. |
| R-2 | **Route existence is not capability.** `/reference/*` has 4 tenant-broken handlers and serves 0 paths; `/ehr/*` serves 54 paths over tables no migration creates. | Any count of endpoints, or of "features", overstates the platform. | Count served paths, and check the tables behind them exist. |
| R-3 | **Local suite counts are corruptible by the environment.** PostgreSQL is reclaimed mid-run and the failure presents as dozens of plausible test errors. | An 18-error environment failure was nearly committed as a regression. | Assert database reachability before collection; re-check `pg_isready` after any surprising error count. |
| R-4 | **Generated code is verified by generating it, not by reading it.** A repair to the capability generator was valid in its output and a `SyntaxError` in the template; the capability tests passed because they never import the generator. | A generator can be broken while everything downstream of its last run is green. | Generate into a temp directory and compile every emitted file. |
| R-5 | **Two lanes share one finding-number space.** 80 ids exist in both registers and 66 mean *different* findings; the fork is at NR-008. | A bare `NR-nnn` above NR-015 is ambiguous in both directions, including inside open PR bodies. | Cite the branch with the number. See `docs/architecture/CROSS_LANE_FINDING_ID_COLLISIONS.md`. |
| R-6 | **A self-certifying test is worse than no test.** Ten generated capabilities asserted their own hard-coded `{"success": True}`. | A passing suite counted them. | A test must be able to fail for the reason it exists; pin the honest state. |
| R-7 | **A missing schema masks every defect above it.** The `/ehr` surface fails at the first table lookup, so nothing downstream is ever reached: IA-005 breaks 59 of its 86 operations and was invisible until the tables were created in a throwaway database. | Fixing the schema will not make the surface work, and the defects it uncovers will appear to be *new* — introduced by the migration — when they have been latent all along. | When a surface fails closed on a missing table, probe the layers above it separately before estimating the remaining work. Never read "one migration away" off a `500`. |
| R-8 | **A weakly-typed probe database buys reachability and sells correctness.** The SQLite code-path run reached the serialisation layer that PostgreSQL never gets to — and would have silently accepted a ULID in `AuditLog.resource_id`, an `INTEGER` column, where PostgreSQL rejects it. | A green code-path run reads as a working feature. Two of the eight `200`s in that run were empty result sets, which is a vacuous pass, not a success. | State the dialect with the result. Never let a SQLite pass stand as PostgreSQL evidence, and mark empty-result `200`s as vacuous. |
| R-9 | **A probe run in the wrong worktree answers a question nobody asked.** The first RB-3 probe ran against the RB-1 proof checkout, which lacks this lane's 51 `@audit_log` decorators. | The conclusion happened to be identical, so the error would have gone unnoticed and the next such error would not. | Record the worktree and commit with every runtime result, and re-run in the lane under audit. |
| R-10 | **An accepted ADR can forbid the fix the code implies.** 18 `ehr_*` ORM models plus 86 served operations read as "18 migrations missing"; ADR-016 (Accepted, not superseded) says *"No new EHR tables"*. | Authoring the obvious migrations would have implemented the data silo an architecture committee explicitly rejected, and it would have looked like progress. | Before authoring schema for models that exist, read the ADRs and the release scope. An absent table is not automatically a missing migration. |
| R-11 | **The backend suite never touches PostgreSQL.** `tests/conftest.py:28` overwrites `DATABASE_URL` with `sqlite:///:memory:` unconditionally, whatever the caller passes. | Every local suite count — including this lane's baselines — is SQLite evidence. Type strictness, enum handling and NOT NULL behaviour that PostgreSQL enforces are untested there, so a green suite cannot support a PostgreSQL claim. Passing a real `DATABASE_URL` does not override it; it hung the run instead. | Say "SQLite" whenever quoting a suite count. PostgreSQL claims need the CI migration/test jobs or a direct probe. |
| R-12 | **`col.key` looks like the mapped attribute and is not.** For `metadata_ = Column("metadata", ...)` SQLAlchemy leaves `col.name == col.key == "metadata"`; only the mapper carries `metadata_`. | A guard written against `col.name` alone passed four defective sites, and this register recorded one of them as *immune*. The wrong conclusion survived a commit. | Resolve values through `mapper.columns`, never through `col.name` or `col.key`. Guards must match both spellings. |
| R-13 | **Fixing a base class is not fixing the defect.** The first IA-005 pass repaired 12 ORM bases and declared the serializer sound; five hand-rolled serializers elsewhere carried the same pattern, four of them on tables that exist. | The declared blast radius was wrong in the direction that matters — latent instead of live. | After fixing a shared helper, sweep for hand-rolled copies of what it replaced, and pin the sweep as an empty set. |
| R-14 | **The audit lane and the database under test come from different lineages.** `gula_agent2` was migrated from `ce097a0c`; this worktree is 176 commits behind it, with every clinical domain diverging. | A pharmacy measurement in this lane produced a textbook P0 — 216 missing columns, 27 unwritable tables, an ORM/DB identity contradiction — that is entirely a cross-lane artefact. It would have been written up as a platform defect. | Before measuring ORM against schema, diff the worktree against the lineage that built the database, and run the measurement on the matched pair. Quote the lineage with every conformance number. |
| R-15 | **A finding that reproduces is not thereby real.** The retracted pharmacy defect reproduced perfectly and repeatedly — the ORM really does disagree with the database, in this lane. | Reproducibility feels like proof. It only establishes the combination tested, not that the combination is one the programme ships. | State the exact (code lineage, database lineage) pair with every runtime claim, and check whether that pair is one anybody deploys. |
