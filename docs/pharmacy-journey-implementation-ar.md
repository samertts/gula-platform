# تنفيذ مسار الصيدلية في GULA

## الملخص

أضيفت طبقة واجهة آمنة لمسار الصيدلية داخل `frontend-v3`. الهدف من هذه الموجة ليس تحويل الواجهة إلى نقطة صرف مستقلة، بل عرض دورة الصيدلية بطريقة متسقة مع نموذج GULA: هوية الشخص، الهوية المهنية، المؤسسة، مساحة العمل، الوصفة، الدواء، الصرف، المخزون، التأمين، والتدقيق. يبقى backend هو المرجع النهائي لكل قرار أو أثر سريري أو مالي.

## ما تم تنفيذه

أصبحت الصفحة `/pharmacy-operations` تميز صراحة بين Demo وLive. في Demo تعرض الواجهة بيانات اصطناعية للكتالوج والوصفات والمخزون والحركات والتنبيهات. أزيلت عمليات الاستلام والصرف المحلية، ولا توجد كتابة أو فاتورة أو خصم مخزون أو اتصال بخدمة خارجية. البحث والتنقل داخل السيناريو التجريبي لا ينتجان أثراً تشغيلياً.

في Live تقرأ الصفحة مساحات العمل من `GET /niam/workspaces`، وتقبل فقط المساحات غير الشخصية المرتبطة بمنشأة، ولا تفتح القراءة قبل أن تكون حالة المساحة فعالة أو موثقة أو معتمدة. تفعيل السياق يتم من خلال `POST /niam/workspaces/{workspace_id}/switch`، وبعده فقط يمكن طلب ملخص الصيدلية والمخزون والكتالوج من العقود الموجودة.

| المجال | عقد الواجهة الحالي | الحالة |
|---|---|---|
| مساحات الصيدلية | `GET /niam/workspaces` | متاح بعد ترشيح مساحة منشأة وسياق خادمي |
| تبديل السياق | `POST /niam/workspaces/{workspace_id}/switch` | متاح فقط للمساحة الفعالة وغير الشخصية |
| ملخص POS | `GET /pharmacy/pos/summary` | قراءة محدودة بعد تفعيل السياق |
| المخزون | `GET /pharmacy/inventory/stock-levels` | قراءة محدودة بعد تفعيل السياق |
| كتالوج الدواء | `GET /pharmacy/drugs` | بحث حي بعد تفعيل السياق وبحد أدنى حرفين |
| البيع/الصرف | `POST /pharmacy/pos/sales` | محجوب في هذه الصفحة حتى يكتمل سياق الصيدلية والتحقق الموحد |
| الاستبدال الدوائي | عقود المرشحين والطلب والاعتماد موجودة | محجوب من مسار الواجهة الحالي حتى يثبت patient/prescription consent وscope |
| الوصفات والعينات والمرتجعات والاستدعاءات | لا يوجد عقد موحد آمن مستخدم هنا | محجوبة |

## الحراسة والعزل

تم تضييق سياسة `/pharmacy-operations` إلى أدوار الإدارة و`staff` و`cashier` و`demo_viewer` الموجودة فعلياً في نموذج `UserRole`. لا يضاف دور `pharmacist` من الواجهة لأن الصفة المهنية يجب أن تنشأ من `Professional Identity` و`VerificationRecord` و`Membership` خادمية. وصول الصيدلي الحقيقي يحتاج أن يعكسه الخادم من خلال مساحة منشأة وعضوية وسياق مناسب.

لا تساوي الصفحة بين امتلاك وصفة وامتلاك سجل صحي. ولا تعرض حقول `account_id` أو بيانات المواطن الوطنية، ولا تفتح الوصفة بمجرد الاسم، ولا تسمح للمساعد أو المرشد بتجاوز التفويض. كما أن حالة الدفع أو التأمين لا تعتبر دليلاً على صرف الدواء.

## وظائف محجوبة عمداً

تبقى عمليات إنشاء الوصفة وتعديلها وإلغائها، والتحقق من هوية المريض أو الوكيل، والصرف الجزئي والكامل، ومنع الصرف المزدوج، والاستبدال الجنيسي، والتداخلات والحساسيات، والأدوية الخاضعة للرقابة، وFEFO، والتشغيلة والانتهاء، والاستدعاء، والتحويل بين الفروع، والاستلام من المورد، والمرتجع، والإتلاف، وضبط المخزون، والسلسلة الباردة، والتأمين، والدفع، والإشعارات الحرجة، ومصالحة الأدوية، والتجديد، والعمل دون اتصال؛ كلها تحتاج عقوداً خادمية متخصصة قبل فتحها من الواجهة.

أي عقد كتابة مستقبلي يجب أن يفرض على الأقل نطاق المؤسسة والفرع، والتحقق من الوصفة والمريض والمنتج والكمية والانتهاء، وفصل الأدوار، وحالة workflow صريحة، ونسخة أو `If-Match`، و`Idempotency-Key`، وسجل تدقيق غير قابل للحذف. وفي حالات Offline لا يجوز اعتماد صرف غير محدود ثم مزامنته لاحقاً من دون سياسة reconciliation تمنع الصرف المزدوج.

## الاختبارات

أضيفت اختبارات تثبت أن Demo لا يستدعي API الحي ولا يعرض أزرار البيع أو الصرف أو الاستلام، وأن Live لا يقرأ الملخص أو المخزون قبل تفعيل workspace، وأن الفشل لا يتحول إلى بيانات Demo أو fallback legacy. كما أضيف اختبار سياسة التنقل لمنع الطبيب والمواطن من فتح مساحة عمليات الصيدلية تلقائياً.

تم تشغيل lint، وفحوص توحيد الواجهة، وحوكمة العقود، وحدود التكامل، وTypeScript، ومجموعة الاختبارات الكاملة، والبناء الإنتاجي. النجاح المحلي لا يمثل بديلاً عن فحوص GitHub البعيدة.

## الحدود التشغيلية

هذه الوثيقة لا تثبت ترخيص صيدلية، ولا اعتماد صيدلي، ولا تكاملاً مع وزارة أو نقابة أو شركة تأمين أو بوابة دفع أو جهاز POS أو LIS أو نظام مورد. كما لا تعني أن المسار جاهز للإنتاج أو أن عمليات الصرف الحقيقية متاحة. الغرض الحالي هو واجهة آمنة قابلة للعرض والتمهيد، مع إبقاء القرار السريري والمالي والتفويض والتدقيق داخل backend.
