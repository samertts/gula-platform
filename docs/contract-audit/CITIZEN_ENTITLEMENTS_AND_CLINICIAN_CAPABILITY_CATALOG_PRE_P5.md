# استحقاقات المواطن وكتالوج صلاحيات الطبيب قبل P5

**الحالة:** `P4_BLOCKED / NON_OPERATIONAL`  
**الغرض:** تحويل قاعدة المنتج إلى مواصفة قابلة للمراجعة: تحقق هوية المواطن هو شرط بدء استحقاقات المواطن، وليس إنشاء الحساب أو تفعيله؛ وتحدد صلاحيات الطبيب بأفعال وسياق وحالات رفض صريحة. لا تنشئ هذه الوثيقة API أو دوراً أو حقاً فعلياً.

> لا تعتبر هذه الوثيقة تأكيداً لمتطلب قانوني أو تنظيمي عراقي أو وجود تكامل رسمي. تمثل سياسة المنتج التي تحتاج مراجعة حوكمة وسريرية وقانونية واعتماداً من الجهات المخولة قبل التشغيل.

## 1. فصل دورة الحساب عن الاستحقاق

| الحالة الخادمية | معناها | ما تمنحه | ما لا تمنحه |
|---|---|---|---|
| `ACCOUNT_CREATED` | سجل حساب أولي موجود | لا شيء | لا استحقاق مواطن ولا دور مهني ولا قراءة صحية |
| `ACCOUNT_ACTIVE` | حساب قادر على المصادقة ضمن سياسات الجلسة | إدارة جلساته الأساسية فقط | لا استحقاق مواطن ولا وصول لخدمة مقيدة |
| `IDENTITY_VERIFIED` | هوية الشخص مثبتة بمصدر وطريقة ودليل وزمن صلاحية مع تدقيق | قابلية تقييم **حزمة استحقاقات المواطن الأساسية** | لا تجاوز لقيود الخدمة، ولا صلاحية طبيب أو منشأة |
| `CITIZEN_ENTITLEMENT_ACTIVE` | تحقق الهوية قائم وسياسة الاستحقاق تسمح بالخدمة والسياق | الأفعال المواطنية المصرح بها للخدمة المعنية | لا أمر سريري ولا تغيير سياسة ولا تجاوز حصة |
| `PENDING_REVIEW / SUSPENDED / EXPIRED` | تحقق أو سياسة أو دليل بحاجة مراجعة/متوقفة/منتهية | لا أفعال حساسة جديدة | لا استمرار افتراضي أو صلاحية مخبأة |

لا يقرر تطبيق الويب أو Android هذه الحالات ولا يخزن نتيجة تفويضها كحقيقة قابلة لإعادة الاستخدام. يعيد الخادم التقييم لكل فعل حساس ويكتب سجل تدقيق للقبول والرفض.

## 2. استحقاقات المواطن الأساسية المقترحة

تعني عبارة «كافة صلاحيات المواطن» **الحزمة الأساسية المعتمدة بعد تحقق الهوية**، لا حقاً مطلقاً في كل خدمة صحية بلا شرط. تظل كل خدمة خاضعة لحالتها، وموافقة المواطن، ونطاقها، وعلمها، وسياسة الاستحقاق السارية.

| الفعل المقترح | الشرط الخادمي | حد واضح |
|---|---|---|
| `citizen.profile.read_self` | هوية متحققة وجلسة صالحة | لا قراءة ملف شخص آخر |
| `citizen.contact.update_self` | جلسة صالحة وخطوة تحقق عند تغيير حساس | لا تغيير حقائق الهوية المتحققة بلا إعادة تحقق |
| `citizen.session.manage_self` | جلسة صالحة | لا إدارة جلسات أو حسابات الغير |
| `citizen.consent.manage_self` | هوية متحققة وسياسة موافقة | لا موافقة بالنيابة إلا عبر تمثيل قانوني مثبت وسياسة منفصلة |
| `citizen.order.read_self` | أمر موقع، موافقة/سياق صحيح، وعلم خدمة مفعّل | لا إنشاء أمر أو تغييره أو قراءته لغيره |
| `citizen.provider.select_for_own_order` | أمر في `PATIENT_SELECTION_REQUIRED` ومنفذ مؤهل | لا إجبار الطبيب أو المنفذ ولا تجاوز الأهلية |
| `citizen.result.read_self` | نتيجة منشورة وعلم جسر القراءة وسياسة المورد | لا نتائج أولية أو غير معتمدة ولا تعديل نتيجة |
| `citizen.appointment.manage_self` | خدمة مفعلة وسياسة وقت/مكان | لا حجز أو تعديل للغير |

## 3. سياسة القيود الوزارية الخادمية

تكون القيود **استحقاقات خدمة** لا تعديلاً لدور المواطن أو الطبيب. لا تكفي تسمية حساب «وزارة» لتعديلها؛ يجب أن يملك الفاعل تعييناً خادمياً موثقاً وصلاحية سياسة محددة ونطاقاً مصرحاً به. يكتب الخادم نسخة السياسة والسبب والفاعل والوقت وحالة النشر وأثر القرار لكل تعديل.

| حقل سياسة مستقبلي | وظيفته |
|---|---|
| `service_code` و`service_type` | تحديد الخدمة أو عائلة الخدمات، مثل فحص محدد أو تصوير بالرنين؛ لا يفعّل خدمة غير مفعلة |
| `jurisdiction` و`city_scope` | تقييد نطاق الدولة/المحافظة/المدينة أو عدم تقييده |
| `window_start` و`window_end` | فترة صلاحية السياسة وحدودها الزمنية |
| `max_uses` و`window_duration` | حد الاستخدام خلال نافذة زمنية؛ مثال تمثيلي فقط ولا ينشئ حدّاً حياً |
| `subject_scope` | شروط أهلية معلنة ومراجعة؛ يمنع استخدام خصائص حساسة أو تمييزية بلا أساس موثق |
| `effective_at` و`supersedes_policy_id` | سريان نسخة جديدة وعلاقتها بالنسخة السابقة بلا كتابة فوق التاريخ |
| `authority_assignment_id` و`approval_reference` | إثبات أن التعديل صدر من تعيين وصلاحية مرخصين لا من واجهة العميل |
| `rollback_policy_id` و`reason_code` | عودة مدققة ومعللة عند الإلغاء أو التصحيح |

يمكن للجهة الوزارية المخولة تعديل السياسة أو إيقافها أو تقييد الخدمة عند الحاجة **من خلال** سير عمل خادمي مدقق وإصدار جديد للسياسة. لا يكون التغيير صامتاً، ولا يبطل الأثر التاريخي للأوامر السابقة، ولا يسمح بتجاوز سلامة المريض أو الالتزامات القانونية أو تدقيق المراجعة البشرية. لا توجد حالياً أرقام أو قيود إنتاجية مفعلة؛ مثال «الرنين مرة كل ستة أشهر» يبقى مثال تصميمي إلى أن تعتمد سياسة حقيقية بمصدر ومالك ونافذة وسبب ومراجعة.

## 4. ترتيب القرار الخادمي

يرفض الخادم عند أول شرط غير متحقق، مع سجل تدقيق غير كاشف:

1. سلامة المنصة وعلم الخدمة والبوابة المرحلية؛ `OFF` يرفض.
2. حالة الحساب والجلسة وتحقيق الهوية للمواطن أو التحقق المهني للطبيب.
3. العضوية والتعيين والنطاق التنظيمي/المنشأة/مساحة العمل عند الحاجة.
4. صلاحية الفعل الصريحة؛ سياسة المنع تطغى على السماح.
5. استحقاق خدمة المواطن وقيود المدينة/النوع/العدد/المدة السارية.
6. حالة المورد، موافقة المواطن، وحالة دورة الأمر.
7. الحصة الذرية أو مفتاح عدم التكرار وتدقيق القرار.

## 5. كتالوج صلاحيات الطبيب المقترح

لا يحصل الطبيب على هذا الكتالوج دفعة واحدة. بعد التحقق المهني الثنائي والتعيين الفعال، تمنح كل صلاحية بقرار خادمي منفصل وحسب التخصص والمنشأة والنطاق والسياسة. العناصر التالية **مقترحة وغير مفعلة**:

| المجال | صلاحية مقترحة | شروط السماح | غير مسموح |
|---|---|---|---|
| ملف المريض | `clinical.patient.read_assigned` | موافقة/سياق، تعيين، نطاق مورد | البحث الحر أو القراءة خارج السياق |
| الفحوص | `clinical.lab.order.create` | طبيب متحقق، قائمة فحوص معتمدة، توقيع، استحقاق المواطن | اختيار المختبر، إدخال/اعتماد النتيجة |
| التصوير | `clinical.diagnostic_imaging.order.create` | سياق وسجل سريري لازم، كتالوج معتمد، توقيع | اختيار المركز أو تفسير التقرير خارج صلاحية منفصلة |
| اللقاحات | `clinical.immunization.order.create` | منتج/جرعة من كتالوج، سياسة موافقة، توقيع | توليد جدول تلقائي أو تسجيل الإعطاء |
| العلاج | `clinical.medication.prescription.create` | دواء وجرعة ومدة من كتالوج، توقيع، سياسة الدواء | صرف الدواء أو اختيار الصيدلية |
| الإحالة | `clinical.referral.create` | سبب وإطار زمني ووجهة اختيارية، تدقيق | فرض جهة على المواطن أو قبول الإحالة بنفسه |
| خطة الرعاية | `clinical.care_plan.propose` | خطة موقعة وسياق صالح | تفعيل خطة تلقائياً أو تعديل خطة موقعة بلا نسخة جديدة |
| المراسلة | `clinical.patient.message.send` | موافقة وقناة آمنة ومحتوى محدود | إرسال تفاصيل حساسة إلى قناة غير محمية |
| المستندات | `clinical.document.create` و`clinical.document.sign` | نوع مستند مسموح، توقيع، نسخة | حذف/إعادة كتابة وثيقة موقعة |
| الطلبات | `clinical.order.cancel_own` | مؤلف الأمر، حالة مسموحة، سبب، تدقيق | إلغاء أمر طبيب آخر أو الالتفاف على دورة الحالة |

### صلاحيات تستبعد عمداً من دور الطبيب العام

لا يشمل الدور العام للطبيب: تعيين أو إزالة الأدوار، التحقق المهني، تغيير القيود الوزارية، تفعيل الميزات، اعتماد نتائج المختبر، إصدار تقارير التصوير، إعطاء اللقاح، صرف الدواء، إدارة التعويضات أو الدفع، أو تجاوز موافقة المواطن واختيار المنفذ. كل منها يتطلب دوراً وتعييناً وسياسة وسير عمل منفصلين، أو يبقى محجوباً.

## 6. بوابة التفعيل

تظل استحقاقات المواطن وقيود الخدمة والكتالوج `PROPOSED_NOT_IMPLEMENTED / OFF` إلى أن تكتمل أدلة P4 للتفويض والتدقيق وتكافؤ الواجهات والعزل وقواعد البيانات وفحوص الجودة وسجل الميزات، ثم المراجعة البشرية والدمج والتحقق الإنتاجي [1]. لا تنفذ هذه المواصفة ABAC أو صلاحيات تخمينية أو تكاملاً وزارياً أو قاعدة عددية حية.
