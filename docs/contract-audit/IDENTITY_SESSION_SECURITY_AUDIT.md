# تدقيق حدود هوية NIAM والجلسات

**الحالة:** قرار منع مرحلي، 13 أغسطس 2026.

## النتيجة التنفيذية

توجد طبقتا هوية مستقلتان في الخلفية. تصدر NIAM رموز جلسة مرتبطة بـ`Account` وتستعمل معرفات حسابات مثل `account_uuid`، بينما يعتمد `app/security/dependencies.py` على رمز موروث يحمل `user_id` ويحمّل `LabUser` أو `User` من قاعدة المختبر. لذلك لا يجوز استعمال `get_current_user` أو `require_permission` الموروثين لحماية واجهات NIAM، ولا يجوز افتراض أن حساب NIAM يملك دور مختبر موروثًا أو نطاق منشأة صالحًا.

| السطح | النتيجة | القرار |
|---|---|---|
| تسجيل الدخول NIAM | أصبح البحث عن المعرف موحدًا في استعلام واحد مع فحص `_DUMMY_HASH` عند غياب الحساب، فلا يتباين مسار كلمة المرور بين البريد واسم المستخدم والحساب غير الموجود. | **مؤهل** مع اختبارات الانحدار. |
| تحديث جلسة NIAM | يستخدم المسار الآن `refresh_token_jti` لاسترجاع الجلسة ثم يدور الجلسة، بدل محاولة البحث بمعرف رمز الوصول. | **مؤهل** مع اختبار دوران. |
| إنشاء/قفل/فتح حساب NIAM | المسارات في `app/identity/api/accounts.py` لا تملك حتى الآن اعتماد جلسة NIAM إداري موثوقًا أو تقييمًا لسياسة دقيقة، وتكشف استجاباتها وجود الحساب عند استخدامها مباشرة. | **ممنوع من أي واجهة تشغيلية**؛ لا تضاف له تبعية التفويض الموروثة. |
| تدقيق أحداث المصادقة والإدارة | يوجد سجل تدقيق هوية، لكن لا يثبت بعد نموذج حدث غير قابل للتعديل مرتبطًا بذات معاملة الأمر الحسّاس. | **مطلوب تصميم منفصل** قبل تفعيل أوامر الإدارة. |

## ضوابط مثبتة في هذه المرحلة

1. يستدعي `AccountService.authenticate` المستودع مرة واحدة عبر `find_by_login` ويجري تحقق كلمة المرور باستخدام قيمة بديلة ثابتة عندما لا يعثر على حساب نشط.
2. لا يعيد البحث حسابًا غير نشط في مسار الدخول، ويظل رد واجهة الدخول عامًا.
3. يستعمل `AuthenticationService.refresh_session` مستودع الجلسات عبر `find_by_refresh_token_jti` فقط، ثم يلغي الجلسة القديمة قبل إنشاء جلسة جديدة.
4. تغطي اختبارات الانحدار غياب الحساب ودوران رمز التحديث، وتبقى اختبارات العقود السريرية مستقلة عن هذا المسار.

## قرار الحوكمة المطلوب قبل أي أمر إدارة حساب

لا تفعّل أوامر إنشاء الحساب أو قفله أو فتحه أو إنهاء جلساته قبل اعتماد تصميم **تفويض إداري لـNIAM** يتضمن على الأقل:

1. اعتماد FastAPI مستقل يستخرج جلسة NIAM ويتحقق من صلاحيتها وحالتها دون الرجوع إلى مطالبة `user_id` الموروثة.
2. ربط قابل للتدقيق بين `Account` و`Person` و`RoleAssignment` النشط، مع `organization_id` و`facility_id` حيث يلزم المورد.
3. تقييم سياسة دقيقة خاصة بكل أمر، مثل `identity.account.lock` أو `identity.account.unlock`، ومنع افتراضي عندما تغيب السياسة أو النطاق.
4. سجل حدث غير قابل للتعديل يربط الفاعل، الحساب المستهدف، سبب القرار، النتيجة، ومعرف الارتباط ضمن معاملة واحدة مع تغيير الحالة.
5. استجابات فشل عامة للواجهات غير الإدارية، وحدود سرعة مناسبة لمسارات الدخول والاستعادة.

> **قرار منع:** لا تستبدل هذه الضوابط باستيراد `require_permission` الموروث؛ فهو يعمل على نموذج رمز وهوية مختلف، وقد يمنح ثقة غير مثبتة أو يفشل في عزل نطاق NIAM.
