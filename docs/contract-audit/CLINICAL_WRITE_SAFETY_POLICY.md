# سياسة سلامة الكتابات السريرية

## الحالة والنطاق

> **الحالة: مسودة إلزامية غير معتمدة للتفعيل.** لا تسمح هذه الوثيقة بتشغيل أي عملية كتابة. وهي تضع شروط الاعتماد التي يجب أن تتحقق وتوثق قبل إتاحة أي إنشاء أو تعديل أو توقيع أو حذف أو انتقال حالة في الأشعة أو السجل الطبي أو التمريض.

تنطبق السياسة على كل أمر سريري يغير سجلًا، أو نتيجته، أو حالته، أو مسؤوليته، أو أثره التشغيلي. لا تشمل عقود القراءة المحكومة الحالية؛ فلا تتحول صلاحية قراءة دقيقة إلى حق كتابة ضمني.

| الفئة | أمثلة ممنوعة حاليًا | شرط الإتاحة المستقبلي |
|---|---|---|
| السجل الطبي | إنشاء أو تعديل أو توقيع أو حذف ملاحظة | سياسة أثر سريري، هوية مؤلف مشتقة من الجلسة، وقواعد توقيع/تصحيح لا تقبل الاستبدال الصامت. |
| التمريض | إكمال أو تأجيل أو إسناد مهمة، تسجيل قياس، تعديل خطة رعاية | آلة حالات معتمدة، قواعد أهلية وانتقال، وتعارض صريح بين التعديلات المتزامنة. |
| الأشعة | تعديل نتيجة أو حالة طلب أو مرفق | نموذج اعتماد نتيجة، أثر تدقيق ذري، وسياسة مرفقات واحتفاظ. |

## بوابة اعتماد إلزامية

لا يضاف مسار HTTP أو إجراء tRPC للكتابة، ولا يزال وصفه من حالة **ممنوع** في سجل العقود، ما لم يقدم مالك المجال حزمة اعتماد مستقلة لكل أمر تتضمن ما يأتي:

1. **تعريف أثر تشغيلي وسريري** يحدد من يتأثر، وما القرار الذي يتغير، وطريقة الإخطار أو التصحيح والرجوع.
2. **سياسة تعارض** تحدد مصدر الحقيقة، واكتشاف الإصدار المتزامن، والنتيجة عند التعارض؛ ويكون الرفض الصريح هو الافتراضي عند غياب سياسة مجال مثبتة.
3. **عقد أمر دقيق** يتضمن المورد، والفعل، والحالة السابقة المقبولة، والحالة التالية، والمدخلات الأدنى، وصلاحية بصيغة `clinical.<domain>.<resource>.<action>`.
4. **إثبات هوية ونطاق خادمي** يربط الحساب بالشخص والتعيين النشط والمنشأة والمؤسسة والمستأجر، ويحمّل المورد ضمن النطاق المثبت قبل التغيير.
5. **خطة أثر تدقيق وحدث** تتضمن قرار التفويض، ومعرّف الأمر، وهوية الفاعل المشتقة من الجلسة، وحالة المورد قبل/بعد، ووقت UTC، وسياق الارتباط.
6. **اختبارات سلبية وتشغيلية** تثبت رفض عدم الصلاحية، واختلاف المستأجر أو المؤسسة أو المنشأة، وغياب الجسر، والتعارض، وإعادة المحاولة، وانقطاع العميل.

لا يعد اجتياز اختبار وحدة أو ظهور زر واجهة دليلًا على الاعتماد. يتم اعتماد الحزمة خطيًا من مسؤول المجال السريري ومالك التشغيل ومسؤول الأمن/الامتثال قبل تغيير حالة العقد في المصفوفة.

## idempotency والتزامن

| الموضوع | القرار الإلزامي |
|---|---|
| مفتاح إعادة المحاولة | يستقبل كل أمر قابل لإعادة الإرسال مفتاح `Idempotency-Key` خادميًا متحققًا ضمن نطاق الفاعل والمنشأة ونوع الأمر. لا يعاد تنفيذ أمر مطابق مكتمل؛ تعاد النتيجة المسجلة نفسها. |
| صحة المفتاح | يربط المفتاح ببصمة حمولة قانونية وبمعرّف المورد. إذا أعيد المفتاح بحمولة أو مورد مختلفين، يرفض الطلب بدل تخمين النية. |
| التحكم بالتزامن | تستخدم كل حالة قابلة للتغيير إصدارًا أو قفلًا متفائلًا. يؤدي اختلاف الإصدار أو خرق انتقال الحالة إلى تعارض مفهوم للمستخدم، لا إلى آخر كتابة تنتصر تلقائيًا. |
| المعاملة | تضم معاملة واحدة تغيير المورد، ونسخة التدقيق، وسجل idempotency، وحدث outbox محليًا إذا كان الحدث جزءًا من العقد. لا يسمح بالتزام جزئي أو نشر حدث قبل نجاح التغيير. |
| الترتيب | تحدد خدمة المجال ترتيب انتقال الحالة؛ لا يقبل الموجّه أو العميل حالة الهدف مباشرة ما لم تتحقق الخدمة من الحالة السابقة. |

## التدقيق والأثر

يجب أن يكون أثر الكتابة **إلحاقيًا غير قابل للتعديل من مسار التطبيق**. لا تحل سجلات الطباعة أو سجل الموجّه محل أثر التدقيق. يتضمن الأثر، كحد أدنى، معرّفًا غير قابل للتخمين، وزمن UTC، والفاعل المستمد من الجلسة، ومعرّف الشخص والتعيين، والمستأجر والمؤسسة والمنشأة المثبتة، والمورد، والفعل، والنتيجة، والارتباط، وبصمة المدخلات القانونية، وملخص الحالة قبل/بعد وفق ضوابط الخصوصية.

تسجل محاولات الرفض الحساسة ببيانات تقنية دنيا لا تحتوي محتوى سريريًا. ولا يسجل النص الحر للملاحظة أو القياس أو أي سر في أثر التدقيق إلا إذا اعتمدت سياسة احتفاظ وإتاحة منفصلة ذلك صراحة.

## عدم الاتصال والتعافي

العمليات السريرية الحساسة **غير متاحة دون اتصال** في المرحلة الحالية. لا يخزن العميل أمرًا قابلًا للتنفيذ لاحقًا ولا يعيد إرساله من تلقاء نفسه. أي دعم لاحق لعدم الاتصال يتطلب، لكل أمر، تصميم طابور محلي مشفر، ومعرّف أمر ثابت، ومراجعة تعارض عند الاستعادة، وتجربة تشغيلية موثقة، واعتمادًا مستقلًا عبر البوابة أعلاه.

## قائمة تحقق قبل التفعيل

- [ ] حزمة أثر وتشغيل معتمدة للطلب المحدد.
- [ ] سياسة تعارض وانتقال حالة معتمدة ومختبرة.
- [ ] صلاحية كتابة دقيقة وسياسة خادمية وتدقيق قرار.
- [ ] نطاق مورد مثبت عبر المستأجر والمؤسسة والمنشأة والجسر المناسب.
- [ ] معاملة ذرية للتغيير والتدقيق وidempotency وoutbox عند الحاجة.
- [ ] اختبار قبول ورفض وتعارض وإعادة محاولة وعزل لكل حد نطاق.
- [ ] مراجعة خصوصية محتوى الأثر وخطة احتفاظ وتصحيح.
- [ ] تحديث سجل العقود ومصفوفة الحوكمة بعد الاعتماد، لا قبله.

ما دامت أي خانة غير مكتملة، يبقى العقد **ممنوعًا** ويبقى زر الواجهة أو استدعاء العميل، إن وُجد، في حالة غير تشغيلية صريحة.
