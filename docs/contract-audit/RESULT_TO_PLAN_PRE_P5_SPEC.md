# مواصفة «نتيجتي إلى خطتي» قبل P5

**الحالة:** `P4_BLOCKED / NON_OPERATIONAL`  
**الغرض:** توحيد مسارات نتائج الفحوص والزيارة والمتابعة والإحالة في حزمة مستقبلية قابلة للمراجعة، **من دون** فتح قراءة سريرية، أو كتابة، أو نقطة API، أو واجهة مستخدم نشطة في هذه الدفعة.

> هذه الوثيقة ليست عقد تكامل ولا تصريحاً بعرض بيانات صحية. لا يحق لأي عميل ويب أو Android استخدام محتواها كمصدر للبيانات أو تفسيرها كقابلية تشغيل.

## 1. القرار

تبقى حزمة «نتيجتي إلى خطتي» محجوبة. أثبت جرد العقود أن الرعاية المستمرة محجوبة حوكميًا، وأن EHR غير صالح حاليًا للتكامل، وأن التوثيق والأوامر السريرية لا تملك عقدًا تشغيليًا موثوقًا للواجهة [1]. كذلك لا يكتمل P4 إلا بعد دليل التنفيذ والاختبار والأمن والحوكمة والمراجعة البشرية والدمج والتحقق الإنتاجي لكل معيار إلزامي [2].

لذلك تنفذ هذه الدفعة **مواصفات الحجب فقط**: لا توجد خدمة منشورة، ولا تغيير علم في الإنتاج، ولا بيانات اختبار تمثيلية، ولا ادعاء بوجود ربط مع مقدم خدمة أو جهة رسمية.

## 2. محفظة الخدمات المستقبلية

| المعرّف | الخدمة | المستخدم المقصود | الحد التشغيلي عند التفعيل المستقبلي | الحالة الحالية |
|---|---|---|---|---|
| R2P-01 | عرض نتيجة إلى مهمة متابعة | المواطن أو الفريق المخول | قراءة نتيجة منشورة ثم عرض خطوة متابعة أنشأها الخادم أو مقدم الرعاية | `BLOCKED` |
| R2P-02 | إحالة مغلقة الحلقة | الطبيب والمنشأة | تتبع الإحالة عبر انتقالات حالة خادمية مدققة | `BLOCKED` |
| R2P-03 | تنبيه آمن لتوافر النتيجة أو المتابعة | المواطن أو الممارس | تنبيه بلا تفاصيل سريرية على شاشة القفل؛ التفاصيل بعد جلسة مصرح بها | `BLOCKED` |
| R2P-04 | خطة رعاية مقروءة | المواطن وفريق الرعاية | قراءة أهداف ومهام معتمدة؛ لا توليد توصية أو تعديل من العميل | `BLOCKED` |
| R2P-05 | مصالحة دواء وإبلاغ أثر ضار | الصيدلي والطبيب | سير عمل مهني مصرح به؛ لا وصف أو تعديل أو قرار علاجي تلقائي | `BLOCKED` |

## 3. شكل المعمارية المطلوبة بعد الإغلاق

تكون تطبيقات الويب وAndroid **عملاء عرض خفيفة**. ولا تتصل هذه التطبيقات مباشرةً بوحدات EHR أو الرعاية المستمرة أو التمريض أو الأوامر. ينشأ بعد P4 فقط جسر قراءة خادمي موحد، يطلب قراراً من محرك التفويض القانوني قبل كل عملية، ويراجع سياق الحساب والتحقق والعضوية والدور والصلاحية والاستحقاق ومساحة العمل والمنشأة والمورد وعلم الميزة. لا يجوز وجود محرّك سياسة ثانٍ في العميل أو اعتماد أي حالة محلية كقرار تفويض.

لا يجوز للجسر المستقبلي أن يعيد نتيجة أو خطة أو إحالة إلا إذا ثبتت هوية المورد، ونطاق مساحة العمل، وموافقة المريض حيث تنطبق، وحالة المورد المنشورة، وقرار التفويض، وسجل التدقيق. وعند الرفض أو عدم التحقق، تستخدم الواجهة عقد أخطاء GULA القائم بلا تسريب للبيانات أو تراجع قديم أو بيانات بديلة [3].

## 4. بوابة التفعيل الإلزامية

| بوابة P4 | دليل مطلوب قبل تفعيل أي R2P | النتيجة عند الغياب |
|---|---|---|
| P4-19 | مصفوفة قرار تفويض فعلية لكل قراءة ومورد وسياق | لا جسر قراءة |
| P4-20 | حدث تدقيق خادمي ثابت لكل قبول ورفض حساس | لا عرض بيانات |
| P4-21 وP4-22 | مصفوفة تكافؤ الخلفية والويب وAndroid على عقد واحد | لا واجهة نشطة |
| P4-23 وP4-24 | اختبارات الرفض والعزل والتزامن على PostgreSQL | لا قراءة أو كتابة |
| P4-25 | نجاح SAST والاعتمادات والأسرار والامتيازات وفحوص الجودة المعتمدة | لا طرح |
| P4-27 | سجل ميزات ومُلكية ونطاق وعودة وتدقيق، والقيمة الإنتاجية OFF قبل الإذن | لا تفعيل |
| P4-31 وP4-32 | موافقة بشرية صريحة ثم دمج ونشر وتحقق من الالتزام الصحيح | لا انتقال إلى P5 |

## 5. اختبارات قبول لاحقة، لا تُنفذ الآن

| الاختبار | الإثبات المطلوب |
|---|---|
| منع القراءة خارج سياق المواطن أو المنشأة أو مساحة العمل | استجابة رفض غير كاشفة وسجل تدقيق للمحاولة |
| منع العميل من تقرير حالة الإحالة أو خطة الرعاية | رفض خادمي وتأكيد عدم تغير الحالة |
| عزل بيانات المريض عند التبديل والتزامن وإعادة المحاولة | اختبارات PostgreSQL للتزامن والتعددية والمورد المفرد والقائمة |
| التنبيه الآمن | لا تفاصيل حساسة في الإشعار؛ ولا رابط يفتح المورد بلا جلسة صالحة |
| إيقاف العلم والعودة | منع فوري للسطح الحساس مع الحفاظ على التدقيق وعدم إتلاف الحالة |

## 6. حدود صريحة

لا تنفذ هذه الحزمة تشخيصاً أو توصية علاجية أو وصفة أو تعديل نتيجة أو موافقة بديلة أو دمج هوية أو تسجيل مواطن أو OCR/NFC أو قياسات حيوية أو تكامل حكومي أو دفع. ويبقى الذكاء الاصطناعي، إن اعتمد لاحقاً، استشارياً وغير حاسم وتحت مراجعة مهنية.
