# تدقيق حدود التكامل بين frontend-v3 وجسر tRPC

## النتيجة

يوجد مساران منفصلان حاليًا. يستخدم تطبيق `gula-platform-ui-refresh` جسر tRPC خادميًا على `/api/trpc`، ويحتفظ برمز خدمة الخلفية وعنوانها في بيئة الخادم فقط. أما `frontend-v3` فيستعمل عميل Axios مباشرًا إلى `VITE_API_BASE_URL` أو `/api` مع ملفات تعريف ارتباط الجلسة؛ ويوجه وكيل التطوير `/api` إلى الخلفية على المنفذ `8000` [1] [2] [3].

كانت صفحتا المرضى والطلبات المنقولتان تفحصان سياق المنشأة والصلاحية عبر `GET /authz/me` و`POST /authz/check` ثم تستدعيان مورد القراءة ذاته. لا يمر هذا المسار عبر tRPC في مشروع ui-refresh [1] [4]، كما أن فحص المتصفح قابل للتجاوز بطلب REST مباشر ما دامت موجهات القراءة لا تفرض مفتاح الصلاحية الدقيق. لذلك تحولت `workspaceScopedReads` إلى **منع آمن افتراضي**: لا تطلب بيانات المرضى أو الطلبات، وتعيد سبب المنع `server_enforcement_required` حتى يثبت الحارس الخادمي أو يعتمد جسر موثق. ولا يصح تمرير رمز الخدمة إلى المتصفح بغرض توحيد المسارين.

| المكون | المسار الفعلي | الأسرار في المتصفح | حالة الحوكمة |
|---|---|---|---|
| `gula-platform-ui-refresh` | متصفح → `/api/trpc` → خادم ui-refresh → خلفية GULA | لا؛ رمز الخدمة خادمي فقط | يوجد تحقق خادمي لسياق المنشأة ثم للصلاحية قبل قراءة المرضى أو الطلبات. |
| `frontend-v3` | متصفح → بوابة قراءة تمنع العقدين غير المفروضين خادميًا | لا؛ يستخدم جلسة Cookie مع `withCredentials` | ممنوع افتراضيًا لعقدي المرضى والطلبات؛ لا يجري طلب REST للبيانات قبل تحقق فرض خادمي. |
| أسطح frontend-v3 الأخرى | متصفح → `/api` → خلفية GULA | لا بحسب العميل المركزي | خارج نطاق بوابة القراءة المنقولة حتى تسجل عقودها. |

## القرار الآمن

لا يدمج التدقيق المسارين تلقائيًا. إذ إن تحويل `frontend-v3` إلى tRPC يتطلب قرارًا معماريًا وتوحيدًا صريحًا للمصادقة والجلسة ومصدر الهوية، وإلا فقد تظهر قرارات تفويض متباينة أو يوسّع رمز الخدمة نطاق الثقة بلا مبرر. يضيف `pnpm verify:integration-boundary` حماية ثابتة تثبت فصل المسارين، وتمنع إدراج `GULA_BACKEND_SERVICE_TOKEN` أو `GULA_BACKEND_BASE_URL` أو `/api/trpc` في عميل `frontend-v3` أو بوابة قراءته.

> **بوابة النقل التالية:** لا يُفعّل أي عقد في `workspaceScopedReads` إلا إذا كان له مسار خلفي مسجل، ومفتاح صلاحية **مفروض داخل مسار البيانات**، وعزل منشأة مثبت، واختبار رفض سلبي. ولا ينقل إلى tRPC إلا بعد اعتماد قرار معماري يوحد هوية الجلسة وموضع فرض التفويض.
