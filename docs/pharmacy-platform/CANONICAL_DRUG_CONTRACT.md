# Canonical Drug Contract (frozen)

**Authority:** ADR-001 (national catalog), ADR-002 (GS1), ADR-005 (ATC), ADR-006 (identity model).
**Status:** FROZEN. Any change requires a new ADR.

This is the contract every Pharmacy artifact must conform to. It is the target
the physical schema, the ORM, the services and the API converge on. Where an
artifact disagrees with this document, the artifact is wrong.

---

## 1. Drug identity

A **Drug** is an entry in the global National Drug Catalog
(`pharmacy_drug_catalog`): a substance/strength/form identity, curated
nationally. It is the single source of truth for medication reference data
across GULA (ADR-001).

## 2. Public identity

`pharmacy_drug_catalog.drug_id` — **UUID4**, server-generated, `NOT NULL`,
`UNIQUE`, indexed, **immutable**. This is the only identifier that may appear in
a public API path, payload, export or report as _the_ identity of a drug.

It is a **GULA platform identity, not a Ministry of Health national
registration number.** A future MoH identifier is an additional external
identifier and must not replace this column or the primary key without a new ADR.

## 3. Internal identity

`pharmacy_drug_catalog.id` — `Integer`, database-assigned, **internal only**.
It is the target of every relational foreign key and must never be exposed as
the canonical public identity. Existing values are never rewritten.

## 4. `drug_code` semantics

A **mutable business/catalog code**. Unique, human-meaningful, editable through
an authorised catalog operation. It is:

- never a primary key,
- never a foreign key,
- never the authoritative key of a clinical rule,
- never the public identity.

It may be displayed, searched and exported as business data.

## 5. GTIN semantics

GS1 **GTIN identifies a package**, not a drug (ADR-002). It belongs on the
package/SKU entity. It must never be used as drug identity.

## 6. Tenancy

The catalog is **global**: it carries no tenant column. Tenant and facility
scope belong to inventory, stock, dispensing, cold-chain and controlled-substance
records, which reference the global drug by internal foreign key.

An entity is either global or tenant-scoped. Never both.

## 7. Clinical-rule relationship

Contraindication, allergy, dose-guideline, monitoring and substitution rules
reference the Drug by **internal foreign key**. A denormalised `drug_code` copy
may persist as display data, but it is never the authoritative relationship.

**Invariant:** editing a business code can never detach a clinical safety rule.

## 8. API identity

Public Pharmacy catalog endpoints identify a drug by `drug_id` (UUID4, String
shaped). The internal Integer primary key is never the canonical public
identifier. `drug_code` remains available as a business field and as a search
key, but is not an identity.

## 9. Inventory identity

Inventory records have their own identity, are tenant/location scoped, and
reference the global catalog by internal foreign key. Inventory never
duplicates catalog identity.

## 10. Immutability guarantees

| Guarantee                              | Enforcement                                                            |
| -------------------------------------- | ---------------------------------------------------------------------- |
| `drug_id` is server-generated          | database default / migration backfill; never from client input         |
| `drug_id` cannot be chosen by a client | rejected by the request schema and the service layer                   |
| `drug_id` cannot change after creation | rejected by the service layer; never regenerated by a migration re-run |
| `drug_id` is unique                    | database `UNIQUE` constraint                                           |
| `drug_id` is never derived             | not from the primary key, `drug_code`, GTIN, timestamps or user input  |
| Internal Integer PK is stable          | never rewritten by any migration                                       |
| `drug_code` changes only deliberately  | explicit authorised catalog operation, never a blind attribute update  |

## 11. Classification of every identifier-like field

Before any field is retyped or repointed it must be classified as exactly one of:

| Class           | Rule                                                                      |
| --------------- | ------------------------------------------------------------------------- |
| `INTERNAL_FK`   | must match the relational primary key type (`Integer` for the catalog)    |
| `PUBLIC_ID`     | `drug_id` UUID4 only                                                      |
| `BUSINESS_CODE` | `drug_code` and similar; never a key                                      |
| `EXTERNAL_ID`   | GTIN, ATC, `fhir_id`, `sync_id`; each in its own column, never overloaded |
| `TENANT_ID`     | `lab_id` / facility / location; never on the catalog                      |

**Only `INTERNAL_FK` fields are type-reconciled to the relational primary key.**
No other identifier is converted on the basis of a similar name.
