# دليل تنفيذ الخطوط الأساسية الذكية (AI Baselines) في GULA

يهدف هذا الدليل إلى تحويل GULA من نظام يعتمد على "الحدود الثابتة" إلى نظام "شخصي" يتعلم النمط الطبيعي لكل مريض باستخدام خوارزميات التعلم الآلي.

---

## 1. اختيار الخوارزميات (Algorithm Selection)

لتحقيق التوازن بين الدقة السريرية والكفاءة التقنية، نعتمد استراتيجية هجينة:

### أ. غابة العزل (Isolation Forest) - للبداية السريعة
- **الاستخدام:** اكتشاف القراءات الشاذة (Outliers) التي تبتعد بشكل كبير عن النمط العام للمريض.
- **الميزة:** لا تحتاج لبيانات ضخمة للبدء، وتعمل بشكل ممتاز مع البيانات الجدولية (مثل النبض، الضغط).

### ب. المشفرات التلقائية (Autoencoders) - للتحليل العميق
- **الاستخدام:** تعلم "التمثيل الطبيعي" لبيانات المريض المعقدة (مثل تخطيط القلب أو أنماط النوم).
- **المنطق:** يتم تدريب النموذج على إعادة بناء بيانات المريض الطبيعية؛ إذا فشل النموذج في إعادة بناء قراءة جديدة بدقة عالية، فهذا يعني أنها "شاذة".

---

## 2. معمارية النظام داخل GULA

يتم دمج هذه الخوارزميات في وحدة `shared/ai` كالتالي:

### المرحلة الأولى: تجميع البيانات (Data Aggregation)
يتم سحب البيانات التاريخية للمريض من `shared/storage` وتصنيفها حسب:
- الوقت (صباح/مساء).
- النشاط (عبر مستشعر الحركة).
- الحالة السريرية (عبر التشخيص المسجل).

### المرحلة الثانية: تدريب النموذج الشخصي (Personalized Training)
يتم إنشاء "نموذج مصغر" (Micro-model) لكل مريض:
```python
# تصور برمجي داخل shared/ai/provider.py
class PatientBaselineModel:
    def train(self, patient_id: str, historical_data: list):
        # تدريب Isolation Forest على بيانات المريض
        self.model = IsolationForest(contamination=0.05)
        self.model.fit(historical_data)

    def is_anomaly(self, new_reading: float) -> bool:
        # تقييم القراءة الجديدة
        prediction = self.model.predict([[new_reading]])
        return prediction == -1 # -1 يعني شاذة
```

### المرحلة الثالثة: الاستدلال اللحظي (Real-time Inference)
عند وصول قراءة جديدة عبر `EventBus`:
1. يتم استدعاء النموذج الشخصي للمريض.
2. إذا كانت القراءة "شاذة" إحصائياً، يتم تمريرها لمحرك القواعد السريرية.
3. إذا كانت "طبيعية" لهذا المريض (حتى لو كانت خارج الحدود العامة)، يتم تجاهلها أو وسمها كـ "طبيعية شخصية".

---

## 3. حلقة التغذية الراجعة (Feedback Loop)

لضمان تحسن النموذج، يجب إشراك الطبيب:
- عندما يرسل النظام تنبيهاً، يحدد الطبيب: **"تنبيه حقيقي"** أو **"تنبيه كاذب"**.
- يتم استخدام هذه الإجابة لإعادة تدريب النموذج (Reinforcement Learning) لتقليل الخطأ في المرة القادمة.

---

## 4. مثال تطبيقي: مريض رياضي
- **الحد العام:** نبض القلب < 60 يعتبر "تباطؤ قلب" (Bradycardia).
- **النمط الشخصي:** المريض رياضي ونبضه وقت الراحة 45.
- **سلوك GULA:** النظام يتعلم أن 45 هي "الخط الأساسي" لهذا المريض، فلا يزعج الطبيب بتنبيهات مستمرة، ولكنه يطلق التنبيه إذا وصل النبض لـ 35.

---

## 5. التوصيات التقنية للتنفيذ

1.  **التدريب على دفعات (Batch Training):** إعادة تدريب النماذج الشخصية أسبوعياً لتعكس التغيرات في حالة المريض الصحية.
2.  **الخصوصية:** التأكد من أن النماذج الشخصية مشفرة ولا يتم مشاركة بيانات مريض لتدريب نموذج مريض آخر (Privacy-Preserving ML).
3.  **التكامل مع `shared/metrics`:** استخدام المقاييس الحالية لمراقبة أداء النماذج (دقة التنبؤ، معدل التنبيهات الكاذبة).

---
**النتيجة:** بهذا النظام، تصبح GULA منصة "ذكية حقاً" لا تكتفي بتطبيق القواعد، بل تفهم مريضها وتتطور معه، مما يضعها في مصاف المنصات الصحية الأكثر تقدماً في العالم.
