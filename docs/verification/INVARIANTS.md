# Invariant Registry

**Generated:** 2026-09-25 · **Head:** `d8c2a31b`

An invariant is a statement that must hold _however_ the operation is attacked.
Each row names the evidence that would earn it and the evidence that exists.
`UNKNOWN` is never promoted by argument.

Domain-specific invariants are separated from platform ones on purpose: the
platform rules generalise, the clinical rules do not, and treating a clinical
rule as generic is how a second-actor check gets refactored away.

## Invariants deliberately not asserted

| Question                                                                             | Why not                                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Should the ICU router require `system:admin`?                                        | Of sixteen roles, only `master_admin` holds it, so no bedside clinician can use the ICU platform. That is an authorization-model decision with clinical consequences, not a defect to patch. Recorded; WP-003. |
| What should follow `ordered`, `dispensed`, `reacted`, `cancelled` for a transfusion? | Clinical policy (NR-020 remainder). Guessing would invent clinical semantics.                                                                                                                                  |
| Who may perform cross-account adaptive-auth reads?                                   | NR-019. A capability decision.                                                                                                                                                                                 |
