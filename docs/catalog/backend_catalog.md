## 9. Audit

- Hash-chained tamper-evident trail: `chain_hash = SHA-256(prev + canonical JSON)`, genesis `0`*64; no-UPDATE trigger on PG; anchor checkpoints every 100 entries (HMAC-SHA256, key rotation); `verify_audit_chain`.
- Table `audit_logs`: id, user_id, user_role, action, resource_type, resource_id, details, ip_address, created_at, chain_hash.

## 13. Findings

- 3 dangling FK targets exist in ORM metadata: niam_adaptive_mfa_sessions->niam_user_sessions, niam_trust_frameworks->niam_identity_authorities, niam_trust_proofing->niam_identity_authorities. Tables only exist in Alembic migrations; any query touching those models raises NoReferencedTableError at mapper configuration (tests survive via conftest stub tables).
- Outbox pattern: producers (national streaming, claims, data platform, MPI, document intelligence) but ZERO registered event consumers - outbox is reliable logging, not workflow-driving.
- Authorization is fragmented across 5 systems (legacy enum 13 perms, extended map 16, national 39, enterprise DB 92, kernel 11) with 2 inverted string formats (read:patients vs patients:read); effective permissions differ by auth path (JWT vs DB-assigned).
- 3 route sets are permanently locked out by orphan permission strings never granted: require_permission('admin') knowledge_graph (7 routes), 'simulation:read' (5), 'simulation:write' (3) - always 403.
- require_role('national_admin','directorate_admin') in governance routes references roles absent from EXTENDED_ROLE_LEVELS (level 0 in hierarchy checks).
- Citizen role has ZERO extended permissions; citizen portal relies on inline role==citizen checks instead of the permission layer.
- LabUser.role is a free-form string (default 'staff'); no constraint to any role vocabulary; authorization_service._check_assignment_permission is a stub returning True.
- Clinical state gating (can_release_results / requires_physician_ack) is implemented but not wired to any result-release endpoint.
- Claims workflow ends at 'submitted' - no adjudication/reimbursement states.
- require_service_account (gula_* API keys) is defined but unused by any route; no route accepts service-account keys.
- GET /test-profiles is fully open (no auth, no rate limit); POST /logout performs no authentication; /metrics/prom is unauthenticated.
- CareContinuumBase and ClinicalBase are separate declarative bases with FKs to national_* tables; CareContinuumBase FKs are not resolvable in its own metadata (EHR fixed earlier via EHRBase = NationalBase; care_continuum still at risk when mappers configure eagerly).
- workflows/ package is empty; real workflow machinery lives in domain/order_state.py + national/workflow_runtime (scaffold: application/service.py is 0 lines) + capabilities/workflow_engine (CRUD-only).
- Offline sync dual-implemented: services/offline_sync_service.py (no route consumers) vs integration/offline.py (wired to /integration/offline/sync).
- Only one task handler registered (national_notification_deliver); documented send_notification handler has no registration.
- GET /setup/status leaks setup state unauthenticated (intentional but worth gating in production).
- Frontend calls backend root paths directly (VITE_API_BASE_URL=http://localhost:8000, no /api prefix); /mobile mobile_router not registered in factory; /authz/* routes have no frontend consumers.
