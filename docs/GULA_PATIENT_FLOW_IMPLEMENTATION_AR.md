# تنفيذ مسار المريض الحكومي في GULA

**الحالة:** منفذ على فرع `manus/government-patient-flow`، ولم يُدمج في `main` بعد.

## الملخص التنفيذي

تم تحويل نتائج تدقيق مسار المريض إلى تنفيذ فعلي يركز على تقليل عدد الخطوات اليومية دون تجاوز الحواجز السريرية. أصبح للمؤسسة الحكومية مسار تشغيل موحد يبدأ من تسجيل الوصول، ثم الطابور والفرز والخدمة والقبول أو النقل، وينتهي بالخروج. ويعتمد الانتقال على الخادم، مع فحص النسخة، ومفتاح منع التكرار، وسجل تدقيق، ورفض صريح لأي انتقال غير مسموح.

تم أيضًا إصلاح نقاط التقاطع الأساسية بين نماذج المختبر والنطاق الوطني ونماذج المستشفى. لم يعد `facility_id` يُستخدم بدلًا من `hospital_id`، ولم يعد الموعد الحكومي يقبل معرف مريض محليًا بصمت؛ بل يتحقق من وجود المريض الوطني النشط داخل نطاق المؤسسة. كما تم ربط `national_router` فعليًا بتطبيق FastAPI، لأن وجود المسارات في الملفات وحده لم يكن كافيًا لجعلها قابلة للوصول.

## ما تم تنفيذه

| المجال | التنفيذ |
|---|---|
| نطاق المؤسسة | إضافة `hospital_id` صريح إلى Appointment وEncounter؛ منع إنشاء مستشفى خاص من مسار المؤسسة الحكومية. |
| منع التكرار | إضافة `idempotency_key` إلى Appointment وEncounter مع فهارس فريدة ضمن نطاق المختبر والمؤسسة. |
| المواعيد | التحقق من وجود المريض الوطني، منع التداخل غير الملغى، توحيد `provider_id` إلى `practitioner_id`، ورفض الموعد بلا `hospital_id`. |
| الأسرة | جعل النقل عملية ذرية، منع النقل إلى السرير نفسه أو غير المتاح، والتحقق من وجود assignment فعال قبل إغلاقه. |
| مؤشرات الأسرة | تقييد احتساب الأسرة بالمستشفى الفعلي بدل احتساب كل أسرة المختبر. |
| الصلاحيات | إضافة صلاحيات `hospital:*`، وربط القراءة والإدارة والقبول والنقل والخروج والمواعيد بحواجز خادمية. |
| الموافقة | إيقاف المسار الوطني الشكلي الذي كان يعيد نجاحًا وهميًا، وتحويله إلى فشل واضح مع الإشارة إلى `/consent`. |
| عزل السجلات | تمرير `lab_id` إلى قراءة وتعديل وحذف وإكمال وإلغاء وبحث Encounter. |
| مسار المريض | إضافة `Patient Flow Core` بآلة حالات محددة وانتقالات غير قابلة للتجاوز. |
| الواجهة | إضافة صفحة `/patient-flow` سريعة تعتمد على API الحقيقي والطابور الخادمي، ولا تنشئ مريضًا محليًا أو تعرض نجاحًا وهميًا. |

## آلة الحالات التشغيلية

| الحالة | الانتقالات المسموحة |
|---|---|
| `planned` | `arrived` أو `cancelled` |
| `arrived` | `triaged` أو `cancelled` |
| `triaged` | `in_progress` أو `cancelled` |
| `in_progress` | `admitted` أو `discharge_pending` أو `transfer_pending` أو `cancelled` |
| `admitted` | `in_progress` أو `discharge_pending` أو `transfer_pending` |
| `transfer_pending` | `admitted` أو `cancelled` |
| `discharge_pending` | `discharged` أو `in_progress` |
| `discharged` و`cancelled` | حالات نهائية؛ لا انتقالات لاحقة |

تُرفض أي محاولة لتجاوز الفرز أو القبول أو الخروج. وإعادة إرسال نفس الانتقال للحالة نفسها عملية idempotent ولا تنشئ أثرًا جانبيًا مكررًا. أما النسخة القديمة من السجل فتُرفض إذا كانت أقدم من النسخة الحالية.

## واجهات التشغيل المختصرة

| العملية | المسار |
|---|---|
| تسجيل الوصول | `POST /national/patient-flow/arrivals` |
| قراءة الطابور | `GET /national/patient-flow/queue?hospital_id={id}` |
| تنفيذ انتقال | `POST /national/patient-flow/{encounter_id}/transition` |
| إنشاء موعد حكومي | `POST /hospital/appointments` |
| نقل المريض بين الأسرة | `POST /hospital/beds/{bed_id}/transfer` |

يرتب الطابور الحالات الحرجة أولًا، ثم حسب الأولوية، ثم حسب وقت الوصول. وتُحدّث صفحة التشغيل كل 15 ثانية، مع زر تحديث فوري، وتعرض رسائل خطأ عند رفض التعارض بدل إخفائه.

## الترحيلات

تم إنشاء ترحيلين متسلسلين:

| الترحيل | الغرض |
|---|---|
| `20260817_0023_hospital_appointment_scope.py` | إضافة `hospital_id` و`idempotency_key` وفهارس المواعيد. |
| `20260817_0024_encounter_flow_state.py` | إضافة `hospital_id` و`idempotency_key` وحالة التدفق وتوقيتات الوصول والفرز والقبول والخروج وفهارسها. |

يجب تطبيق الترحيلات في بيئة النشر باستخدام `alembic upgrade head` بعد أخذ نسخة احتياطية والتحقق من اتصال قاعدة البيانات. لا ينبغي تشغيلها على إنتاج حكومي دون خطة رجوع وموافقة مسؤول قاعدة البيانات.

## التحقق والاختبارات

تم تشغيل فحص الصياغة للملفات المعدلة، واختبارات آلة الحالات والموافقة والتهيئة الوطنية، ثم مجموعة backend كاملة. النتيجة الأخيرة هي **2659 اختبارًا ناجحًا، 4 اختبارات متجاوزة، و252 تحذيرًا غير حاجب**. كما نجح `frontend-v3` في `typecheck` و`eslint` للملفات المعدلة و`build` الكامل، وظهر bundle صفحة التشغيل السريع في البناء النهائي.

التحذيرات الموجودة في suite الكاملة تتعلق أساسًا باستخدامات قديمة لـ`datetime.utcnow()` وتحذيرات مكتبات خارجية، وليست فشلًا في التغييرات الحالية.

## ملاحظات الإطلاق

هذا التنفيذ يجهز نواة التشغيل ولا يثبت وحده جاهزية المؤسسة الحكومية للإطلاق السريري. قبل الإنتاج يجب ربط هوية المريض الوطني بمصدر حكومي موثوق، وتحديد سياسة break-glass، وتطبيق migration على قاعدة الإنتاج بعد مراجعة، وإجراء اختبار ضغط واقعي، واختبار استعادة النسخ الاحتياطية، واعتماد قوائم الفرز والخروج من المسؤول السريري. كما يجب عدم اعتبار بيانات العرض القديمة في `PatientManagementWorkspacePage` مصدرًا تشغيليًا؛ صفحة `/patient-flow` الجديدة هي المسار المرتبط بالعقود الخادمية.
