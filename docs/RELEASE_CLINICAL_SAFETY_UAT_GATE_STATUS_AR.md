## 2. بوابة التشغيل الآلي الإلزامية

بعد معالجة عائق الحساب، يعاد تشغيل جميع البوابات على **نفس رأس فرع الإصدار**. يجب أن تكون كل نتيجة نهائية ناجحة قبل بدء قرار المراجعة.

| التسلسل | التحقق                             | معيار القبول                                                                  | المالك                |
| ------: | ---------------------------------- | ----------------------------------------------------------------------------- | --------------------- |
|       1 | CI Pipeline                        | نجاح `Syntax Gate` ثم كل المهام التابعة، بما فيها الترحيلات والانحدار السريري | مهندس المنصة          |
|       2 | Quality/Formatting/Security/CodeQL | نجاح تام، أو استثناء موثق ومصدق لا يخص مساراً سريرياً ولا يخفض بوابة          | الأمن والهندسة        |
|       3 | Frontend/Mobile                    | نجاح البوابات أو قرار فصل نطاق موثق لا يؤثر في الإصدار السريري                | مالك الواجهة/الموبايل |
|       4 | إعادة التحقق المحلي                | إعادة حزمة الانحدار السريري و`alembic heads`                                  | مهندس الإصدار         |

> يمنع إخفاء الفشل أو تحويل البوابة إلى تحذير لتجاوز هذا السجل. أي استثناء لا بد أن يثبت سبب عدم الصلة، والأثر، والمالك، وتاريخ انتهاء، وموافقة صريحة.

## 5. قرار تحويل PR وحذف الفروع

يبقى PR #242 **مسودة** ولا ينفذ دمج تلقائي. لا يجري تحويله إلى مراجعة إلا إذا كان كل ما يأتي صحيحاً: بوابات GitHub ناجحة، UAT مكتمل وموقع، لا توجد حالة مانعة مفتوحة، والرأس هو المعتمد.

لا يحذف أي فرع الآن. بعد الدمج ومراقبة مستقرة لا تقل عن سبعة أيام، يُراجع [سجل جرد الفروع البعيدة](reports/GULA_REMOTE_BRANCH_CLEANUP_REGISTER_20260821.csv) من مالك كل فرع. يقتضي كل حذف وسم أرشفة، وقراراً مسجلاً، وموافقة مالك، وتاريخ تنفيذ. لا تشمل هذه القاعدة فروع `main` و`develop` و`staging` أو الفروع ذات طلبات مفتوحة.
