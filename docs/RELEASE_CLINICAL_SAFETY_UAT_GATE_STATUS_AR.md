## 2. بوابة التشغيل الآلي الإلزامية

بعد معالجة عائق الحساب، يعاد تشغيل جميع البوابات على **نفس رأس فرع الإصدار**. يجب أن تكون كل نتيجة نهائية ناجحة قبل بدء قرار المراجعة.

| التسلسل | التحقق | معيار القبول | المالك |
|---:|---|---|---|
| 1 | CI Pipeline | نجاح `Syntax Gate` ثم كل المهام التابعة، بما فيها الترحيلات والانحدار السريري | مهندس المنصة |
| 2 | Quality/Formatting/Security/CodeQL | نجاح تام، أو استثناء موثق ومصدق لا يخص مساراً سريرياً ولا يخفض بوابة | الأمن والهندسة |
| 3 | Frontend/Mobile | نجاح البوابات أو قرار فصل نطاق موثق لا يؤثر في الإصدار السريري | مالك الواجهة/الموبايل |
| 4 | إعادة التحقق المحلي | إعادة حزمة الانحدار السريري و`alembic heads` | مهندس الإصدار |

> يمنع إخفاء الفشل أو تحويل البوابة إلى تحذير لتجاوز هذا السجل. أي استثناء لا بد أن يثبت سبب عدم الصلة، والأثر، والمالك، وتاريخ انتهاء، وموافقة صريحة.

## 3. سجل UAT المطلوب بالتواقيع

يُنفذ الاختبار في `staging` فقط وببيانات وهمية خالية من PHI. تسجل معرفات الطلبات والأوقات ونتائج HTTP وإثبات التدقيق، من دون نسخ قيم تعريفية أو نتائج مرضى فعلية في هذا الملف.

| الدور | النطاق الإلزامي | الدليل المطلوب | الاسم/التوقيع | التاريخ | القرار |
|---|---|---|---|---|---|
| فني مختبر | تعريف العينة، الإدخال، رفض الانتقال غير القانوني | نتائج الحالة ومعرف سجل التدقيق |  |  |  |
| أخصائي اعتماد مختبر | الاعتماد، التصحيح، منع إعادة اعتماد غير مصرح | أثر الحالة وسجل تدقيق |  |  |  |
| طبيب مستلم | التحقق من النتيجة النهائية والتنبيه الحرج | إيصال/سجل إشعار بلا PHI |  |  |  |
| مسؤول خصوصية/أمن | عزل المؤسسات، الرؤوس، منع التخزين، تنقيح المقاييس | مخرجات فحوص مسجلة |  |  |  |
| مهندس منصة | الجاهزية، الرحلات، التكرار، المراقبة | سجل تشغيل ومقاييس خالية من PHI |  |  |  |
| قائد سلامة سريرية | مراجعة الاستثناءات وحالات الرفض | قرار قبول نهائي |  |  |  |

## 4. السيناريوهات المانعة للقبول

تُنفذ السيناريوهات التفصيلية في [حزمة حالات الحافة للدفعة الأولى](UAT_BATCH1_LIMS_EDGE_CASES_AR.md). لا يقبل الإصدار إن فشل أي من الحالات التالية أو لم يتوفر دليلها.

| فئة الضابط | السيناريو | نتيجة القبول |
|---|---|---|
| التزامن | `If-Match` غائب أو قديم أو متعارض | رفض آمن، بلا تعديل للمورد، وسجل تدقيق |
| عدم التكرار | مفتاح مفقود أو مكرر أو متزامن أو أُعيد بعد مهلة شبكة | لا أثر جانبي مكرر وإيصال محفوظ |
| آلة الحالات | نتيجة لعينة غير متحققة، أو تجاوز مسار `draft → final → corrected` | رفض واضح وسجل محاولة غير قانونية |
| الصلاحيات | اعتماد/إقرار/تصحيح من دور غير مخول | رفض 4xx مناسب وسجل تدقيق |
| النتيجة الحرجة | إقرار قبل الإبلاغ أو من مستخدم غير مخول أو تكرار الإقرار | رفض أو معالجة آمنة بلا ازدواج |
| عزل المؤسسة | معرف مورد تابع لمؤسسة مختلفة أو مفتاح معاد استخدامه عبر مؤسستين | عدم كشف المورد وعدم تنفيذ التغيير |
| الخصوصية | PHI في مقاييس أو تتبع أخطاء أو رؤوس تخزين مؤقت ناقصة | لا بيانات تعريفية في المخرجات والحماية مفعلة |
| الجاهزية | بدء خدمة أو تنفيذ أمر أثناء جاهزية جزئية | رفض مغلق وتحويل النظام إلى مسار آمن |

## 5. قرار تحويل PR وحذف الفروع

يبقى PR #242 **مسودة** ولا ينفذ دمج تلقائي. لا يجري تحويله إلى مراجعة إلا إذا كان كل ما يأتي صحيحاً: بوابات GitHub ناجحة، UAT مكتمل وموقع، لا توجد حالة مانعة مفتوحة، والرأس هو المعتمد.
