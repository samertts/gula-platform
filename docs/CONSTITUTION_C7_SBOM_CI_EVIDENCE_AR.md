# دليل C7: أثر SBOM قابل للتحقق في CI

**الفرع:** `fix/ci-sbom-artifact-guard`
**التزام التنفيذ:** `1d431e14aa0742c614d6c3b4d13d6826f8b4c864`
**الحالة:** أضيف ضابط توليد SBOM إلى تعريف CI؛ لم يُشغّل على GitHub بعد، ولذلك يبقى C7 وحالة الإطلاق **مفتوحين / NO-GO**.

> تنتج هذه الدفعة ملفاً برمجياً يصف المكونات، لا مسح ثغرات، ولا إصلاح اعتماديات، ولا نشر، ولا رفع release asset، ولا قرار قبول للإطلاق.

## الخطر المعالج

سجل التحقق الدستوري يسجل غياب SBOM في CI كفجوة C7 ويطلب إضافة توليد SBOM إلى المسار. من دون أثر محفوظ وقابل للفحص لا يمكن لصاحب الأمن تأكيد مجموعة المكونات التي فحصها تدقيق الاعتماديات لالتزام مرشح محدد. [1]

## الضابط المضاف

| المجال | التطبيق |
|---|---|
| نقطة التشغيل | وظيفة مستقلة `sbom` تعتمد فقط على `syntax-gate` في `.github/workflows/ci.yml`. |
| المولد | `anchore/sbom-action` مثبت إلى commit `e22c389904149dbc22b58101806040fa8d37a610`، مع Syft `v1.51.0`. |
| النطاق والمخرج | مسح workspace وإخراج `artifacts/gula-platform.cdx.json` بصيغة CycloneDX JSON. |
| أقل صلاحيات | الوظيفة تعلن `contents: read` فقط. لا تملك إذن `contents: write`. |
| عدم النشر | عطلت `upload-artifact` الخاص بالمولد و`upload-release-assets`؛ لا إنشاء release asset ولا dependency submission. |
| الأثر | يرفع `actions/upload-artifact` المثبت إلى `ea165f8d65b6e75b540449e92b4886f43607fa02` الأثر باسم ثابت لمدة 30 يوماً، ويفشل عند غياب الملف. |
| فشل مغلق | `validate_sbom_artifact.py` يرفض الملف غير القابل للقراءة أو غير CycloneDX أو بلا `specVersion` أو بلا قائمة مكونات مسماة وغير فارغة. |

اختيرت طريقة إخراج ملف ثم رفعه منفصلة عن رافع المولد لتبقى صلاحية الوظيفة أدنى من صلاحية النشر ولتمنع رفع SBOM كأصل لإصدار تلقائياً. توثق Action الرسمية أن رفع release asset يتطلب صلاحيات أوسع، وأن صيغة CycloneDX JSON ومخرج الملف مدعومان. [2] كما توثق GitHub أن أثر workflow يخزن نواتج التشغيل بعد انتهائه. [3]

## الأدلة المحلية

| التحقق | النتيجة |
|---|---|
| اختبارات `validate_sbom_artifact` | 4/4 ناجحة؛ نجاح بنية صحيحة ورفض SPDX والمكونات الفارغة وJSON التالف. |
| اختبار تعريف workflow | 1/1 ناجح؛ يثبت pinning والصلاحية `contents: read` وتعطيل النشر ورفض الملف الغائب. |
| Ruff | ناجح على مدقق SBOM واختباراته. |
| MyPy | ناجح على الملفات الثلاثة الجديدة. |
| `git diff --check` | ناجح قبل الالتزام. |
| بوابة changed-files مقابل RC1 | **PASS** على الالتزام `1d431e14`: Ruff `0→0` وMyPy `0→0` للملفات المتغيرة؛ الدين التاريخي الحرج لم يتغير: Ruff `27` وMyPy `510`. |

لم يجرِ توليد SBOM فعلي لهذا المستودع محلياً في هذه الدفعة؛ اختبارات المدقق تستعمل fixtures تركيبية فقط. ولم تنجح CI الخارجية بعد بسبب عائق الحساب/الإنفاق المعروف، ولذلك لا يصح تحويل هذه الأدلة إلى نجاح CI أو امتثال C7 كامل.

## المتطلبات لإغلاق C7

يلزم للمالك البشري إزالة عائق CI، وتشغيل الوظيفة على commit مرشح، ثم حفظ رابط التشغيل وSHA الأثر ووقت الإنتاج ونتيجة المدقق. يجب أن يراجع الأمن الـSBOM الناتج لمكونات Python وNode وAndroid وأي صورة/حزمة إطلاق فعلية، وأن يقارن الفحص مع lockfiles وartifact المبني. يلزم أيضاً تحديد سياسة الاحتفاظ ومسؤوليتها وتدفق التعامل مع مكونات ضعيفة أو غير معروفة. لا تكفي مجرد رؤية job خضراء من دون الأثر ومراجعته.

> لا يعد C7 «محلولاً» ولا تحول هذه الدفعة قرار RC1 من NO-GO إلى GO. تبقى كذلك أدلة الترحيل والاستعادة، UAT، Android الموقّع، mTLS للأجهزة، وقرار الإنسان المخول.
