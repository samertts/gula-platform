# Command 06 — Gap Analysis and Safe Remediation Plan

## Priority findings

| Priority | Finding | Root cause | Safe remediation direction | Acceptance evidence |
|---:|---|---|---|---|
| P0 | Legacy `/authz` delegation mutators do not prove delegator authority or maximum privilege. | The legacy service creates a delegation from client-provided role/scope using only the authenticated legacy `User`. | Add a server-side management gate before legacy delegation create/revoke; validate target role, scope ownership, active assignment, delegation eligibility, bounded dates, and same tenant/facility boundary. Deny by default when proof is absent. | Tests for unauthorized create/revoke, cross-organization scope, expired/revoked delegation, and audit deny. |
| P0 | Membership/role revocation does not visibly propagate to sessions and workspace contexts. | Lifecycle services change status and audit but do not invalidate affected `UserSession` rows or active `WorkspaceSessionContext`. | Add a shared async revocation helper that deactivates sessions and contexts for the affected account, invoked on membership revoke/suspend/expiry and role revoke. No production data modification. | Tests show session/context invalidation and authorization deny immediately after revocation. |
| P0 | Audit service does not populate its existing facility/workspace/decision/reason/request/correlation columns. | `IdentityAuditEntry` has the columns, but callers pass most context through generic metadata only. | Extend audit APIs with explicit bounded context fields and include them in the chain hash. Preserve compatibility defaults. | Audit tests query columns and verify hash integrity; no secret/patient payload. |
| P1 | Workspace status/context and organization/facility alignment are incomplete. | `Workspace.facility_id` has no FK; `_validate_context()` does not verify workspace active status or facility alignment. | Validate workspace active/allowed lifecycle and derive/check organization/facility consistency server-side before membership/invitation and switch. | Cross-org/facility/workspace deny tests and migration FK/index review. |
| P1 | Organization management authority does not validate actor account state or validity windows. | Ownership/representative queries check only active row status. | Require active actor account and `valid_from`/`expires_at` windows for ownership/representative authority. | Expired/suspended authority tests deny management. |
| P1 | Invitation acceptance/replay has an audit naming issue and lacks explicit row-lock proof. | Invalid token is recorded under `invitation_accepted`; acceptance reads a pending row without `FOR UPDATE`. | Correct deny action/reason and use row lock where supported; preserve safe behavior for SQLite tests. Do not expose token hashes. | Wrong account, invalid token, expired, replay, concurrent acceptance tests. |
| P1 | Role/permission scope is distinct but Entitlement/Delegation is not a NIAM object. | NIAM has Role/Permission/RoleAssignment but no separate entitlement or delegation aggregate. | Do not fake a provider. Keep role/permission server-authoritative and classify Entitlement as not implemented; harden legacy delegation boundary. | Inventory/report marks MISSING/PARTIAL honestly. |
| P1 | Frontend auto-selects a lone workspace and caches permissions at organization granularity. | `AuthContext` calls `switchWorkspace()` automatically and `effectivePermissions` is keyed only by organization. | Remove implicit client auto-switch; require explicit selection, and refresh scoped permissions after switch. Server remains authoritative. | Auth state/UI tests show `WORKSPACE_REQUIRED` until explicit switch and no stale permission map. |
| P2 | Duplicate policy/authorization stacks remain. | NIAM and legacy services coexist for compatibility. | Do not delete legacy routes in this command; make their high-risk mutation boundaries fail-closed and document migration status. | Static inventory and legacy boundary tests. |
| P2 | Native cross-platform Command 06 parity is not proven. | Android/iOS/Flutter SDKs were unavailable during Command 05. | Update only if an existing typed contract can be identified; otherwise classify `UNVERIFIED` rather than claim parity. | Source inventory plus available web tests. |

## Safe-stop triggers

Implementation stops and remains `AUTHORIZATION_CONTEXT_BLOCKED` if any new test demonstrates cross-tenant leakage, IDOR/BOLA, privilege escalation, stale privilege after revocation, audit failure for a deny, data corruption, or an unsafe migration. No automatic merge, production deployment, production database change, public registration, or privilege bypass is allowed.
