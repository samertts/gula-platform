# GULA Certification Framework

## Overview

The GULA Certification Framework establishes a comprehensive digital certification
ecosystem for healthcare organizations, professionals, and technology partners
within the Iraqi healthcare ecosystem. Certifications validate competence,
compliance, and compatibility with the GULA platform.

### Certification Philosophy

1. **Trust through Verification**: Every certification is evidence-based and verifiable
2. **Continuous Improvement**: Certifications drive quality improvement, not just compliance
3. **Patient Safety Focus**: Clinical certifications prioritize patient safety outcomes
4. **Arabic-First Excellence**: All certification materials and processes available in Arabic
5. **International Recognition**: Aligned with global standards for interoperability

## 2. Certification Process

### Standard Process Flow

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│          │    │          │    │          │    │          │    │          │    │          │
│Application│───►│Pre-      │───►│  Audit   │───►│Remediation│───►│  Issue   │───►│Surveillance│
│          │    │Assessment │    │          │    │          │    │Certificate│    │          │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### Phase 1: Application

| Step | Description | Documents | SLA |
|------|-------------|-----------|-----|
| 1.1 | Submit application via GULA Certification Portal | Application form, scope declaration | 1 day |
| 1.2 | Initial document review | Organization profile, certifications held | 3 days |
| 1.3 | Eligibility determination | Eligibility checklist, risk assessment | 2 days |
| 1.4 | Fee assessment and payment | Fee schedule, invoice | 5 days |
| 1.5 | Audit team assignment | Audit team composition, conflict check | 3 days |
| 1.6 | Audit schedule agreement | Proposed dates, resource requirements | 5 days |

**Total SLA: 19 business days**

### Phase 2: Pre-Assessment

| Step | Description | Documents | SLA |
|------|-------------|-----------|-----|
| 2.1 | Document submission by applicant | Quality manual, SOPs, policies | 10 days |
| 2.2 | Document review by auditors | Review checklist, gaps identified | 10 days |
| 2.3 | Pre-assessment report | Gap analysis, readiness score | 3 days |
| 2.4 | Corrective action (if needed) | CAP plan, evidence of correction | 10 days |

**Total SLA: 33 business days (can overlap with Phase 3)**

### Phase 3: Audit

| Audit Type | Description | Duration | Frequency |
|------------|-------------|----------|-----------|
| **On-Site Audit** | Full physical inspection | 2-5 days | Initial + renewal |
| **Remote Audit** | Video-based document review | 1-3 days | Surveillance |
| **Hybrid Audit** | Combined on-site + remote | 2-4 days | Initial preferred |
| **Continuous Monitoring** | Automated data-based assessment | Ongoing | All certifications |

**On-Site Audit Components:**

| Component | Duration | Focus |
|-----------|----------|-------|
| Opening meeting | 30 min | Scope, schedule, logistics |
| Facility tour | 1-2 hours | Physical environment, equipment |
| Document review | 4-8 hours | Policies, SOPs, records |
| Staff interviews | 2-4 hours | Competency verification |
| System demonstration | 2-4 hours | GULA workflow demonstration |
| Process observation | 2-4 hours | Real-time workflow observation |
| Closing meeting | 1 hour | Findings, report timeline |

### Phase 4: Remediation

| Finding Type | Definition | Remediation Period | Verification |
|--------------|------------|-------------------|--------------|
| **Critical** | Patient safety risk or data integrity threat | 5 business days | On-site re-verification |
| **Major** | Significant non-conformance | 15 business days | Evidence submission |
| **Minor** | Isolated non-conformance | 30 business days | Evidence submission |
| **Observation** | Improvement opportunity | N/A (recommendation) | N/A |

### Phase 5: Certification Decision

| Outcome | Criteria | Action |
|---------|----------|--------|
| **Certified** | Zero critical, zero major, minor closed | Certificate issued |
| **Conditionally Certified** | Minors open with CAP, no critical/major | Certificate with conditions |
| **Deferred** | Major non-conformances open | Re-audit required |
| **Denied** | Critical finding or uncorrected major | Application rejected |

### Phase 6: Surveillance

| Surveillance Type | Frequency | Method |
|-------------------|-----------|--------|
| **Continuous automated** | Real-time | API-based monitoring of GULA metrics |
| **Periodic remote** | Quarterly | Remote document review |
| **Periodic on-site** | Annually | Half-day site visit |
| **Unannounced** | Random (10% of certificates) | Surprise inspection |

## 4. Scoring Rubric

### Scoring Methodology

Each certification assessment uses a weighted scoring model:

```
Total Score = Σ(Domain Score × Domain Weight) / Total Weight

Where:
Domain Score = Σ(Control Score × Control Weight) / Total Control Weight
Control Score = Evidence-based rating (0-100)
```

### Domain Weights by Certification Type

| Domain | ORG-01 (Hospital) | ORG-02 (Lab) | IND-01 (Clinical) | TEC-01 (Device) |
|--------|-------------------|--------------|-------------------|-----------------|
| Platform Configuration | 15% | 20% | 25% | 30% |
| Staff Competency | 20% | 20% | 40% | 15% |
| Quality Management | 20% | 25% | 5% | 10% |
| Security & Privacy | 20% | 15% | 15% | 20% |
| Patient Safety | 15% | 10% | 10% | 10% |
| Technical Infrastructure | 10% | 10% | 5% | 15% |

### Control Scoring

| Score | Description | Evidence Required |
|-------|-------------|-------------------|
| 0 | Not implemented | N/A |
| 25 | Planned but not implemented | Roadmap, timeline |
| 50 | Implemented partially | Evidence of deployment, gaps exist |
| 75 | Implemented effectively | Full evidence, minor gaps |
| 100 | Implemented optimally | Best practices, continuous improvement |

| Software | 2 years | Annual compatibility check | 2 years |
| AI Model | 1 year | Semi-annual validation | 1 year |

### Renewal Process

```
90 days before expiry: Renewal notification
60 days before expiry: Submit renewal application
30 days before expiry: Renewal assessment window opens
Expiry date: Certificate suspended if not renewed
Grace period: 30 days after expiry (late fee applies)
```

### Early Renewal

Certificates may be renewed up to 60 days before expiry without loss of validity period.

## 6. Audit Framework

### Auditor Qualifications

| Auditor Level | Requirements | Can Lead |
|---------------|--------------|----------|
| **Trainee Auditor** | Completed GULA audit training | Observations only |
| **Auditor** | 5+ audits completed, exam passed | Simple certifications |
| **Lead Auditor** | 20+ audits, advanced exam, peer review | All certifications |
| **Principal Auditor** | 50+ audits, specialization, trainer | Complex + cross-border |

### Auditor Independence

- Auditors must not have consulted for the audited organization in the past 2 years
- Auditors must not have personal relationships with audited organization staff
- Auditor rotation every 3 audits for the same organization
- Independent review of all certification decisions

### Audit Documentation

| Document | Template | Storage |
|----------|----------|---------|
| Audit plan | Standardized plan template | Certification Portal |
| Opening meeting minutes | Meeting template | Certification Portal |
| Evidence collection | Digital evidence forms | Secure repository |
| Non-conformance report (NCR) | NCR template | Certification Portal |
| Audit report | Comprehensive report template | Certification Portal |
| Certification decision | Decision form | Certification Portal |

### Remote Audit Protocol

Remote audits follow the same rigor as on-site with additional technical requirements:

1. **Video platform**: Encrypted, recorded, retained for 3 years
2. **Screen sharing**: Live system demonstrations required
3. **Document sharing**: Secure portal with access controls
4. **Staff interviews**: Private video calls, no coaching
5. **Virtual site tour**: Live video walkthrough if applicable

## 7. Appeals Process

### Grounds for Appeal

1. **Procedural error**: Certification process not followed correctly
2. **Factual error**: Evidence misinterpreted or overlooked
3. **Bias**: Auditor conflict of interest or prejudice
4. **New evidence**: Information unavailable during audit
5. **Score calculation error**: Mathematical error in scoring

### Appeals Procedure

```
┌─────────────────────┐
│  Appeal Filed        │  Within 30 days of decision
│  (written notice)    │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│  Acknowledgment     │  Within 5 business days
│  + Appeal Review    │
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│  Investigation      │  Within 20 business days
│  (independent panel)│
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│  Decision Rendered  │  Written decision with rationale
└──────────┬──────────┘
           ▼
      ┌──────────┐
      │ Accepted │──► Certificate reinstated/modified
      └──────────┘
      ┌──────────┐
      │ Rejected │──► Final, no further appeal within GULA
      └──────────┘
           │
           ▼
      External mediation if applicable
```

### Appeal Panel Composition

| Certification Level | Panel Composition |
|--------------------|-------------------|
| Bronze/Silver | 2 independent auditors + 1 quality manager |
| Gold | 2 lead auditors + 1 subject matter expert |
| Platinum | 1 principal auditor + 1 external expert + 1 certification board member |

├── Appeals Panel (independent review)
├── Auditor Management (quality, training)

### Certification Board Membership

| Role | Appointment | Term |
|------|-------------|------|
| Chair | GULA executive nomination | 3 years |
| Vice Chair | Board election | 2 years |
| Technical Members | Industry experts | 2 years |
| Regulatory Liaison | MoH representative | 2 years |
| Auditor Representative | Elected by auditors | 2 years |
| Customer Representative | Customer advisory board | 2 years |

### Conflicts of Interest

All certification personnel must:

1. Disclose any relationship with applicant organizations
2. Recuse themselves from decisions where conflict exists
3. Sign conflict of interest declaration for each assessment
4. Report any post-certification relationships that arise

## Appendix: Certification Database Schema

```sql
-- Certification Framework Core Tables
CREATE TABLE cf_certification_types (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code VARCHAR(20) UNIQUE NOT NULL,
    name_ar TEXT NOT NULL,
    name_en TEXT NOT NULL,
    category VARCHAR(50), -- org, ind, tec, cmp
    validity_years INTEGER DEFAULT 1,
    max_level VARCHAR(20) DEFAULT 'platinum',
    requires_on_site BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE cf_certificates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    certificate_number VARCHAR(100) UNIQUE NOT NULL,
    certification_type_id UUID REFERENCES cf_certification_types(id),
    holder_type VARCHAR(20), -- organization, individual, device, software
    holder_id UUID,
    holder_name_ar TEXT,
    holder_name_en TEXT,
    level VARCHAR(20) DEFAULT 'bronze',
    score DECIMAL(5,2),
    issued_at TIMESTAMPTZ DEFAULT NOW(),
    expires_at TIMESTAMPTZ,
    status VARCHAR(20) DEFAULT 'active',
    blockchain_hash VARCHAR(128),
    metadata JSONB,
    issued_by UUID REFERENCES lab_users(id),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE cf_assessments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    certificate_id UUID REFERENCES cf_certificates(id),
    assessment_type VARCHAR(50), -- initial, renewal, surveillance, unscheduled
    started_at TIMESTAMPTZ,
    completed_at TIMESTAMPTZ,
    status VARCHAR(20) DEFAULT 'in_progress',
    lead_auditor_id UUID,
    audit_team JSONB,
    findings JSONB,
    score DECIMAL(5,2),
    recommendation VARCHAR(50),
    report_url TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE cf_findings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    assessment_id UUID REFERENCES cf_assessments(id),
    finding_type VARCHAR(20), -- critical, major, minor, observation
    description_ar TEXT,
    description_en TEXT,
    clause_ref VARCHAR(50),
    evidence_collected TEXT,
    severity INTEGER CHECK (severity BETWEEN 1 AND 5),
    status VARCHAR(20) DEFAULT 'open',
    remediation_plan TEXT,
    remediated_at TIMESTAMPTZ,
    verified_by UUID REFERENCES lab_users(id),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE cf_appeals (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    certificate_id UUID REFERENCES cf_certificates(id),
    appellant_name TEXT,
    appellant_relationship VARCHAR(50),
    grounds_ar TEXT,
    grounds_en TEXT,
    evidence_submitted TEXT,
    status VARCHAR(20) DEFAULT 'filed',
    panel_composition JSONB,
    decision_ar TEXT,
    decision_en TEXT,
    filed_at TIMESTAMPTZ DEFAULT NOW(),
    decided_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```
