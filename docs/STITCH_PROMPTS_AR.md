# حزمة موجّهات Stitch لتصميم GULA

هذه الموجّهات مخصصة لـGoogle Stitch. يجب تحميل `DESIGN.md` أو نسخ قواعده إلى سياق المشروع قبل استخدامها. استخدم كل موجّه في مشروع أو استكشاف منفصل، ثم اربط الشاشات داخل prototype بعد اعتماد الاتجاه البصري.

## الموجّه العام

صمّم واجهات منصة GULA، وهي منصة عربية أولًا وRTL لتمثيل المواطنين والمؤسسات والوزارات والنقابات والشركات والجهات العامة والخاصة، مع فصل واضح بين نوع الجهة، القطاع، الاختصاص، مستوى التحقق، العضوية، الدور، الصلاحية، الاستحقاق، ومساحة العمل. استخدم لغة بصرية هادئة وموثوقة ومناسبة للخدمات العامة والعمليات الحساسة: خلفية `#F5F8FA`، أسطح بيضاء، لون أساسي كحلي `#0B3658`، لون نجاح أخضر مزرق `#258B76`، تحذير كهرماني `#F59E0B`، وخط Tajawal مع بدائل عربية مناسبة. اجعل التصميم Arabic-first RTL مع دعم English وKurdish وTurkmen وSyriac. لا تستخدم بيانات حقيقية أو أسماء حكومية حقيقية أو ادعاءات اعتماد قانوني. لا تفترض أي صلاحية من اسم الجهة أو نوعها. أظهر حالات loading وempty وerror وoffline وpending verification وread-only. التزم WCAG 2.2 AA، وأظهر focus states وأحجام لمس لا تقل عن 44×44، واستخدم تباينًا واضحًا وحالات وصول لقارئات الشاشة.

## 1. شاشة الدخول واختيار مسار الوصول

أنشئ شاشة دخول GULA عربية RTL على سطح المكتب والهاتف. اجعلها تحتوي على هوية GULA، عنوان ترحيبي واضح، اختيار اللغة، ومسارين منفصلين بصريًا: دخول المواطن ودخول المؤسسة. أضف حقلي البريد/الهاتف وكلمة المرور مع autocomplete مناسب، زر إظهار كلمة المرور، رسائل خطأ قابلة للقراءة، وحالة تحميل. أضف بطاقة عرض تجريبي اصطناعي موسومة بوضوح بأنها قراءة فقط ولا تنفذ عمليات كتابة أو تكاملات خارجية. لا تعرض زر تسجيل مواطن أو تفعيل تلقائي؛ بدل ذلك أظهر رابطًا معلوماتيًا لطلب الحساب الخاضع للمراجعة.

أنشئ الحالات التالية كإطارات مرتبطة: الحالة العادية، خطأ بيانات الدخول، فشل الشبكة مع زر إعادة المحاولة، تحميل، واللغة الإنجليزية. لا تستخدم صورًا لبطاقات وطنية أو بصمات أو كاميرات أو NFC.

## 2. لوحة التحكم ومساحة العمل

أنشئ لوحة تحكم GULA للمستخدم المصادق عليه. استخدم شريطًا جانبيًا RTL قابلًا للطي، وشريطًا علويًا يعرض اسم المستخدم ومساحة العمل الحالية وحالة البيئة التجريبية إن وجدت. يجب أن يكون تبديل مساحة العمل server-authoritative في المعنى البصري: اعرض قائمة المساحات التي يرسلها الخادم فقط، وحالات switching وdenied وpending وerror، ولا تعرض مفتاحًا لتغيير حالة العضوية أو مساحة العمل من الواجهة.

اعرض بطاقات ملخص بلا بيانات وهمية حساسة: حالة التحقق، الطلبات المفتوحة، التنبيهات، وآخر نشاط تدقيقي. استخدم skeleton عند التحميل وempty state عند عدم توفر بيانات. أضف تنبيهًا واضحًا عند العرض التجريبي يوضح أنه اصطناعي وقراءة فقط.

## 3. مساحة المواطن

أنشئ شاشة مواطن مبسطة تركز على الخدمات والطلبات الشخصية. اعرض عنوانًا واضحًا، خطوات الحالة، الطلبات الأخيرة، والتنبيهات. لا تعرض صلاحيات سريرية أو إدارية غير مثبتة، ولا تعرض بيانات مرضى أو نتائج مختبرية حقيقية. صمّم حالات: لا توجد طلبات، طلب قيد المراجعة، فشل الاتصال، والعمل دون اتصال مع رسالة تمنع الإيحاء بأن عملية الكتابة تمت قبل تأكيد الخادم.

## 4. مساحة المؤسسة

أنشئ شاشة مؤسسة تعرض بيانات الجهة في أقسام مستقلة: الاسم المعروض، نوع الجهة، القطاع، الاختصاص، مستوى السلطة، نطاق الولاية، مستوى التحقق، الجهة الأم، والعلاقات. اجعل الحالة الابتدائية `PENDING_VERIFICATION` واضحة بصريًا، ولا تمنح أي صلاحية تلقائيًا بسبب اسم الجهة أو القطاع.

أضف تبويبات للمنشآت والأقسام ومساحات العمل والعضويات والأدوار والصلاحيات والاستحقاقات. اجعل كل تبويب يوضح أن القرار النهائي من الخادم وأن العضوية لا تمنح صلاحية خارج النطاق المحدد. أظهر حالة محاولة تصعيد ذاتي مرفوضة برسالة عربية واضحة دون كشف تفاصيل أمنية.

## 5. لوحة الوزارة أو الجهة الإدارية

أنشئ لوحة تشغيلية لجهة إدارية مصادق عليها، من دون ذكر وزارة محددة أو اختلاق تكامل حكومي. ركّز على طوابير التحقق، الحالات المعلقة، ملخص العمليات المسموح بها، وسجل التدقيق. افصل بصريًا بين البيانات التشغيلية، حالة التحقق، والصلاحيات الفعلية. استخدم تسميات مثل «بانتظار المراجعة» و«مرفوض» و«بحاجة إلى معلومات إضافية» بدل «معتمد حكوميًا» ما لم توجد بيانات موثقة من الخادم.

## 6. سجل التدقيق والحوكمة

أنشئ شاشة سجل تدقيق قابلة للبحث والتصفية. كل عنصر يعرض الممثل، الزمن، نوع العملية، الكيان المتأثر، ملخص الحالة قبل وبعد، ومعرّف الطلب. أظهر أن السجل append-only وغير قابل للتحرير من الواجهة. صمّم حالات نتائج البحث الفارغة، فشل التحميل، منع الوصول، والتحميل الجزئي. لا تعرض أسرارًا أو رموز JWT أو معلومات شخصية غير لازمة.

## 7. التصميم المتجاوب وإمكانية الوصول

حوّل كل شاشة إلى نسخة desktop بعرض 1440px وtablet بعرض 1024px وmobile بعرض 390px. اختبر RTL وEnglish LTR. أظهر focus-visible لكل زر ورابط وحقل، واحترم reduced motion. لا تجعل الجداول تعتمد على تمرير أفقي غير معلن؛ استخدم عرضًا تكيفيًا أو بطاقة صف على الهاتف. أضف skip link، عناوين landmarks، aria-live للتنبيهات، وaria-busy لحالات التحميل.

## تعليمات المراجعة قبل نقل التصميم إلى الكود

راجع الاتساق بين كل الشاشات، وتأكد من عدم وجود بيانات وهمية تبدو حقيقية، ومن عدم منح أي جهة أو مستخدم صلاحية من خلال اللون أو الاسم. افصل كل حالة server state عن الحالة البصرية. بعد الموافقة على الشاشة، حوّلها إلى مكونات GULA القائمة أو PR مستقل، ثم نفّذ اختبار TypeScript وVitest وESLint وPlaywright وaxe قبل أي دمج أو نشر.
