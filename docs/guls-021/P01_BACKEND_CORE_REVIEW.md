## 2. Backend core architecture as implemented

### 2.1 Registry and runtime

`backend/app/localization/language_registry.py` holds the canonical registry as data. `LanguageDefinition.from_mapping()` validates required fields, the BCP 47 subset (`LOCALE_TAG_RE`), direction, classification, boolean flags, approval status values, a null locale for inactive standards, coverage in `[0, 1]`, and catalog typing. `LanguageRegistry.load()` requires `fallback_language == "en"`, a non-empty language list, unique language IDs, and an active LTR fallback. `resolve()` deliberately keeps stable internal IDs distinct from locale tags. The loaded registry contains 14 languages (`registry_schema.log`: `registry_schema=PASS languages=14`), of which 5 are classified `core` (`test_registry_runtime.py::test_registry_contains_five_core_entries`, `test_delivery_api.py::test_list_languages_exposes_five_core_entries`).

`backend/app/localization/runtime.py` implements `LanguageRuntime.resolve()` as requested → preferred → mandatory English fallback, with `NoUsableLanguageError` when no active usable language exists. `translate()` never returns a raw key (empty display text in non-strict mode, `MissingTranslationError` in strict mode); `InvalidTranslationKeyError` enforces the `ui|action|label|message|error|clinical.*` key convention. `format_number()`, `format_date()`, `format_identifier()`, and `shape_for_display()` return display values only and never mutate stored clinical values or identifiers. `stable_message()` and `StableMessage` carry a validated uppercase code plus parameters and correlation ID, not translated prose. `runtime_contract()` publishes the engine version, fallback, key convention, direction values, and identifier policy.

### 2.2 Pack schema, builder, and manager

- `backend/app/localization/pack_schema.py`: strict Pydantic models (`extra="forbid"`). `LanguagePackManifest` validates version/hash patterns, safe pack paths, a single catalog list, `fallback_locale="en"`, `content_size`, signer key ID, approval status (`approved` or `synthetic_test_only`), and file entries with path/SHA-256/size. `signing_payload()` is the canonical JSON excluding `signature`. `ApprovalRecord.check_role_separation()` requires distinct translator and linguistic reviewer roles and a documented clinical reviewer for L4. `TerminologyEntry.check_separation()` keeps translated display separate from original clinical value/unit.
- `backend/app/localization/pack_builder.py`: `build_signed_pack()` rejects unsafe inputs before signing, calls `validate_pack_governance()`, derives per-file SHA-256 digests and `content_hash`, signs with a caller-supplied Ed25519 private key, and writes a deterministic data-only ZIP. Private keys are never written into a pack or the repository.
- `tools/guls_sign_pack.py`: release signing tool that loads an Ed25519 PEM from `GULS_SIGNING_KEY_PATH`, verifies the key type, refuses a source `manifest.json`, and writes only the signed ZIP plus a JSON line of non-sensitive metadata.
- `backend/app/localization/pack_manager.py`: `PackManager` verifies and installs packs, enforces the lifecycle state machine, checks registry/clinical governance, manifest file set, per-file digests and sizes, content size/hash, expected hash, and Ed25519 signature. `_safe_extract()` enforces member count, path, symlink, suffix, and byte-size limits. `_write_pack()` stages files with fsync, swaps via rename with a backup, and restores the backup on failure. State is written with tmp-file + `os.replace`.

### 2.3 Clinical governance and HTTP wiring

`backend/app/localization/clinical.py::validate_pack_governance()` enforces the registry approval gates, derives actual catalogs from archive paths, rejects declared/actual catalog mismatch, applies the clinical catalog gate from archive contents, and validates L3/L4 terminology through `ApprovalRecord` with L4 role separation. `ClinicalTerminologyRegistry.assert_unchanged()` protects original value, unit, LOINC, UCUM, code system, code, and result status from localization changes.

`backend/app/localization/delivery.py` and `preferences.py` provide the API; `backend/app/routes/localization.py` binds them to FastAPI with the shared `PackManager` and the existing accessibility-profile preference store. `backend/app/core/error_contract.py` and `backend/app/factory.py` preserve exact stable GULS codes in production HTTP responses and omit submitted values from validation details. Delivery, preferences, error codes, and residual state/token risks are documented in `P07_DELIVERY_PREFERENCES_CLINICAL_GATES.md`; security controls and residual risks are documented in `SECURITY_EVIDENCE.md`.

## 3. Corrections applied to the backend core

### 3.1 C1 (CRITICAL) — hidden clinical catalog bypass

Previously, a pack declaring `catalogs: ["common"]` could still contain `catalogs/clinical.json`, because the signed declaration was trusted instead of the archive contents. `validate_pack_governance()` now computes `actual_catalogs` from `catalogs/<name>.json` entries in `files`, rejects `set(catalogs) != actual_catalogs`, and applies the clinical approval gate to `actual_catalogs`. Regression evidence: `test_clinical_governance.py::test_hidden_clinical_catalog_is_rejected` (declared/actual mismatch) and `::test_clinical_catalog_gate_uses_archive_contents` (archive-driven clinical gate), plus `test_pack_manager.py::test_clinical_catalog_cannot_be_signed_without_clinical_approval`.

### 3.2 H4 (HIGH) — L4 role separation in the governance path

Clinical terminology could previously reach `READY` through the governance path without translator / linguistic reviewer / clinical reviewer separation. `validate_pack_governance()` now builds an `ApprovalRecord` from `metadata/*.json` plus embedded terminology fields, requires the record class and key to match the entry, and rejects invalid L3/L4 approval. `ApprovalRecord.check_role_separation()` requires three distinct roles for L4 and a documented clinical reviewer. Evidence: `test_clinical_governance.py::test_l4_role_separation_is_enforced_during_pack_governance`, `::test_role_separation_enforced`, `::test_l4_without_clinical_approval_cannot_be_published`, and `test_pack_manager.py::test_l4_approval_requires_clinical_reviewer`.

### 3.3 M1 (MEDIUM) — `ROLLBACK_REQUIRED` dead-end

`_ALLOWED_TRANSITIONS["ROLLBACK_REQUIRED"]` now includes `NOT_INSTALLED`, and both `_prepare_for_install()` and `install()` handle `ROLLBACK_REQUIRED` so a failed installation can be retried cleanly instead of being stranded. Evidence: `test_pack_manager.py::test_install_can_retry_from_rollback_required`.

### 3.4 M2 (MEDIUM) — archive member-count denial of service

`MAX_PACK_MEMBERS = 256` is enforced both by `pack_builder._validate_pack_files()` before signing and by `PackManager._safe_extract()` during verification, using `len(archive.infolist())` before reading members. Evidence: `test_pack_manager.py::test_archive_member_count_is_limited` (300 members rejected). The same shared constants enforce `MAX_PACK_FILE_BYTES = 10 MiB` and `MAX_PACK_TOTAL_BYTES = 50 MiB`.

### 3.5 M7 (MEDIUM) — dead clinical and quota checks

Clinical gating is no longer a check against a caller-supplied catalog list: it is computed from the archive contents, as described in section 3.1, and `verify()` calls `validate_pack_governance()` on every pack before install or delivery. On the storage side, `check_storage_quota()` sums files under the pack root and compares `used + additional_bytes` with `max_total_bytes`; the delivery API applies a conservative browser requirement of `2 * requiredBytes` (`available_storage_bytes < len(pack_bytes) * 2` → `INSUFFICIENT_STORAGE`). Evidence includes `test_clinical_governance.py::test_hidden_clinical_catalog_is_rejected`, `test_pack_manager.py::test_clinical_catalog_cannot_be_signed_without_clinical_approval`, and `test_delivery_api.py::test_download_policy_blocks_data_saver`.

### 3.6 M8 (MEDIUM) — unvalidated signed fields

`verify()` now checks `manifest.content_size` against the sum of extracted non-manifest file lengths and `manifest.content_hash` against the recomputed `_content_hash()`; it also validates approval metadata through `ApprovalRecord`, so a signed manifest cannot be internally inconsistent with its files. `expected_hash` is checked against `content_hash` for download/install pinning. Evidence: `test_pack_manager.py::test_expected_hash_mismatch_is_rejected`, `test_modified_content_after_signing_is_rejected`, `test_invalid_manifest_is_rejected`, and `test_clinical_governance.py::test_l4_role_separation_is_enforced_during_pack_governance`.

### 3.7 Related corrections covered elsewhere in this review set

H1 (blocked language accepted as preferred), H2 (stable GULS codes discarded in the production HTTP handler), and H3 (synthetic flag bypassing all approval gates) are implemented in `preferences.py`, `error_contract.py`/`factory.py`, and `routes/localization.py`/`pack_manager.py` respectively. They are reviewed in `P07_DELIVERY_PREFERENCES_CLINICAL_GATES.md` and `SECURITY_EVIDENCE.md` and are not duplicated here.
