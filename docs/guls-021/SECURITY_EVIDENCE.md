## 5. Residual risks and limitations

- **M4 (residual):** GULS and legacy accessibility share `accessibility_profiles.preferences["language"]`; the in-memory store has no ETag/`If-Match`. Multi-writer deployments need optimistic concurrency.
- **M5 (residual):** Download sessions and lifecycle state are process-local; a multi-replica deployment requires shared persistent state.
- **M6 (partially mitigated, residual):** Default state root moved under the service account home and writes are atomic, but local state is unsigned and still depends on OS-level protection and a future shared-state design.
- **M9 (code fix, verification gap):** `DOWNLOAD_TOKEN_EXPIRED` is implemented with a five-second grace, but no focused test directly asserts that branch.
- **Key management:** Only ephemeral generated test keys were used. No production key provisioning, rotation, HSM/KMS integration, or signing-ceremony evidence exists here.
- **Human gates:** No human linguistic or clinical approval was performed; synthetic pack content is verification material only and not for clinical use.
- **Environment:** Native build toolchains are unavailable locally (`local_toolchain.log`); no Android/iOS/desktop build or client integration verification was performed.
- **Evidence:** The `registry_schema` harness exit and log disagree, and the secret-scan script uses `|| true`; both limitations are stated rather than normalized.
