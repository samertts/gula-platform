## Consumer scan findings

The source scan found direct frontend consumers for `patientCardApi`, `clinicalDocumentationApi`, and `clinicalOrdersApi` in `frontend-v3/src/api/endpoints.ts`; the modern workspace uses `workspaceScopedReads` for canonical patient/order/result reads. It also found dashboard/mobile navigation and E2E references to `/results`, and the patient-management page contains hard-coded patient, appointment, and queue state.

## Safe migration sequence

أولاً تُقفل الكتابات legacy الحساسة خلف deny policy أو 410/503 محكوم، من دون حذف route. ثانياً تُنفذ canonical durable command services وتُضاف negative HTTP tests. ثالثاً تُهاجر consumers وتُمنع imports القديمة بقاعدة lint/contract scan. رابعاً تُراقب compatibility read-only فقط. خامساً، بعد إثبات عدم وجود consumers، يُطبق 410 أو removal في release منفصل مع rollback plan.

## Non-negotiable status

هذا inventory لا يرفع أي route إلى PASS. وجود HMAC أو lab filter أو unit tests لا يعوض غياب workspace/purpose/role/assignment policy. أي route ينفذ clinical write مع authentication فقط يبقى **CRITICAL/HIGH** حتى يثبت actor-derived context وstate transition وaudit وtenant isolation عبر HTTP negative tests.
