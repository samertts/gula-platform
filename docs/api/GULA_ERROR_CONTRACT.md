# GULA API Error Contract

**الحالة:** مطبق جزئياً في طبقة FastAPI المركزية، ويتطلب تعميماً تدريجياً على العملاء والعقود المجالّية.

## الهدف

تستخدم استجابات الأخطاء المركزية شكلاً ثابتاً يسمح للعميل بتمييز فشل المصادقة عن فشل التفويض والتعارض وفشل التحقق، مع الحفاظ على الحقول القديمة التي تعتمد عليها التطبيقات الحالية.

## الاستجابة القياسية

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Request validation failed.",
  "details": {
    "errors": [
      {
        "loc": ["body", "field"],
        "type": "value_error",
        "message": "Invalid value"
      }
    ]
  },
  "request_id": "request-correlation-id",
  "timestamp": "2026-08-12T00:00:00+00:00",
  "detail": "Request validation failed.",
  "detail_ar": "بيانات الطلب غير صالحة."
}
```

يبقى `detail` و`detail_ar` للتوافق مع العملاء القديمة. الحقول التي يجب أن تستخدمها الواجهات الجديدة هي `code` و`message` و`details` و`request_id` و`timestamp`.

## رموز الحالات الأساسية

| HTTP | code | المعنى التشغيلي |
|---:|---|---|
| 400 | `BAD_REQUEST` | الطلب غير صالح أو لا يطابق شروط العملية |
| 401 | `AUTHENTICATION_REQUIRED` | لا توجد جلسة مصادقة صالحة؛ لا يُعامل كفشل تفويض |
| 403 | `FORBIDDEN` | الجلسة صالحة لكن الهوية لا تملك التفويض المطلوب |
| 404 | `NOT_FOUND` | المورد أو المسار غير موجود |
| 409 | `CONFLICT` | تعارض في الحالة أو idempotency أو النسخة الحالية |
| 412 | `PRECONDITION_FAILED` | فشل شرط `If-Match` أو شرط سابق صريح |
| 422 | `VALIDATION_ERROR` | فشل تحقق schema أو قيم الطلب |
| 429 | `RATE_LIMITED` | تجاوز حد المعدل |
| 503 | `SERVICE_UNAVAILABLE` | الخدمة أو النظام غير جاهز مؤقتاً |
| 5xx | `INTERNAL_ERROR` | خطأ داخلي؛ لا تُعرض تفاصيل البنية أو traceback |

## قواعد الحماية

لا تُعاد قيم `input` أو `ctx` الخاصة بـPydantic إلى العميل، لأنّها قد تحتوي على PHI أو أسرار أو بيانات اعتماد. لا يُعاد سبب عدم جاهزية الخدمة الداخلي؛ يُسجل السبب في الخادم ويُعاد للعميل مؤشر آمن فقط. كما لا تُعرض الاستثناءات أو مسارات الملفات أو أخطاء قاعدة البيانات في استجابات 5xx.

التمييز الإلزامي هو: `401` يعني أن المصادقة مطلوبة، بينما `403` يعني أن المصادقة نجحت لكن التفويض مرفوض. يجب أن يحتفظ أي عميل بحالة التعارض ولا يعيد العملية السريرية تلقائياً عند `409/412`.

## النطاق الحالي والدعم المستقبلي

المعالج المركزي في `backend/app/factory.py` يدعم `DomainError` و`StarletteHTTPException` و`RequestValidationError` والاستثناءات غير المعالجة. هذا لا يعني أن كل خدمة خارج FastAPI أو كل عميل mobile أصبح مستهلكاً للعقد؛ تعميم العميل المشترك يجب أن يتم endpoint-by-endpoint مع contract tests، دون تغيير base URLs أو deployment configuration ضمن هذه الموجة.
