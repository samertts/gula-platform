## قواعد أمان مقترحة إلى حين القرار

لا ينشأ أي معيار جديد من تعارض المستندين. عند وجود اختلاف، يطبق الضابط التنفيذي القابل للفحص مع دستور المنصة الأعلى، ويصعّد التناقض إلى Architecture Board. لا يتغير معيار coverage أو الاختبار أو الأمن أو قواعد سريرية من خلال هذه الخريطة.

تظل الوثائق الأصلية موجودة ولا يعاد تسميتها في هذه الدفعة. ولا تُحدث روابط واسعة أو عمليات نقل Git لأن ذلك يتطلب فحصاً للروابط الداخلية والاستخدام في pipelines والعمل على أنظمة ملفات مختلفة.

## خطوات الإغلاق المقترحة

1. يعين Architecture Board مصدر سلطة واحداً لكل مجال ويوقع قراراً أو ADR.
2. يجرد مالك التوثيق كل المراجع والروابط ويدقق التوافق بين النص المختار والدستور.
3. ينفذ فرع منفصل خطة حفظ: نقل النص التاريخي إلى archive أو صفحة redirect واضحة، مع تجنب مسارين يختلفان في حالة الحروف فقط.
4. يضاف فحص CI يمنع إعادة إنشاء أسماء وثائق متصادمة case-insensitively ويثبت وجود المصادر المعتمدة.
5. يعاد تشغيل التحقق الدستوري ويُحدث C8 فقط مع دليل القرار والتنفيذ الفعليين.

## حدود الحالة

لا يغلق هذا التحليل C8 ولا يتحول RC1 إلى GO. تبقى حواجز CI الخارجي، والتغطية، والـmTLS، والـstaging restore، وAndroid الموقّع، وUAT، والتوقيعات البشرية كما هي.
