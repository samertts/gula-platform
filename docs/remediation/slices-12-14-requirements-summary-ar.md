# ملخص متطلبات Slices 12–14

هذا سجل عمل مستخرج من المرفقات الثلاثة، ولا يمثل readiness أو تكاملاً حياً.

## Slice 12 — Finance / Insurance

الفصل الإلزامي: Clinical Record وIdentity وInsurance وBilling وPayment وClaims. المطلوب canonical payer/coverage/eligibility/preauthorization/service/price/bill/claim/payment/refund/settlement/reconciliation، مع أدوار Citizen/Provider/Payer/Insurer/Employer/Government Program/TPA/Payment Provider. حالات coverage تشمل ACTIVE/EXPIRED/SUSPENDED/PENDING/UNKNOWN/TERMINATED، وeligibility REQUESTED/PROCESSING/ELIGIBLE/INELIGIBLE/UNKNOWN/FAILED، وpreauthorization REQUESTED/UNDER_REVIEW/APPROVED/PARTIALLY_APPROVED/DENIED/EXPIRED/CANCELLED، وclaim DRAFT/SUBMITTED/RECEIVED/UNDER_REVIEW/APPROVED/PARTIALLY_APPROVED/DENIED/PAID/REJECTED/APPEALED، وpayment INITIATED/AUTHORIZED/CAPTURED/SETTLED مع FAILED/CANCELLED/REFUNDED/PARTIALLY_REFUNDED.

يجب استعمال integer minor units لا floating point، وتثبيت currency/exchange-rate snapshot، وحساب gross/covered/copay/deductible/noncovered/discount/net deterministic. المطلوب idempotency وobject/tenant authorization وIf-Match/version وsegregation of duties وdouble-entry capable append-only ledger وtransactional outbox. Payment/insurance/government/FX providers interfaces فقط؛ provider failure يبقى UNKNOWN/PENDING. Webhooks تحتاج signature/timestamp/nonce/event-id/replay protection. Offline يسمح draft bill فقط، ولا يسمح capture أو PAID. لا يوقف التأمين الرعاية الطارئة. لا يرى الطبيب التفاصيل المالية إلا عند الحاجة، ولا يرى المحاسب التفاصيل السريرية إلا minimum necessary. المطلوب أيضاً typed errors، API contracts، security/concurrency/performance/recovery tests، وdocs/finance files.

## Slice 13 — National LIS

يجب إعادة استخدام CoreLabOrder/CoreSpecimen/CoreLabResult/CoreCriticalResultEvent/CoreClinicalNotification الحاليين، مع إضافة test catalog/versioning/specimen requirements/accession/barcode/collection/transport/reception/analyzer registry/message boundary/results/QC/calibration/maintenance/reagents/reference-lab/critical-notification. يجب فصل raw analyzer message عن clinical result، واستخدام AnalyzerAdapter وHL7/FHIR/ASTM interfaces فقط. Analyzer states REGISTERED/VALIDATED/ACTIVE/MAINTENANCE/QUARANTINED/RETIRED؛ الجهاز quarantine لا ينتج نتائج سريرية. Result lifecycle PRELIMINARY/VERIFIED/FINAL مع CORRECTED/AMENDED/CANCELLED، no overwrite، manual result source واضح، technician لا يحقق clinical validation وحده، وQC failure يمنع release إلا override مصرح مع سبب وتدقيق. Critical flow detect→flag→verify→notify→acknowledge→document، مع escalation. Citizen يرى final released فقط، ولا يرى raw analyzer/QC/internal comments. Unit normalization UCUM، calculated result يحفظ inputs/formula/version، وFHIR Patient/ServiceRequest/Specimen/Observation/DiagnosticReport وHL7 ORM/ORU mappings versioned.

مطلوب wrong-patient/specimen hard stop، duplicate analyzer message idempotent، accession/barcode collision detection، chain-of-custody، split/merge controlled/audited، add-on/reflex/panel versioned، server-side pagination/filtering، TAT/SLA metrics، transactional outbox، retry/dedup/conflict بدون last-write-wins، offline non-final فقط، وAPI security/concurrency/idempotency/migration/load/recovery/Browser-Mobile-Desktop E2E. لا يتم إعلان LIS_CORE_READY قبل تحقق كل final gate بما فيه analyzer/QC/release/audit/concurrency/migration/load/recovery/remote CI/staging/rollback. المطلوب docs/lab files.

## Slice 14 — Pharmacy / Medication

يجب توسيع CoreMedicationCatalog/CorePrescription/CoreMedicationBatch/CoreMedicationStockLedger/CoreDispense الحاليين، لا إنشاء medication/prescription/dispensing owner ثانية. المطلوب medication mappings/local/ATC/RxNorm/GTIN، versioning، drug forms/routes، prescription states DRAFT/SIGNED/ACTIVE/DISPENSING/PARTIALLY_DISPENSED/DISPENSED/COMPLETED مع CANCELLED/EXPIRED/SUSPENDED، prescriber/workspace/scope، allergy coded master، interaction/duplicate therapy/dose alerts versioned، controlled medication policy/audit، batch/lot/expiry/recall/quarantine، FEFO، stock reservation/expiry/partial/refill/substitution/shortage، return/waste/cold-chain/storage/procurement interfaces.

يجب فصل dispensing عن administration/eMAR وعن insurance/billing وعن clinical record. يمنع expired/recalled/quarantined/negative stock، ويستخدم append-only inventory movements وrow locks، ويثبت one winner عند آخر كمية. High/Critical alerts تحتاج clinical override صريح عند policy، والصيدلي لا يغير clinical intent بلا صلاحية. Emergency medication لا يتوقف على insurance outage. Payment لا يغير medication history. الصلاحيات workspace/tenant/object، والأدوار clinical dispensing/stock/financial/audit منفصلة. Signed/dispensed/administered immutable والتصحيح reversal/amendment. المطلوب APIs medication/prescription/dispensing/inventory/recall/history، typed errors، FHIR versioned mappings، security/concurrency/idempotency/migration/load/recovery tests، وdocs/pharmacy files.

## حدود مشتركة

Synthetic data فقط، لا government/payment/insurance/analyzer/device/PACS/LIS/RIS/HIS/SMS/Telegram/WhatsApp live integration، ولا raw PHI/credentials. يجب استخدام adapters/protocols وUNKNOWN/PENDING عند unavailable provider، ولا يجوز production claim. يجب تحديث Engineering Inventory وPR evidence مع `production_ready=false` و`golden_path_passed=false` إذا بقيت الأدلة ناقصة.
