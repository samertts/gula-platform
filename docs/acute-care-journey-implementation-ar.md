# تنفيذ مسار الطوارئ والإسعاف والرعاية الحادة في GULA

## الملخص

أضيفت بوابة Acute Care مستقلة داخل `frontend-v3` تحت `/acute-care-operations`. تغطي البوابة رحلة الطوارئ والإسعاف والرعاية قبل المستشفى والعناية الحرجة والعمليات وبنك الدم والمرضيات ومكافحة العدوى والتسليم والتدقيق ضمن تجربة واحدة، مع إبقاء كل Domain منفصلاً في العرض والسياسات.

أصبح المساران القديمان `/ems` و`/critical-care` يفتحان البوابة الآمنة نفسها بدلاً من صفحات API الخام. ما تزال الملفات القديمة موجودة في المصدر لأغراض الانتقال والمراجعة، لكنها لم تعد مربوطة من خلال router؛ لا ينبغي إعادتها إلى مسار حي قبل توفير عقود workspace-scoped واختبارات حوكمة مقابلة.

> السرعة في الطوارئ لا تعني تجاوز الهوية أو السلامة أو التدقيق. الواجهة دفاعية، والـbackend هو صاحب السلطة النهائي في المصادقة والتفويض والسياق والحالة والتدقيق.

## ما تم تنفيذه

| النطاق | ما يظهر في Demo | حالة Live الحالية |
|---|---|---|
| الطوارئ والفرز | P1/P2/P3، منطقة الإنعاش، إعادة التقييم، فرق الاستجابة، وهوية مؤقتة اصطناعية | محجوب؛ لا Emergency Encounter أو Triage أو Break-Glass |
| الإسعاف والتوجيه | حالات وحدات اصطناعية، طاقم، وجهة، ETA وPre-alert للشرح | محجوب؛ لا Dispatch أو GPS أو مشاركة موقع |
| الرعاية قبل المستشفى | Incident وePCR وعلامات حيوية وتدخلات وتسليم | محجوب؛ لا تسجيل سريري أو حفظ أحداث |
| المرضى والأوامر | صفوف اصطناعية تفصل الأولوية عن التشخيص وOrder عن Performed | قراءة patients/orders فقط بعد تفعيل سياق الخادم |
| العناية الحرجة | ICU وflowsheets وdevice gateway وalert fatigue | محجوب؛ لا ICU أو ventilator أو telemetry خام |
| غرفة العمليات | Consent وPre-op وTeam وVerification وChecklist | محجوب؛ لا جدولة أو تخدير أو تنفيذ أو implant |
| بنك الدم | المنتجات وcrossmatch والتحقق الثنائي وتفاعل الدم | محجوب؛ لا Issue أو Administration |
| المرضيات والعينات | دورة specimen والتقرير المؤجل والتتبع | محجوب؛ لا accession أو barcode أو تقرير قابل للإصدار |
| مكافحة العدوى | Exposure وIsolation وCluster وPurpose-based access | محجوب؛ لا كشف للمخالطين أو المناطق |
| التسليم والتحويل | قبول الفريق المستلم وقائمة Identity/Vitals/Medication/Lines/Devices | محجوب؛ لا ICU acceptance أو transfer أو discharge |
| التدقيق والحوكمة | أحداث اصطناعية تفرق acknowledgement عن الإجراء | محجوب؛ لا سجل نشاط شامل أو وصول فضولي |

## Demo

وضع Demo اصطناعي ومعزول وقابل للقراءة فقط. لا يستدعي `listWorkspaces` أو clinical gateway، ولا يتصل ببيانات مواطنين أو مستشفى أو HIS أو LIS أو RIS أو PACS أو أجهزة طبية أو خدمة Dispatch. المعرف `TEMP-000123` مثال اصطناعي لهوية طوارئ مؤقتة، وليس سجلاً حقيقياً ولا مواطناً جديداً.

تُعرض في Demo رحلة المريض المجهول من الهوية المؤقتة إلى المطابقة والمراجعة كشرح فقط. لا تنشئ الواجهة Encounter أو ePCR أو Vital أو نتيجة أو دواء أو عملية أو نقل دم أو عزل أو تحويل أو سجل تدقيق حي، ولا تقوم بدمج سجلين تلقائياً.

## Live والعقود المعتمدة

في Live تقرأ الصفحة مساحات العمل من `GET /niam/workspaces`، ولا تقبل إلا مساحة غير شخصية مرتبطة بمنشأة وبحالة `ACTIVE` أو `VERIFIED` أو `APPROVED`. تفعيل السياق يتم عبر `POST /niam/workspaces/{workspace_id}/switch`. لا تعتبر الواجهة اختيار workspace دليلاً على الصلاحية؛ يظل الخادم مطالباً بإعادة فحص الحساب والهوية والعضوية والدور والمنشأة والقسم والغرض وعلاقة الرعاية.

بعد نجاح تفعيل السياق، تستخدم الصفحة فقط عقود القراءة السريرية canonical الحالية:

| العقد | الاستخدام |
|---|---|
| `GET /api/v1/clinical/patients` | قائمة مرضى محدودة ضمن سياق الرعاية، مع رفض الحقول الحساسة غير المسموح بها |
| `GET /api/v1/clinical/orders` | قائمة أوامر محدودة للقراءة فقط، مع منع `patient_id` و`results` والكتابة |

لا تستخدم البوابة الجديدة `/ems/*` أو `/critical-care/*` أو `/hospital/*` كـfallback، ولا تعرض استجابة خاماً إذا فشل العقد أو كان envelope أو السياق غير صالح.

## حواجز السلامة

الفرز يحدد الأولوية ولا يساوي التشخيص. العلاج العاجل لا يتوقف منطقياً على الدفع أو التأمين، لكن ذلك لا يبرر إنشاء هوية أو تغيير حالة أو استخدام Break-Glass من الواجهة دون عقد خادمي. كما أن فتح التنبيه لا يساوي acknowledgement سريرياً، و`Admission` لا يساوي `Bed`، و`Order` لا يساوي `Performed`، و`Dispensing` لا يساوي `Administration`.

أي عقد مستقبلي لعمليات الطوارئ أو الإسعاف أو الرعاية الحادة يجب أن يفرض RBAC سياقياً، ونطاق المنشأة والقسم والجناح وعلاقة الرعاية والغرض، وstate machine، ونسخة أو `If-Match`، و`Idempotency-Key`، وسجل تدقيق append-only، ومعالجة صريحة للتعارضات. لا يجوز استخدام Last Write Wins للهوية أو العلامات الحيوية أو الوصفات أو العمليات أو الدم أو التقارير.

## علي رضا والذكاء الاصطناعي

علي رضا مرشد داخل البوابة. يمكنه شرح الخطوات، وترتيب المعلومات، وتلخيص Encounter المسموح به، وتذكير الفريق بتنبيه أو Checklist، لكنه لا يفرز المريض، ولا يشخّص Sepsis أو Stroke أو STEMI، ولا يقرر الوجهة، ولا يعتمد ICU أو OR، ولا يصف أو يعطي دواء أو دم، ولا يدمج الهويات، ولا يمنح صلاحية، ولا يتجاوز Break-Glass.

## اختبارات وحدود الإصدار

تثبت اختبارات البوابة أن Demo لا يستدعي API، وأن Live لا يقرأ المرضى أو الأوامر قبل تفعيل workspace، وأن القراءة الحية تستخدم gateway المحدود، وأن الطوارئ وDispatch والرعاية قبل المستشفى وICU وOR والدم والمرضيات والعدوى والتسليم محجوبة. كما تختبر سياسة التنقل أن `/acute-care-operations` و`/ems` و`/critical-care` تستخدم مجموعة الأدوار الآمنة نفسها ولا تسمح بدور المواطن.

هذه الجولة تنفذ واجهة تشغيلية آمنة وقابلة للمشاهدة، وليست دليلاً على جاهزية تشغيل إسعاف أو طوارئ حقيقية. لا تتضمن تكاملاً حكومياً أو GPS أو HIS أو PACS أو LIS أو جهازاً طبياً أو بيانات حقيقية أو نشر إنتاجي. فتح العمليات الحية يتطلب أولاً عقود backend مستقلة ومراجعة سريرية وتشغيلية وأمنية واختبارات staging اصطناعية.
