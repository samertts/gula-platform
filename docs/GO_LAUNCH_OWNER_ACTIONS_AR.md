# حزمة تنفيذ الملاك قبل قرار GO

**المرشح المستهدف:** `release/clinical-safety-2026q3` على SHA موثق في سجل الأدلة.  
**حالة البدء:** `NO_GO`. لا يُستبدل أي بند أدناه بتصريح شفهي أو نتيجة اختبار محلي لفرع مختلف.

> تستخدم هذه الحزمة بيانات تركيبية فقط. يمنع إدخال PHI أو مفاتيح Android أو بيانات دفع أو رموز خدمة في المستودع أو سجل الأدلة أو الدردشة.

## 1. تسلسل التنفيذ

| الترتيب | المالك المخول                                                      | الإجراء                                                                                  | الدليل الذي يضاف إلى سجل GO                                         | شرط الإغلاق                                       |
| ------: | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------- |
|       1 | مالك حساب GitHub أو مدير الفوترة                                   | يصحح الدفعة الفاشلة أو حد الإنفاق لـActions وفق سياسة الجهة                              | رابط صفحة التشغيل الجديدة ووقت المعالجة، بلا بيانات دفع             | تبدأ وظيفة `Syntax Gate` وتنفذ خطواتها            |
|       2 | مهندس الإصدار                                                      | يشغل CI على SHA المرشح نفسه ويجمع روابط النتائج                                          | روابط CI ونتائج بوابات الجودة والأمن والانحدار                      | جميع البوابات المطلوبة `PASS`                     |
|       3 | مهندس الإصدار                                                      | ينفذ `alembic heads` ويشغل فاحص GO من SHA نفسه                                           | مخرج رأس Alembic وتقرير `release_go_preflight.py`                   | رأس واحد يطابق `20260820_0005` ولا تناقض في السجل |
|       4 | مالك إصدار Android                                                 | يوفّر الأسرار عبر إعدادات CI فقط، ويبني AAB موقّعاً، ويتحقق من التوقيع واختبار جهاز فعلي | رابط artifact/provenance ونتيجة الاختبار؛ لا keystore ولا كلمة مرور | حزمة موقعة قابلة للتثبيت ونتيجة جهاز موثقة        |
|       5 | قائد UAT السريري                                                   | ينفذ حالات `UAT_BATCH1_LIMS_EDGE_CASES_AR.md` في `staging` ببيانات تركيبية               | سجل الحالات، HTTP، أرقام تدقيق، والـSHA                             | نجاح كل حالات P0/P1، بلا حادث مانع                |
|       6 | أخصائي اعتماد المختبر والطبيب المستلم والأمن والمنصة وقائد السلامة | يراجع كل منهم نطاقه ويوقع في سجل الأدلة                                                  | مرجع توقيع وتاريخ وقرار `APPROVED` لكل دور                          | اكتمال التوقيعات الخمسة                           |
|       7 | سلطة الإصدار المخولة                                               | تراجع سجل الأدلة وتشغل فاحص GO                                                           | تقرير `HUMAN_GO_DECISION_REQUIRED` ثم قرار بشري مستقل               | قرار GO صريح ومسجل؛ لا دمج آلي                    |

## 2. ضوابط لا يجوز تجاوزها

| المجال           | الرفض الإلزامي                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------- |
| CI               | لا يعامل تشغيل محجوب بالفوترة أو وظيفة متخطاة كنجاح.                                          |
| Alembic          | يمنع وجود أكثر من head أو إدخال ترحيلات `0006–0008` في مسار المرشح الحالي.                    |
| السلامة السريرية | يتوقف UAT فور انتقال ممنوع أو أثر مكرر أو فشل تدقيق أو تسرب عابر للمؤسسات أو PHI في المراقبة. |
| Android          | يمنع رفع أو نسخ keystore أو متغيرات السر داخل الشفرة أو سجل UAT.                              |
| الدمج            | تبقى كل PRs مسودات حتى اكتمال الأدلة؛ لا دمج إلى `main` أو `develop` أو نشر إنتاجي تلقائي.    |

## 3. أمر التحقق الموحد

ينفذه مهندس الإصدار من SHA المرشح بعد ملء سجل الأدلة:

```bash
python3 scripts/release_go_preflight.py --json
```

تفسر النتيجة كما يأتي:

| المخرج                       | المعنى                                                             | الإجراء                                               |
| ---------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------- |
| `NO_GO`                      | دليل ناقص أو بوابة غير ناجحة أو توقيع غائب أو رأس Alembic غير متسق | يعالج المالك البند المحدد؛ يمنع الدمج والنشر          |
| `HUMAN_GO_DECISION_REQUIRED` | السجل مكتمل بنيوياً فقط                                            | تراجع سلطة الإصدار الأدلة وتصدر قراراً بشرياً مستقلاً |
