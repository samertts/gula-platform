## Maintainer Responsibilities

Maintainers are responsible for:

- Reviewing and merging pull requests
- Triaging and responding to issues
- Ensuring code quality and test coverage
- Managing releases and versioning
- Enforcing the [Code of Conduct](../../CODE_OF_CONDUCT.md)
- Maintaining project documentation
- Onboarding new contributors
- Ensuring Platform Constitution compliance

## Becoming a Maintainer

To become a maintainer:

1. Demonstrate sustained, high-quality contributions to the project
2. Show understanding of the project's architecture and standards
3. Participate actively in code reviews and community discussions
4. Be nominated by an existing maintainer
5. Receive consensus approval from the current maintainer team

## Maintainer Expectations

- Respond to PRs and issues within 5 business days
- Participate in quarterly maintainer syncs
- Uphold the project's [Governance](../../GOVERNANCE.md) model
- Follow the [Contributing Guide](../../CONTRIBUTING.md)

## Emeritus Maintainers

Maintainers who are no longer actively contributing may be moved to emeritus
status. They retain their contributions in the project history and may return
to active status by re-engaging with the community.

## Review Process

- All code changes require at least one maintainer review
- Security-critical changes require two maintainer reviews
- Changes to governance or constitution documents require maintainer consensus
