# دليل C6: منع النقل غير المؤمّن في Device Bridge

**الفرع:** `fix/device-bridge-mtls-fail-closed`
**التزام التنفيذ:** `a2d541f017671d7af0f3cfe15fc0164253db47d7`
**الحالة:** النقل الخارجي معطل افتراضياً ومقيد بـmTLS عند طلب التفعيل؛ C6 وقرار تفعيل جهاز حي ما زالا **مفتوحين**.

> هذه الدفعة لا تنشئ شهادة أو مفتاحاً، ولا تعدل شبكة، ولا تشغّل خدمة مستمرة، ولا تفعّل جهازاً. كما لا تنشئ `LabResult` أو تتجاوز حجر القياسات أو أمر المراجعة البشري.

## الخطر الذي عولج

كان Device Bridge ينشئ عميلاً بعنوان `http://gula.local`، ويستطيع إرسال نتائج إلى مسار الإدخال القديم. هذا يناقض شرط النقل المتبادل الموثق في C6. حتى مع بقاء endpoint الخلفي محتوى ومعطلاً، لا ينبغي أن توجد قيمة HTTP افتراضية قابلة للاستعمال في عميل جهاز.

## الضوابط المضافة

| المجال | الضابط |
|---|---|
| الحالة الافتراضية | `GulaClient` يبدأ مع `enabled=False` ولا يفتح اتصالاً؛ يعيد `device_bridge_forwarding_disabled`. |
| العنوان | أي محاولة تفعيل تتطلب URL صحيحاً بمخطط `https`؛ يرفض `http` في constructor. |
| هوية العميل | التفعيل يتطلب مسارات CA وشهادة عميل ومفتاح عميل جميعاً. |
| TLS | ينشئ العميل `SSLContext` مع CA ويحمل سلسلة شهادة العميل قبل أي HTTP request. |
| الفشل | غياب الملفات أو خلل TLS أو خطأ نقل يعيد نتيجة فشل مجردة بلا payload أو identifiers في السجل. |
| القيم الافتراضية | أزيل `http://gula.local` من `app.py` و`main.py` و`DataPipeline`. |
| الاختبار | إعداد pytest يستخدم مفتاحاً عابراً في البيئة فقط؛ لم يضف مفتاح تطبيق ثابت أو fallback إنتاجي. |

## الأدلة المحلية

| التحقق | النتيجة |
|---|---|
| اختبارات Device Bridge | **33/33 ناجحاً**. |
| اختبارات mTLS الجديدة | تغطي التعطيل، ورفض HTTP، ورفض مواد mTLS الناقصة، وفشل ملفات الشهادة بشكل مغلق. |
| Ruff للملفات المتغيرة | ناجح. |
| MyPy لعميل mTLS واختباره | ناجح؛ لا تشخيص نوع جديد. |
| بوابة changed-files مقابل RC1 | **PASS**؛ Ruff `0→0` وMyPy `26→25`. |

## ما لا يزال مانعاً للتفعيل الحي وGO

لا يجوز تغيير `enabled=True` في بيئة حية لمجرد وجود هذا الكود. يلزم قبل ذلك ما يأتي:

1. اعتماد هندسي وسريري لمسار جهاز محلي منفصل عن API الخلفي، مع تعريف endpoint محجور غير سريري؛ المسار القديم `/device/results` يبقى محتوى ويرفض الإدخال المباشر.
2. PKI تشغيلية: CA موثوقة، شهادة ومفتاح مستقلان لكل bridge، تدوير وإبطال ومراقبة انتهاء الشهادات، ومخزن أسرار خارج Git.
3. شبكة منشأة: allow-list، تقسيم شبكي، mTLS termination مضبوط، ومنع HTTP عند طبقة الشبكة كذلك.
4. اختبار تكامل في staging بشهادات تركيبية، ثم UAT بشري ببيانات تركيبية وحالات رفض handshake/revocation/replay/tenant isolation.
5. توقيعات مالك المنصة والأمن وLIMS والسلامة السريرية؛ ثم دليل CI رسمي محفوظ على الالتزام المرشح.

> لذلك تظل حالة الإطلاق **NO-GO**، وتبقى ميزات الجهاز الحي مغلقة حتى اكتمال الأدلة أعلاه وقرار بشري مخول.
