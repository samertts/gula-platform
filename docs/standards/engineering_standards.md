## 1. Coding Standards

| Rule | Standard |

| Line Length | 100 characters |
| Indentation | 4 spaces (no tabs) |
| Quotes | Double quotes for strings |
| Line Endings | LF (Unix) |
| Encoding | UTF-8 |
| Formatter | Ruff (format on save) |
| Linter | Ruff (all rules) |
| Type Checker | Mypy (strict mode) |
| Imports | isort (Ruff I rules) |

### Naming Conventions

| Element | Convention | Example |
|---------|-----------|---------|
| Packages | lowercase, no underscores | `lims`, `ehr` |
| Modules | snake_case | `patient_card.py` |
| Classes | PascalCase | `LabResult`, `PatientService` |
| Functions | snake_case | `get_patient_by_id` |
| Variables | snake_case | `patient_id` |
| Constants | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| Private | _prefix | `_validate_internal` |
| Type Variables | PascalCase | `TModel`, `TResponse` |

### Python Imports Order

## 2. API Standards

### REST API Design

- **Base URL:** `/api/v1/` for public APIs
- **Naming:** Plural nouns for resources (`/patients`, `/orders`)
- **HTTP Methods:** GET (read), POST (create), PUT (replace), PATCH (update), DELETE (remove)
- **Query Parameters:** For filtering, sorting, pagination
- **Path Parameters:** For resource identification (`/patients/{patient_id}`)
- **Response Format:** Always JSON
- **Error Format:** `{ "detail": "message", "detail_ar": "رسالة" }`

### Required Headers

| Header | Required | Purpose |
|--------|----------|---------|
| `Authorization` | Yes (unless public) | Bearer JWT token |
| `X-Request-ID` | Generated by middleware | Correlation ID |
| `Content-Type` | Yes (POST/PUT/PATCH) | `application/json` |
| `Accept-Language` | Optional | `ar` or `en` |

### Pagination

```json
{
  "items": [...],
  "total": 100,
  "page": 1,
  "size": 20,
  "pages": 5
}
```

### API Versioning

- **URL versioning:** `/api/v1/`, `/api/v2/`
- **Backward compatibility:** Within a major version, no breaking changes
- **Deprecation:** `Sunset` and `Deprecation` headers
- **Migration period:** Minimum 90 days for breaking changes

### OpenAPI Specification

- All APIs must have OpenAPI 3.x specification
- Spec generated from code using FastAPI's auto-generation
- CI validates required endpoints exist
- Spec published as API documentation

## 3. Database Standards

### SQLAlchemy ORM

| Element | Standard |
|---------|----------|
| Declarative Base | `app.models.Base` |
| Table Naming | snake_case, plural (`lab_results`) |
| Primary Key | `id: Mapped[int] = mapped_column(primary_key=True)` |
| Foreign Key | `lab_id: Mapped[int] = mapped_column(ForeignKey("labs.id"))` |
| Timestamps | `created_at`, `updated_at` (UTC) |
| Soft Delete | `is_deleted: Mapped[bool]`, `deleted_at: Mapped[datetime\|None]` |
| Optimistic Lock | `version: Mapped[int] = mapped_column(default=1)` |
| Tenant Isolation | `lab_id` on all patient-data tables |
| Audit | All mutations logged to `audit_logs` table |

### Migration Standards

- Every migration must be a new Alembic revision
- Existing migrations must NEVER be modified
- Migrations must be idempotent (use `_has_column()`, `_table_exists()`, `_index_exists()` guards)
- New columns must be nullable or have `server_default`
- Every migration must have a downgrade path
- CI enforces round-trip migration testing

### Query Standards

- N+1 queries must be avoided (use `selectinload` / `joinedload`)
- All queries must filter by `lab_id` for tenant isolation
- Use parameterized queries (never string formatting)
- Slow queries (>200ms) must be logged and optimized
- Statement timeout: 30s default

## 4. Security Standards

### Authentication

- JWT-based authentication with HS256
- Access token TTL: 15 minutes
- Refresh token TTL: 7 days
- Refresh token rotation on use
- Blacklisted tokens invalidated in Redis
- Rate limiting on login: 10 requests/minute

### Authorization

- RBAC with 9 roles × 13 permissions
- ABAC for tenant isolation
- Permission version for fast invalidation
- Service accounts for machine-to-machine

### Data Protection

| Data Type | Protection |
|-----------|-----------|
| Passwords | bcrypt hashing |
| National ID | Fernet encryption (NID_HMAC_KEY) |
| PII | Fernet encryption (ENCRYPTION_KEY) |
| Patient Card | HMAC-signed tokens |
| API Keys | Hashed at rest |

### Secrets Management

- No default/fallback secrets (hard fail on missing)
- Weak secret detection at startup
- All secrets from environment variables
- Secret rotation scripts available
- Production secrets never in code

## 7. Logging Standards

### Structured Logging

```json
{
  "timestamp": "2026-07-18T10:30:00Z",
  "level": "INFO",
  "logger": "app.routes.patients",
  "request_id": "req_abc123",
  "endpoint": "GET /api/v1/patients/{id}",
  "user_id": "usr_456",
  "lab_id": "lab_789",
  "message": "Patient retrieved",
  "elapsed_ms": 42,
  "extra": {}
}
```

### Log Levels

| Level | Usage |
|-------|-------|
| DEBUG | Development only, not in production |
| INFO | Normal operations, request lifecycle |
| WARNING | Unexpected but handled issues |
| ERROR | Failures requiring investigation |
| CRITICAL | System-level failures (DB down, out of memory) |

### Security Logging

- All authentication attempts (success and failure) must be logged
- All authorization failures must be logged
- All patient data access must be logged
- All configuration changes must be logged
- All privilege escalations must be logged

## 8. Error Handling Standards

### API Error Response Format

```json
{
  "detail": "Patient not found",
  "detail_ar": "المريض غير موجود",
  "code": "PATIENT_NOT_FOUND",
  "request_id": "req_abc123"
}
```

### HTTP Status Codes

| Code | Usage |
|------|-------|
| 200 | Success |
| 201 | Created |
| 204 | No content (successful delete) |
| 400 | Bad request (validation failure) |
| 401 | Unauthorized (not authenticated) |
| 403 | Forbidden (not authorized) |
| 404 | Not found |
| 409 | Conflict (optimistic lock, duplicate) |
| 413 | Request entity too large |
| 422 | Unprocessable entity (validation) |
| 429 | Too many requests (rate limited) |
| 500 | Internal server error |
| 503 | Service unavailable (degraded/starting) |

### Error Handling Principles

- Never expose stack traces in production
- Always return bilingual error messages
- Always include request_id for correlation
- Never log sensitive data in error messages
- Always log sufficient context for debugging

## 9. Versioning Standards

### Semantic Versioning (SemVer 2.0)

```
MAJOR.MINOR.PATCH
```

- **MAJOR:** Breaking changes (API, database, module contracts)
- **MINOR:** New features, backward-compatible
- **PATCH:** Bug fixes, backward-compatible

### Additional Labels

- `-alpha.N`: Internal testing
- `-beta.N`: External testing
- `-rc.N`: Release candidate

## 10. Repository Standards

### Branch Strategy

- `main`: Production-ready code
- `develop`: Integration branch
- `feature/*`: Feature branches
- `fix/*`: Bug fix branches
- `release/*`: Release preparation branches
- `hotfix/*`: Emergency production fixes

### Commit Convention

```
<type>(<scope>): <description>

[optional body]
```

**Types:** feat, fix, refactor, test, docs, chore, security, perf, ci, style

**Examples:**
- `feat(auth): add MFA TOTP support`
- `fix(lims): correct Westgard R-4s rule evaluation`
- `security(auth): rotate SECRET_KEY on role change`

## 11. Dependency Standards

### Evaluation Criteria

Every dependency must satisfy:

| Criterion | Minimum |
|-----------|---------|
| Business value | Justified need |
| Maintenance status | Actively maintained |
| License | Compatible (no AGPL without review) |
| Security | No known CVEs |
| Community | Active community or reputable vendor |
| Performance | Meets platform benchmarks |
| Compatibility | Works with existing stack |
| Long-term viability | Clear roadmap, stable API |
| Replacement strategy | Documented exit path |

### Allowed Dependencies

- **Python:** FastAPI, SQLAlchemy, Alembic, Pydantic, Pytest, httpx, Cryptography, bcrypt, PyJWT
- **Node.js:** React, tRPC, Vite, TailwindCSS, Firebase
- **Infrastructure:** PostgreSQL, Redis, nginx, Prometheus, Grafana, Docker, Kubernetes
