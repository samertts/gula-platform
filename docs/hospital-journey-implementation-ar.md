# تنفيذ مسار المستشفى في GULA

## الملخص

أضيفت بوابة عمليات مستشفى مستقلة داخل `frontend-v3` تحت `/hospital-operations`. لا تُعامل هذه البوابة باعتبارها امتداداً بسيطاً للعيادة؛ فهي تعرض Hospital Domain منفصلاً يشمل الطوارئ والإدخال والأسرة وفريق الرعاية والأوامر والعمليات والعناية المركزة وبنك الدم والخروج والتدقيق.

## ما تم تنفيذه

تقدم بوابة Demo رحلة اصطناعية ومعزولة تشمل الطوارئ والفرز، الإدخال والإقامة، مركز الأسرة، المرضى ضمن النطاق، أوامر CPOE، فريق الرعاية والتسليم، العمليات والعناية المركزة، الخروج والمتابعة، وسجل الحوكمة. لا تنشئ الواجهة مريضاً أو قبولاً أو سريراً أو نقلاً أو أمراً أو إعطاء دواء أو نقل دم أو عملية أو خروجاً.

في Live تقرأ الصفحة مساحات العمل من `GET /niam/workspaces`، ولا تقبل إلا مساحة غير شخصية مرتبطة بمنشأة وبحالة `ACTIVE` أو `VERIFIED` أو `APPROVED`. تفعيل السياق يتم عبر `POST /niam/workspaces/{workspace_id}/switch`. بعد نجاح التفعيل تستخدم الصفحة عقد القراءة السريرية canonical الحالية:

| المجال | العقد | الحالة |
|---|---|---|
| مرضى ضمن نطاق المستشفى | `GET /api/v1/clinical/patients` | قراءة محدودة بعد Clinical Context وAuthorization |
| أوامر ضمن نطاق المستشفى | `GET /api/v1/clinical/orders` | قراءة محدودة بعد Clinical Context وAuthorization |
| Hospital structure وoccupancy | عقود `/hospital/*` الحالية واسعة وغير workspace-scoped للواجهة | محجوبة من هذه البوابة |
| Admission وEmergency وTriage | لا يوجد عقد frontend آمن موحد مستخدم هنا | محجوبة |
| Bed allocation وTransfer | تحتاج state machine وIf-Match وIdempotency | محجوبة |
| Nursing وeMAR وMedication Administration | تحتاج دوراً مهنياً وسياق جناح وتحققاً | محجوبة |
| OR وICU وBlood Bank | Domains متخصصة تحتاج عقوداً مستقلة | محجوبة |
| Discharge وMedication Reconciliation | تحتاج كتابة سريرية وإصداراً وتدقيقاً | محجوبة |

## حدود الهوية والصلاحية

المستشفى Organization وليس User. الموظف يعمل بحسابه وهويته المهنية وعضويته ومساحة المنشأة، ولا تمنح العضوية صلاحيات الطبيب أو الممرض تلقائياً. كما أن اختيار workspace لا يكفي للوصول؛ يجب أن يعيد الخادم فحص المستخدم والمؤسسة والدور والترخيص والسياق والغرض وعلاقة الرعاية.

أضيفت سياسة دفاعية لمسار `/hospital-operations` للأدوار الموجودة فعلياً في frontend-v3: الإدارة، الطبيب، الموظف، موظف المختبر، الفني، و`demo_viewer`. لا يوجد في النموذج الحالي دور مستقل باسم Nurse أو Pharmacist أو Blood Bank Staff؛ لا يتم اختلاق هذه الأدوار من الواجهة.

## الفصل بين النطاقات

تعرض الواجهة صراحة أن `Admission` لا يساوي `Bed`، وأن `Order` لا يساوي `Performed`، وأن `Dispensing` لا يساوي `Administration`. كما لا يتحول الدفع أو رفض التأمين إلى قرار علاجي، ولا يستخدم Barcode أو Device Fingerprint بديلاً عن التحقق من الهوية. لا توجد قراءة فضولية أو بحث حر خارج سياق الرعاية.

## العمليات الحرجة المحجوبة

لم يتم تفعيل تسجيل المريض أو Identity Resolution أو Emergency Registration أو Triage أو Break-Glass أو Admission أو تخصيص السرير أو النقل أو Isolation أو Care Team أو Handover أو CPOE الكتابي أو eMAR أو إعطاء الدواء أو النتائج الحرجة أو العمليات أو التخدير أو Blood Bank أو مكافحة العدوى أو الوفاة أو Discharge أو النقل الإسعافي أو التأمين أو المطالبات أو سجل التدقيق الحي.

فتح هذه العمليات يتطلب عقود backend تفرض state machine، وRBAC سياقي، وFacility/Ward/Department Scope، وعلاقة مريض، ونسخة أو `If-Match`، و`Idempotency-Key`، ومنع Last Write Wins، وسجل تدقيق append-only. يجب أن يكون كل انتقال غير صالح فشلاً صريحاً ومسجلاً كمحاولة مخالفة.

## الذكاء الاصطناعي

علي رضا مرشد محدود داخل المستشفى. يمكنه شرح الإجراءات، وتلخيص البيانات المسموح بها، وتذكير الفريق بالمهام، واقتراح حقول ناقصة أو مسودة. لا يشخّص، ولا يعتمد عملية، ولا يوقع تقريراً، ولا يعطي Blood Product، ولا يمنح صلاحية، ولا يتجاوز Break-Glass، ولا يعدل السجل دون Workflow. أي استخدام حساس لاحقاً يحتاج تسجيل النموذج والإصدار والسياق والمستخدم والوقت والمخرجات والقرار البشري.

## Demo وOffline

Demo لا يتصل ببيانات حقيقية أو مؤسسة حية أو HIS أو RIS أو LIS أو PACS، ولا يحفظ أحداثاً سريرية. لم يتم إضافة Offline Hospital Edge أو queue للمزامنة؛ لأن ذلك يحتاج تخزيناً مشفراً ومجموعة أحداث وإعادة تحقق وتعارضاً domain-specific، ولا يجوز استخدام Last Write Wins للهوية أو التشخيص أو الوصفات أو العمليات أو التقارير.

## الاختبارات والحدود

تمت إضافة اختبارات تثبت عزل Demo عن API الحي، وتفعيل السياق قبل قراءة المرضى والأوامر، وعدم كشف معرفات المرضى، وحجب الطوارئ والإدخال والأسرة والعمليات والخروج في Live، وحراسة التنقل ضد المواطن. الفحوص المحلية لا تثبت جاهزية الإنتاج ولا تستبدل فحوص GitHub البعيدة أو تجربة PostgreSQL staging اصطناعية أو اعتماداً قانونياً وتشغيلياً.
