# Cross-lane finding-ID collision map

**Measured:** 2026-09-27, by comparing the two registers directly rather than by
reading either lane's prose.

Two hands maintain a file called `docs/architecture/GULA_MASTER_NEGATIVE_REGISTER.json`,
and they are not the same register. They share a numbering space and agree on
almost none of it.

| | |
|---|---|
| findings on `claude/p0-2-pharmacy-reconciliation` (PR #258) | **162** |
| findings on `claude/autonomous-run-1` (this lane) | **80** |
| ids present in both | **80** |
| ids where both lanes mean the **same** finding | **14** — NR-001..NR-007, NR-009..NR-015 |
| ids where they mean **different** findings | **66** |
| first divergence | **NR-008** |

So the numbering forked at the fifteenth finding and every number since has two
meanings. `NR-074` is a foreign-key topology repair here and an NHDW ORM split
there; `NR-082` is 52 unaudited EHR write routes here and a dead radiology module
there.

## What this corrects, including in my own words

Two notes in this lane's register — on NR-077 and NR-081 — say that NR-078 and
NR-080 were **deliberately left unused** so that "one number means one thing
across both hands." **That rationale is false, and it was false when written.**
Measured, 66 numbers already meant two things; skipping two of them avoided two
collisions while the same commits created seven more (NR-074, NR-075, NR-076,
NR-077, NR-079, NR-081, NR-082). The skip was cosmetic. Those two notes are
corrected in place to point here.

## Why this is not being fixed by renumbering

Renumbering is refused, and not for convenience:

* 66 findings across two lanes are referenced by number in dozens of commit
  messages, in ADR filenames (`NR-006-…md`, `NR-070-…md`, `NR-076-…md`), in test
  module docstrings, and in the bodies of two open pull requests. Those
  references are the audit trail; a renumber silently falsifies all of them.
* Neither lane owns the numbering. Resolving by "whoever renumbers first wins"
  is resolution by precedence, which the dual-hand protocol rules out — conflicts
  resolve by correctness, security, clinical safety, canonical ownership and
  evidence, none of which favours either lane's numbers.
* A renumber is wide churn across a shared artifact while two PRs are open
  against it. That is exactly the shape of change that should not be taken
  unilaterally.

## What is done instead

This map. It lets either hand translate a number it reads in the other's commit
message, PR body or queue row into the finding actually meant. It is generated by
comparing the two registers, so it can be regenerated rather than maintained.

## The decision this needs, which is not mine

Namespacing future findings per lane — `NR-AA-nnn` and `NR-MU-nnn`, or a single
lane ceding the bare `NR-nnn` space — is a convention change to a shared artifact
that both lanes and two open PRs read. It is recorded as a recommendation, not
applied. Until it is decided, **cite the branch with the number**: "NR-074 on
`autonomous-run-1`", never a bare "NR-074".
