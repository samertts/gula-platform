# دليل معالجة C11: حارس الاعتمادات الدائرية في CI

**الفرع:** `fix/ci-circular-dependency-nonregression`
**التزام التنفيذ:** `9ae7ee93aa626b06274df1894d1a552cb4eeb1fb`
**الحالة:** جاهز للتحقق في CI، لكنه **ليس** إغلاقاً نهائياً لـC11 حتى تنجح مهمة CI المسجلة على التزام محدد.

> سجل التحقق الدستوري المؤرخ 18 يوليو 2026 صنف C11 مانعاً لأنه لم يكن يوجد فحص تلقائي للاعتمادات الدائرية في مسار CI. كانت هناك مهمة تدقيق معماري مجدولة لاحقاً، لكنها لا تعمل كحارس طلب دمج تفاضلي. هذه الدفعة لا تدعي إزالة الدورات الست التاريخية، ولا تغير عتبات الجودة أو تتجاوزها.

## الضابط المضاف

أضيف `scripts/circular_dependency_nonregression.py` إلى مسار `Changed Files Quality Gate`. ينفذ الحارس محرك الامتثال المعماري نفسه على كل من base وhead في worktrees مؤقتة، ويطبع تقرير JSON. يطبع الدورات التاريخية في baseline، لكنه يفشل فقط إذا أضاف head دورة موجهة canonical جديدة.

| خاصية | الضمان |
|---|---|
| مقارنة base/head | لا تمر دورة جديدة لمجرد وجود دين تاريخي. |
| تطبيع الدورة | تساوي الدورات المعاد تدوير بدايتها، مع الحفاظ على اتجاه الاستيراد. |
| فشل مغلق | أي خطأ في Git أو parsing أو مخرج المحرك يعيد `ERROR` ورمز خروج غير صفري. |
| التقارير | يرفع CI تقرير quality وتقرير الدورات معاً حتى عند الفشل. |
| الدين التاريخي | بقيت ست دورات في baseline الحالي؛ لا يعامل الحارس وجودها كامتثال أو قبول. |

## الأدلة المحلية

| التحقق | النتيجة |
|---|---|
| اختبار وحدة الحارس | `3/3` ناجح. |
| Ruff وMyPy للملفات الجديدة | ناجحان بلا تشخيص جديد. |
| بوابة quality changed-files مقابل RC1 | **PASS**؛ Ruff `0→0` وMyPy `0→0` للملفات المتغيرة. |
| فحص YAML للـworkflow | تحليل YAML ناجح. |
| تشغيل الحارس مقابل RC1 والرأس نفسه | **PASS** مع baseline/head يساويان ست دورات و`new_cycles=[]`. |

## شروط إغلاق C11

لا يحدّث سجل الدين التقني إلى `resolved` بعد هذا الالتزام فقط. الإغلاق الصحيح يحتاج نجاح workflow المحمي من GitHub Actions على هذا الالتزام أو على مرشح لاحق يحتويه، واحتفاظ artifact لتقرير الدورات، ثم تحديث سجل التحقق الدستوري وسجل الدين بواسطة مسؤول الهندسة المخول.

إذا فشل CI بسبب دورة جديدة، يعالج الفريق التغيير الذي أحدث الدورة أو يتراجع عنه. لا يحل الفشل بإضافة bypass أو بتسجيل الدورة الجديدة كـbaseline.
