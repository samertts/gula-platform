# PI-003 — Deployment Guide

## National Applications Deployment Guide

**Version:** 2.1.0
**Platform:** @gula/national-applications

---

## 1. Build Commands

### 1.1 Prerequisites

```bash
node >= 18.0.0
pnpm >= 8.0.0
```

### 1.2 Environment Setup

```bash
# Clone and install dependencies
git clone <repo>
cd gula-platform
pnpm install

# Build shared UI platform first
cd platform/ui
pnpm build           # tsc compilation

# Build all applications
cd platform/apps

# Individual builds
pnpm --filter @gula/citizen-app build
pnpm --filter @gula/doctor-app build
pnpm --filter @gula/laboratory-app build
pnpm --filter @gula/radiology-app build
pnpm --filter @gula/pharmacy build
pnpm --filter @gula/hospital-app build
pnpm --filter @gula/nurse-app build
pnpm --filter @gula/ministry-app build

# Build update platform
cd platform/update
pnpm build           # tsc → dist/
```

### 1.3 Build Output

Each app produces a `dist/` directory:

```
dist/
├── index.html
├── assets/
│   ├── index-<hash>.js
│   ├── index-<hash>.css
│   ├── vendor-<hash>.js       (react, react-dom, router)
│   ├── ui-<hash>.js           (@gula/ui-platform, if applicable)
│   ├── charts-<hash>.js       (recharts, if applicable)
│   └── pwa-<hash>.js          (workbox, if applicable)
├── icons/
├── screenshots/
├── manifest.webmanifest
└── sw.js                      (generated by vite-plugin-pwa)
```

## 2. PWA Configuration

### 2.1 Service Worker (vite-plugin-pwa)

All apps use `registerType: 'autoUpdate'` — the service worker updates automatically when a new version is detected.

**Common configuration across all PWA apps:**

| Setting | Value |
|---------|-------|
| `registerType` | `autoUpdate` |
| `workbox.globPatterns` | `**/*.{js,css,html,ico,png,svg,woff2}` |
| API cache strategy | `NetworkFirst` with 7-day expiry |
| Image cache strategy | `CacheFirst` with 30-day expiry |
| Font cache strategy | `StaleWhileRevalidate` with 365-day expiry |
| Background sync | Enabled for transactional endpoints |

### 2.2 Manifest Configuration

Each app has a customized web manifest:

| Property | Citizen | Doctor | Lab | Radiology | Ministry |
|----------|---------|--------|-----|-----------|----------|
| `theme_color` | `#1e3a5f` | `#1e3a5f` | `#6366f1` | `#d946ef` | `#1e3a5f` |
| `display` | standalone | standalone | standalone | standalone | standalone |
| `orientation` | portrait | any | any | any | any |
| `dir` | rtl | rtl | rtl | rtl | rtl |

## 4. S3 / CloudFront Deployment

### 4.1 S3 Bucket Structure

```
s3://gula-apps-prod/
├── citizens/           → Citizen PWA
├── doctors/            → Doctor App
├── laboratories/       → Laboratory App
├── radiologies/        → Radiology App
├── pharmacies/         → Pharmacy App
├── hospitals/          → Hospital App
├── nurses/             → Nurse App
└── ministry/           → Ministry Dashboard
```

### 4.2 CloudFront Distribution

| Configuration | Value |
|---------------|--------|
| Origin | S3 bucket (website endpoint) |
| Price Class | PriceClass_All (Global) |
| Default TTL | 86400s (1 day) |
| Max TTL | 31536000s (1 year) |
| Error page (404) | /index.html (SPA routing) |
| Viewer protocol | Redirect HTTP→HTTPS |
| Allowed methods | GET, HEAD, OPTIONS |
| CORS | Enabled for api.gula.health |
| WAF | AWS WAF with SQL injection + XSS rules |

### 4.3 Deployment Commands

```bash
# Build
cd platform/apps/<app-name>
pnpm build

# Deploy to S3
aws s3 sync dist/ s3://gula-apps-prod/<app-path>/ \
  --delete \
  --cache-control "public, max-age=31536000, immutable"

# Deploy index.html with no-cache
aws s3 sync dist/ s3://gula-apps-prod/<app-path>/ \
  --exclude "*" \
  --include "index.html" \
  --cache-control "public, no-cache, must-revalidate"

# Invalidate CloudFront
aws cloudfront create-invalidation \
  --distribution-id <DISTRIBUTION_ID> \
  --paths "/<app-path>/*"
```

## 5. Performance Optimization Flags

### 5.1 Vite Build Configuration

```typescript
// vite.config.ts optimizations
build: {
  target: 'es2022',           // Modern browser target
  outDir: 'dist',
  sourcemap: true,            // Source maps for production debugging
  rollupOptions: {
    output: {
      manualChunks: {         // Code splitting
        vendor: ['react', 'react-dom', 'react-router-dom'],
        ui: ['@gula/ui-platform'],
        charts: ['recharts'],
        pwa: ['workbox-*'],
      },
    },
  },
  cssCodeSplit: true,         // Per-component CSS
  minify: 'esbuild',          // Fast, effective minification
  assetsInlineLimit: 4096,    // Inline assets < 4KB
},
```

### 5.2 Performance Targets

| Metric | Target |
|--------|--------|
| Initial JS bundle | < 120KB (gzipped) |
| Initial CSS bundle | < 30KB (gzipped) |
| Total assets | < 500KB (gzipped, excluding images) |
| Lighthouse PWA score | >= 90 |
| Lighthouse Performance | >= 85 |
| Lighthouse Accessibility | >= 95 |

## 6. Update Platform Deployment

The Update Platform (`@gula/update-platform`) is deployed as an npm package:

```bash
cd platform/update
pnpm build
npm publish --access public
```

Applications consume it as:

```json
{
  "dependencies": {
    "@gula/update-platform": "^2.1.0"
  }
}
```

## 7. CI/CD Pipeline

```yaml
# .github/workflows/deploy-apps.yml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'
      - run: pnpm install
      - run: pnpm --filter @gula/ui-platform build
      - run: pnpm --filter @gula/citizen-app build
      - run: pnpm --filter @gula/doctor-app build
      # ... for each app
      - uses: aws-actions/configure-aws-credentials@v4
      - run: ./scripts/deploy-all.sh
```

## 8. Health Check Endpoints

Each app exposes a health check at build time:

```bash
# Verify deployment
curl -I https://citizen.gula.health/
# Expected: HTTP/2 200
# Headers: content-type: text/html, service-worker-allowed: /

# Verify service worker
curl https://citizen.gula.health/sw.js
# Expected: JavaScript service worker code
```
