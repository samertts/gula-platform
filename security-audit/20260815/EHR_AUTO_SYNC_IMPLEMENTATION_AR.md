# تنفيذ تكامل EHR التلقائي في GULA

## الملخص التنفيذي

أُضيفت آلية محلية تجعل تكامل سجل التحصينات مع السجل الصحي الإلكتروني قابلاً للتفعيل تلقائياً عند توفر إعداد موصل مؤسسي مكتمل. لا يحدث التفعيل بمجرد وجود endpoint فقط؛ بل يتطلب بروتوكول FHIR R4، نسخة عقد، مرجع مادة ثقة، موافقة مسجلة، وسراً runtime خارج قاعدة البيانات. عند اكتمال هذه الشروط يتحول الموصل إلى `ready` و`enabled`، وعند غياب أي شرط يبقى `blocked` أو `not_configured`.

## ما تم تنفيذه

أُضيف نموذجا `EHRConnectorConfig` و`EHRSyncRecord`، مع migration جاهزة غير منفذة بالمعرّف `20260816_0029` بعد migration المخزون `20260816_0028`. يخزن النموذج حالة الموصل ومراجع الأسرار فقط، ولا يخزن bearer token أو الرقم الوطني أو بيانات اتصال المريض.

عند تسجيل جرعة تحصين مكتملة، تُبنى حمولة FHIR `Immunization` منزوعة البيانات المباشرة، ويُنشأ سجل مزامنة ومخرج outbox داخل المعاملة نفسها. إذا كان الموصل غير جاهز، تُحفظ الحالة `blocked` دون إرسال. وإذا كان جاهزاً، تُحفظ الحالة `queued` وتُرسل عبر عامل outbox الموجود مسبقاً، مع إعادة المحاولة عند الفشل وidempotency على مستوى المنشأة والجرعة.

أُضيفت مسارات الحالة والتهيئة والإقرار تحت `/integrations/ehr`، وأُضيفت بطاقة RTL في صفحة التكامل تعرض حالة الجاهزية والتفعيل دون عرض endpoint أو الأسرار. كما أُضيف معالج outbox يستخدم سر التشغيل `GULA_EHR_BEARER_TOKEN` من بيئة التشغيل فقط، ولا يكتب السر إلى قاعدة البيانات أو السجلات.

| البند | الحالة المحلية |
|---|---|
| فحص العقد والموافقة والثقة | منفذ |
| تفعيل تلقائي مشروط | منفذ |
| FHIR Immunization | منفذ محلياً |
| Transactional outbox | مرتبط بعامل GULA الموجود |
| إعادة المحاولة | عبر عامل outbox الحالي |
| إقرار خارجي | endpoint محمي |
| منع التكرار | منفذ بمفتاح المنشأة والجرعة |
| واجهة حالة EHR | منفذة RTL |
| موصل حكومي حقيقي | غير مفعّل |
| migration | منشأة فقط، غير منفذة |

## التحقق

نجحت اختبارات EHR المركزة **4/4**، واختبارات برنامج التحصين **8/8**، واختبارات الهوية والتحصين المشتركة **18/18**. كما نجح `TypeScript` و`ESLint` وproduction build وPWA و`compileall` للملفات الجديدة.

## طريقة التفعيل عند الربط الفعلي

يجب أولاً إنشاء إعداد EHR للمنشأة عبر مسار التهيئة المحمي، مع endpoint staging الرسمي ونسخة العقد ومرجع مادة الثقة. يجب بعد ذلك وضع السر في secret manager أو بيئة التشغيل باسم `GULA_EHR_BEARER_TOKEN`، وليس في قاعدة البيانات أو المستودع. عند وصول الإعداد الكامل يعيد فحص الجاهزية الحالة `ready` ويحول الموصل إلى `enabled` تلقائياً. أما إذا غاب السر أو العقد أو مرجع الثقة فيبقى التكامل محجوباً ولا تُرسل أي رسالة.

قبل تفعيل الإنتاج يجب اعتماد عقد FHIR، اختبار المطابقة والدمج للرقم الصحي المؤقت، تعريف endpoint الإقرار، اختبار إعادة المحاولة وdead-letter، مراجعة الصلاحيات، اختبار PostgreSQL متعدد العمال، ومراجعة أمنية في Staging. لا يُسمح بتطبيق migration أو استخدام بيانات مواطنين حقيقية أو ربط الموصل الحكومي قبل تلك المراجعة والموافقة البشرية.

## قيود مهمة

التنفيذ الحالي يثبت دورة التفعيل والتخزين والإرسال الآمن، لكنه لا يدّعي اعتماد عقد حكومي عراقي أو جدول ترميز وطني. كما أن الاختبارات استخدمت بيانات اصطناعية وسراً اصطناعياً داخل test فقط. لم يحدث اتصال بموفر EHR حقيقي، ولم يُنفذ Alembic، ولم يُجرَ commit أو push أو merge.
