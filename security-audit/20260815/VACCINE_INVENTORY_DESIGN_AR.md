# تصميم مخزون اللقاحات وسلسلة التبريد في GULA

**التاريخ:** 16 آب 2026

## قرار التصميم

سيكون مخزون اللقاحات bounded context مستقلاً عن مخزون الأدوية العام، مع إبقاء موصل التكامل الخارجي اختيارياً ومغلقاً في البيئات المحلية. السبب أن اللقاحات تحتاج lot/expiry، حالة quarantine، سجل هدر، سلسلة تبريد، وتسوية يمكن تدقيقها مع إعطاء الجرعة، بينما نموذج الصيدلية العام لا يفرض هذه القيود السريرية الخاصة.

| الكيان | الغرض | قاعدة السلامة الأساسية |
|---|---|---|
| VaccineCatalog | تعريف اللقاح ورمز المستضد ووحدة القياس | لا يُنشأ تعريف تشغيلي من واجهة عامة دون صلاحية إدارة المخزون |
| VaccineLot | رقم التشغيلة، الكمية، الصلاحية، بلد/مصنع المصدر، الحالة | lot منتهي أو محجور لا يُصرف |
| VaccineStockMovement | استلام، صرف، تحويل، هدر، تسوية | كل تغيير كمية يترك حركة غير قابلة للمحو |
| ColdChainReading | درجة الحرارة والوقت والجهاز والمنشأة | القراءة خارج المجال تنتج تنبيهاً ولا تغيّر الجرعات تلقائياً |
| VaccineWastage | فتح/انسكاب/انتهاء/كسر/تلف مع كمية وسبب | الهدر يحتاج مبرراً ومستخدماً ومراجعة |
| VaccineConsumptionLink | ربط الجرعة بالـ lot والحركة | idempotency على `administration_record_id` لمنع الخصم المزدوج |

## قواعد التشغيل

تستخدم الخدمة FEFO (الأقرب انتهاءً أولاً) عند اختيار lot، لكنها لا تختار lot محجوراً أو منتهياً أو خارج نطاق سلسلة التبريد. لا يجوز تسجيل جرعة مع خصم مخزني ناجح جزئياً؛ العملية ذرية في جلسة قاعدة البيانات، ويعاد استخدامها بأمان عند إعادة الطلب عبر مفتاح الجرعة. لا تتصل هذه الطبقة بموفر خارجي تلقائياً.

تُحسب حالة سلسلة التبريد من قراءات موثقة مع مجال مرجعي لكل تعريف لقاح. لا يصدر النظام حكماً سريرياً بصلاحية الجرعة؛ حالة الانحراف تنتج quarantine ومراجعة مسؤول اللقاحات. وتبقى قيم المجال المرجعي قابلة للضبط وفق تعليمات وزارة الصحة والشركة المصنعة، ولا تُزرع أرقام وطنية في الكود.

## أقل صلاحيات

| الصلاحية | الوظيفة |
|---|---|
| `vaccine_inventory:read` | الاطلاع على الأرصدة والدفعات وقراءات الحرارة |
| `vaccine_inventory:manage` | الاستلام والتحويل والتسوية والحجر وإدارة الكتالوج |
| `vaccine_inventory:dispense` | ربط جرعة مع lot وخصم الكمية |
| `vaccine_inventory:report` | تقارير النقص والهدر والاستهلاك وسلسلة التبريد |

لا تمنح صلاحية `immunization:administer` وحدها إدارة المخزون، ولا تمنح إدارة المخزون صلاحية تعديل بيانات المريض.

## حدود المرحلة

تتضمن هذه المرحلة النماذج، الخدمة، API، الربط idempotent مع سجل إعطاء الجرعة، واجهة RTL، والاختبارات المحلية. لا تتضمن تشغيل Alembic migration، أو اعتماد سياسة جرعات، أو مزامنة مخزون حكومي خارجي، أو بيانات حقيقية. تُنفذ هذه البنود فقط بعد مراجعة نموذج البيانات وموافقة بشرية.

## حالة التنفيذ المحلي

أُضيفت نماذج `VaccineCatalogModel` و`VaccineLotModel` و`VaccineStockMovementModel` و`ColdChainReadingModel`، وخدمة استقبال الدفعات والصرف المرتبط بسجل الإعطاء والهدر والتسوية وFEFO، إضافة إلى الحجر التلقائي للدفعات المرتبطة بجهاز خرجت قراءته عن المجال. أضيفت API محمية بنطاقات `vaccine_inventory:read/manage/dispense/report`، وشاشة RTL في `/public-health/immunization/inventory` مع مؤشرات الدفعات وقراءات التبريد.

أُنشئت migration غير منفذة `20260816_0028_vaccine_inventory_cold_chain.py` بعد `20260816_0027`. لا تُعد أرقام المجال الحراري أو أسماء اللقاحات جدول جرعات وطنياً؛ هي قيم تعريفية قابلة للضبط وتحتاج اعتماد الجهة المختصة.

اختبارات الدورة الجديدة أصبحت **8/8 ناجحة**، واختبارات الهوية والتحصين المشتركة **13/13 ناجحة**. كما نجح `tsc` و`lint` و`build` وPWA للواجهة. لم يُستخدم مخزون حقيقي، ولم تُشغّل migration، ولم يحدث اتصال خارجي أو commit أو push أو merge.

يبقى قبل التشغيل الفعلي اختبار التزامن على PostgreSQL، اعتماد إجراءات الحجر بعد انحراف التبريد، ربط عامل الإشعارات، وربط المخزون الحكومي الخارجي فقط بعد عقد تكامل ومراجعة صلاحيات وتدقيق.
