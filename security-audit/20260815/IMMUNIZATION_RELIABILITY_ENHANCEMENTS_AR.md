# تحسينات اعتمادية ومزايا برنامج التحصين

## نطاق التنفيذ

تم تعزيز برنامج التحصين في GULA ليحافظ على سجل الجرعة محلياً حتى أثناء انقطاع EHR أو الشبكة، ثم يرسلها لاحقاً عبر transactional outbox. شمل التنفيذ backoff متدرجاً مع jitter، تأجير الرسائل العالقة، hash للحمولة، تصنيف dead-letter، إعادة تشغيل مدققة، ومؤشرات تشغيلية لا تعرض بيانات شخصية.

## دورة Outbox بعد التحسين

تبدأ الرسالة بحالة `pending`، ثم ينتقل بها العامل إلى `processing` مع `lease_until`. إذا توقف العامل قبل الإكمال، تعود الرسالة إلى `failed` عند انتهاء التأجير، وتُعاد المحاولة بعد `next_attempt_at`. تزداد فترة الانتظار تدريجياً حتى سقف تشغيلي، مع jitter لتفادي اندفاع جميع العمال في الوقت نفسه. بعد استنفاد المحاولات تحفظ الرسالة كـdead-letter مع السبب ولا تُحذف.

يُحفظ `payload_hash` للتحقق من سلامة الحمولة، وتُسجل هوية من أعاد تشغيل الرسالة في `replayed_by`. لا يمكن إعادة تشغيل رسالة `done`، ولا يتغير payload عند إعادة التشغيل. يضمن ذلك at-least-once delivery مع idempotency على مستوى الجرعة، بينما تبقى المصالحة مع ACK الخارجي مطلوبة لإثبات الوصول النهائي.

| التحسين | النتيجة |
|---|---|
| `next_attempt_at` | يمنع إعادة المحاولة المتسارعة أثناء الانقطاع |
| exponential backoff وjitter | يقللان ضغط الشبكة وEHR عند عودة الخدمة |
| `lease_until` | يعيدان الرسالة التي فقدت عاملها |
| `payload_hash` | يكشف تغير الحمولة أو فسادها |
| `dead_letter_reason` | يجعل الفشل قابلاً للتصنيف والمراجعة |
| `replayed_by` | يحفظ أثر التدخل اليدوي |
| `/integrations/ehr/outbox/metrics` | يعرض backlog والعمر الأقدم والرسائل المعزولة |
| `/integrations/ehr/outbox/{id}/replay` | يتيح إعادة تشغيل مدققة بصلاحية الإدارة |

## المزايا السريرية والتشغيلية المتاحة

يتضمن برنامج التحصين بالفعل سجل الطفل والرقم الصحي المؤقت، جدولاً مرجعياً قابلاً للاعتماد، توليد الجرعات، المواعيد، سجل الإعطاء، كشف التأخر، مهام المتابعة، أسباب عدم الإعطاء، AEFI، سجل المخزون والدفعات، FEFO، الحجر، الهدر، التسوية، وقراءات سلسلة التبريد. كما تتوفر إحصاءات شهرية للجرعات المجدولة والمعطاة والمتأخرة ومعدل التسليم حسب اللقاح.

تظهر في واجهة التكامل حالة EHR والتفعيل المشروط ومؤشرات backlog وdead-letter والعمر الأقدم للرسائل، دون عرض endpoint أو token أو رقم وطني أو بيانات اتصال.

## الاختبارات

نجحت اختبارات reliability وEHR والتحصين بمجموع **15/15**، كما نجحت TypeScript وESLint وProduction Build وPWA وcompileall. استخدمت الاختبارات بيانات اصطناعية فقط، وتم اختبار التكرار، إعادة التشغيل، dead-letter، وقياس العمر دون كشف payload في المؤشرات.

## القيود قبل الإنتاج

لم تُنفذ migration `20260817_0030`، ولم يُستخدم EHR حقيقي أو bearer token حقيقي أو بيانات مواطنين. قبل الإنتاج يجب اختبار القفل والتأجير على PostgreSQL متعدد العمال، وضبط secret manager، وتفعيل التنبيهات التشغيلية، واختبار الاستعادة من النسخ الاحتياطية، وتشغيل reconciliation بين GULA وACK الخارجي، واعتماد سياسات dead-letter والاحتفاظ من الجهة المالكة.
