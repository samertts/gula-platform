# GULA Security Assessment — 2026-08-12

تحتوي هذه الحزمة على التقرير الأمني المنقح وملخص النتائج بصيغة JSON والمراجع الخارجية وحالة المعالجة. أُزيلت منها قيم الأسرار وبيانات الاعتماد والمخرجات الخام التي قد تكشف معلومات حساسة. التقييم كان مصرحاً به، غير مؤثر، ولم يتضمن تسجيل دخول أو استغلالاً أو استخراج بيانات مستخدمين.

المرجع الرئيسي هو `security-assessment-report.md`. قبل نشر هذا المجلد للعامة، يجب التأكد من أن المستودع خاص وأن صلاحيات الوصول إليه مناسبة لطبيعة التقرير.

## الإصلاحات المطبقة في هذا التحديث

- توحيد Workflow النشر مع `frontend-v3` وإضافة فحص typecheck/build وLighthouse دون إخفاء فشل الخطوات.
- توحيد متغيرات API في عميل `frontend-v2` مع دعم `VITE_API_BASE_URL` و`VITE_API_BASE`، وإبقاء المسار الافتراضي عبر `/api`.
- نقل استدعاءات Gemini المباشرة في الواجهة القديمة إلى بوابة الخلفية `/api/ai/v2/orchestrate` وإزالة تبعيات Google AI وتعليمات المفاتيح من الحزمة.
- تحديث Android وiOS لاستخدام نطاق API الإنتاج الرسمي، وإزالة certificate pins الوهمية، ووضع pin عام متحقق للنطاق الرسمي فقط.
- إضافة `wss://api.gula-platform.org` إلى `connect-src` في CSP لدعم WebSocket الإنتاجي.
- إضافة إعداد Lighthouse إلى `frontend-v3` بعد توحيد مسار البناء المنشور.

## عناصر تتطلب إجراءً تشغيلياً خارج Git

- تدوير وإبطال كل الأسرار التي ظهرت في تاريخ Git، بما في ذلك مفاتيح API وJWT وقواعد البيانات وأي شهادات أو رموز جلسات.
- مراجعة تنبيهات Dependabot وتحديث التبعيات المتأثرة قبل الإطلاق.
- إضافة pin احتياطي متحقق إلى تطبيقات الهاتف قبل تدوير شهادة API، وإجراء اختبار اتصال على نسخ release موقعة.
- تنفيذ اختبار authenticated في بيئة Staging للتحقق من RBAC وIDOR وMFA ورفع الملفات وتجديد الجلسات؛ هذه العناصر لم تُختبر في الفحص غير المؤثر.

## التحقق المحلي

تم التحقق من `frontend-v2` و`frontend-v3` باستخدام TypeScript، وبُنيت `frontend-v3` بنجاح، كما تم التحقق من صحة JSON في `vercel.json`. لم يُعتبر وجود كلمة `Gemini` في نصوص واجهة المستخدم دليلاً على كشف مفتاح؛ المهم أن المصدر والحزمة لا يحتويان على استدعاء مباشر لمكتبة Google AI أو متغير مفتاح Gemini.
