# GULA Platform — سجل التشغيل والمحادثة المنقح

**المالك والتفويض:** أكد مالك المنصة تفويض اختبار الموقع والمستودع والتطبيقات. نُفذت المراجعة ضمن نطاق المنصة المملوكة فقط.

**النطاق:** الموقع العام `https://www.gula-platform.org`، مستودع `samertts/gula-platform`، الواجهة، API، تطبيقات Android وiOS وdesktop، وملفات CI/CD والبنية المعلنة في المصدر.

## ملخص ما طُلب وما نُفذ

طُلب إجراء فحص أمني شامل قبل الإطلاق يشمل المراجعة الخارجية، تحليل سطح الهجوم، فحص المستودع، مراجعة تطبيقات الهاتف، توثيق النتائج، ورفع المواد والإصلاحات إلى GitHub. نُفذت مراجعة خارجية غير مؤثرة، وتحليل ساكن للمصدر والإعدادات والتبعيات، ثم طُبقت إصلاحات دفاعية محددة في مسار النشر والواجهات وتطبيقات العميل.

لم تُرسل بيانات اعتماد، ولم تُستخرج بيانات مستخدمين، ولم تُنفذ عمليات تغييرية على الخدمة، أو استغلال فعلي، أو تصعيد صلاحيات. لذلك لا يمثل هذا السجل شهادة اختراق كاملة؛ وتبقى اختبارات authenticated وRBAC/IDOR وMFA ورفع الملفات وتجديد الجلسات مطلوبة في Staging بحسابات اختبار.

## النتائج والإصلاحات

| المجال | ما تم توثيقه | الإجراء المنفذ | الحالة |
|---|---|---|---|
| أسرار Git التاريخية | ظهرت ملفات بيئة في تاريخ Git السابق | لم تُرفع القيم؛ أوصي بالإبطال والتدوير والتدقيق | يحتاج إجراء تشغيلي عاجل |
| SPA وVercel | مسارات عميقة مثل `/login` كانت تعيد 404 مباشرة | إضافة rewrite إلى `index.html` وتوحيد مخرجات `frontend-v3` | يحتاج تحققاً بعد النشر |
| ترويسات HTTP | عدم اتساق الترويسات بين استجابات HTML و404 | إضافة CSP وترويسات hardening موحدة في `vercel.json` | يحتاج تحققاً بعد النشر |
| Workflow | انقسام بين `frontend-v2` و`frontend-v3` ومتغيرات Vite ومسارات artifacts | توحيد Workflow مع `frontend-v3` وإضافة lint/typecheck/tests/build وفحص الأسرار | أُصلح في المصدر |
| Gemini في المتصفح | وجود مسارات استدعاء مباشرة محتملة لمزود AI | تحويل الاستدعاءات إلى بوابة الخلفية وإزالة تبعيات Google AI من الواجهة | أُصلح في المصدر |
| تطبيقات الهاتف | pins تجريبية ونطاقات API غير متسقة | تحديث Android وiOS إلى النطاق الرسمي وبصمات عامة متحققة | يحتاج signed build |
| تطبيق desktop | interceptor كان يوحي بالتحقق دون فحص native فعلي | تحويله إلى fail-closed وتوحيد عنوان API | يحتاج native runtime validation |

## الاختبارات المنفذة

نجحت فحوصات JSON وVercel و`git diff --check`، كما نجحت فحوصات lint وTypeScript وbuild للواجهتين. لم تتوفر أدوات أو بيئة تشغيل كاملة لـGradle وFlutter وiOS داخل بيئة التنفيذ، ولذلك يجب استكمال البناء الموقّع واختبارات التشغيل في CI أو بيئة التطوير.

## المواد المرفوعة

توجد المواد المنقحة في `security-audit/2026-08-12/`، وتشمل التقرير الفني، ملخص النتائج JSON، سجل المعالجة، المراجع، وملف التشغيل الحالي. رُفعت التحديثات إلى فرع `main` في الالتزام الأخير الناتج عن إصلاحات الأمن والنشر.

## مواد مستبعدة عمداً

لم تُرفع قيم الأسرار التاريخية، أو ملفات `.env`، أو رموز الوصول، أو سجلات الطرفية الخام، أو أي بيانات مستخدمين. هذا الاستبعاد مقصود لحماية المنصة؛ ويمكن الاحتفاظ بهذه المواد محلياً فقط عند الحاجة للتحقيق الداخلي وبضوابط وصول مناسبة.

## الإجراءات المتبقية قبل الإطلاق

يجب إبطال وتدوير الأسرار التاريخية، ومعالجة تنبيهات التبعيات، وتنفيذ smoke tests بعد النشر لمسارات SPA وCSP وWebSocket، ثم إجراء اختبار Staging موثّق للمصادقة والصلاحيات وتجديد الجلسات ورفع الملفات. لا يُنصح باعتبار المنصة جاهزة للإطلاق الإنتاجي قبل إغلاق هذه البنود أو قبول مخاطرها رسمياً.
