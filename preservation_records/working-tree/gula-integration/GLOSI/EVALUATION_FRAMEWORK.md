# GLOSI Evaluation Framework

**Version:** 1.0.0
**Date:** 2026-11-15
**Scale:** 100 points
**Status:** Established (Phase 1)

---

## 1. نطاق التقييم

يُقيَّم كل مورد عبر تسعة أبعاد. الدرجة الكلية لا تُحتسب إلا عند توفر دليل كافٍ لكل بُعد. الدرجة العالية **لا تتجاوز** عائقاً قانونياً أو أمنياً حرجاً.

## 2. الأوزان

| المعيار | المفتاح | الوزن |
|---|---|---:|
| الوظائف والملاءمة الصحية | `functionality_fit` | 15 |
| النضج والاستقرار | `maturity_stability` | 15 |
| الأمن والخصوصية | `security_privacy` | 15 |
| التوافق والتكامل | `interoperability` | 15 |
| جودة الهندسة والاختبارات | `engineering_quality` | 10 |
| الترخيص والاستدامة القانونية | `license_sustainability` | 10 |
| الاعتمادية وقابلية التوسع | `reliability_scalability` | 10 |
| التكلفة والصيانة | `cost_maintenance` | 5 |
| ملاءمة البيئة العراقية | `iraqi_context` | 5 |
| **المجموع** | | **100** |

الصيغة:
```
weighted_total = Σ (dimension_score × weight) / 100
```
تُقارب النتيجة إلى عدد صحيح واحد. المدقق يحسبها ويتحقق من التطابق.

## 3. التصنيف

| النطاق | التصنيف | المعنى |
|---|---|---|
| 90–100 | ممتاز (`excellent`) | مرشح قوي جداً بعد اكتمال المراجعات |
| 80–89 | مرشح قوي (`strong_candidate`) | يستحق دراسة تكامل مفصلة |
| 70–79 | يحتاج تحققاً إضافياً (`needs_verification`) | فجوات أدلة أو مخاطر تحتاج معالجة |
| 60–69 | دراسة محدودة (`limited_study`) | فائدة محدودة أو مخاطر أعلى |
| <60 | غير موصى به (`not_recommended`) | لا يُعتمد |

## 4. مستويات الثقة

| المستوى | الشرط |
|---|---|
| `HIGH` | أدلة رسمية حديثة (≤90 يوماً) لكل الأبعاد + مراجعة أمنية وقانونية بشرية |
| `MEDIUM` | أدلة رسمية لمعظم الأبعاد، مع فجوات ثانوية موثقة |
| `LOW` | بيانات وصفية أو مصادر ثانوية فقط؛ لا مراجعة أمنية/قانونية |

**الدفعة الأولى:** كل السجلات `PARTIAL` و`LOW`، لذلك لا درجة كلية ولا اعتماد.

## 5. قواعد الأدلة

### مقبول كدليل
- المستودع الرسمي وملف LICENSE/NOTICE.
- صفحة الإصدارات الرسمية أو GitHub Releases API.
- سياسة الأمن/الإفصاح الرسمية.
- وثائق المطوّر الرسمية والمعايير الدولية.
- تقارير مراجعة مستقلة أو أدلة إنتاج منشورة.
- SBOM أو نشرية CVE رسمية.

### غير مقبول كدليل
- مقالات دعائية أو تسويقية.
- عدد النجوم/التنزيلات وحده.
- ادعاء "مستخدم في دول كثيرة" دون رابط.
- نسخة غير رسمية أو Fork غير موثوق.
- ذكاء اصطناعي كمرجع وحيد.

### قواعد صارمة
1. لا درجة بلا رابط دليل.
2. `UNKNOWN` تُسجل كما هي؛ لا تُحوَّل إلى 0 ولا إلى درجة كاملة.
3. لا يُقبل الدليل الأقدم من 12 شهراً لحالة الصيانة أو الإصدار، إلا مع وسم `STALE`.
4. لا تُجمع درجات من سجلات مختلفة أو إصدارات مختلفة دون توثيق.
5. درجة كل بُعد لا تزيد عن 100.

## 6. مقياس كل بُعد

| البُعد | 0–20 | 21–40 | 41–60 | 61–80 | 81–100 |
|---|---|---|---|---|---|
| الوظائف | لا يغطي الحاجة | تغطية جزئية كبيرة | تغطية أساسية مع فجوات | تغطية جيدة قابلة للتكيف | تغطية مباشرة موثقة |
| النضج | تجريبي/مهجور | إصدارات نادرة | نشط مع مخاطر | مستقر ومنتج | ناضج واسع الانتشار |
| الأمن | خطر حرج/غير معروف | ضوابط ضعيفة | ضوابط أساسية | ضوابط جيدة + إفصاح | مراجعة أمنية مستقلة |
| التكامل | لا توافق | توافق ضعيف | واجهات عامة | معايير صحية | معايير + عقود موثقة |
| الهندسة | بلا اختبارات | اختبارات محدودة | CI أساسي | تغطية واختبارات جيدة | جودة عالية موثقة |
| الترخيص | غير متوافق/مجهول | قيود كبيرة | يحتاج مراجعة | متوافق مع شروط | متوافق OSI واضح |
| الاعتمادية | غير معروف | مخاطر عالية | أساسي | تحمل أخطاء | HA/DR موثق |
| التكلفة | مرتفعة جداً | مرتفعة | متوسطة | منخفضة | منخفضة ومستدامة |
| السياق العراقي | غير مناسب | يحتاج تغييراً جوهرياً | يحتاج تكييفاً | مناسب مع تعديل | مناسب ومحلي بالكامل |

## 7. شروط الاستبعاد الإلزامية

أي شرط منها يمنع `ADOPT`/`INTEGRATE`/`ADAPT` حتى لو كانت الدرجة 100:
1. ترخيص غير متوافق أو غير محدد.
2. خطر أمني حرج غير معالج أو ثغرة نشطة بلا خطة.
3. عدم وجود مصدر رسمي يمكن التحقق منه.
4. توقف الصيانة دون بديل مستدام.
5. مخالفة خصوصية صحية أو عدم إمكانية الاستضافة المحلية.
6. عدم وجود خطة استبدال/رجوع.
7. تجاوز صلاحيات GULA أو فرض هوية خارجية تلقائياً.
8. بيانات مرضى حقيقية أو اعتماد على خدمة سحابية إلزامية مدفوعة.

## 8. إجراء التقييم

1. تحقق من المصدر والهوية والإصدار.
2. راجع الترخيص وNOTICE/التبعيات.
3. راجع الأمن وCVE وSBOM وسياسة الإفصاح.
4. راجع البنية والتوافق والتكامل.
5. قيّم الوظائف مقابل GULA (لا مقابل قائمة ميزات تسويقية).
6. قيّم الاختبارات وCI والصيانة.
7. قيّم التكلفة الكلية (ترخيص + تشغيل + تدريب + صيانة + ترحيل).
8. قيّم السياق العراقي (لغة، أجهزة، اتصال، استضافة، كفاءات).
9. سجّل الدرجات والأدلة ومستوى الثقة.
10. اكتب قراراً مقترحاً وسببه؛ لا تعتمد.

## 9. إعادة التقييم

يجب إعادة التقييم عند:
- إصدار رئيسي أو تغيير جوهري في الوظائف.
- تغيّر الترخيص أو NOTICE.
- CVE حرج أو اختراق أو نشرية أمنية.
- توقف الصيانة > 12 شهراً.
- تغيّر متطلبات GULA أو السياق العراقي.
- اكتشاف دليل يناقض تقييماً سابقاً.

يُضاف التقييم الجديد إلى `evaluation_history` ولا يُحذف القديم.

## 10. الفصل بين الدرجة والقرار

- الدرجة أداة مقارنة، وليست إذناً.
- القرار يتطلب مراجعة بشرية وتوثيق ADR عند الدمج.
- يمكن رفض مشروع عالي الدرجة لسبب قانوني أو أمني أو سيادي.
- يمكن قبول مشروع متوسط الدرجة إذا كان يغطي حاجة حرجة بلا بديل، مع توثيق الاستثناء.
