# GLOSI Governance

**Version:** 1.0.0
**Date:** 2026-11-15
**Status:** Established (Phase 1)
**Parent authority:** `GOVERNANCE/GULA_STABLE_V1_PROGRAM_CHARTER.md`, `AI_OPERATING_CONSTITUTION.md`

---

## 1. المبدأ الحاكم

GLOSI طبقة **بحث وتقييم وحوكمة** مستقلة منطقياً عن GULA Core. وجود سجل في GLOSI لا يمنح أي إذن بتعديل GULA. القرار الملزم للدمج يبقى قراراً معمارياً في GULA بعد مراجعة بشرية وADR، وليس قراراً آلياً من GLOSI.

```
GLOSI Registry → Evidence → Evaluation → Governance Review → ADR → GULA Decision → Approved Integration → Testing
```

## 2. الأدوار والمسؤوليات

| الدور | المسؤولية | سلطة القرار |
|---|---|---|
| **GLOSI Program Owner** | إدارة البرنامج والسجل والمراجعات الدورية | قبول/رفض إدخال سجل، إحالة القرار |
| **Technical Reviewer** | التحقق من الوظائف والبنية والتكامل والاختبارات | توصية فنية؛ لا يعتمد قانونياً أو أمنياً |
| **Security Reviewer** | تقييم نموذج الأمن، CVEs، الاعتماديات، SBOM، التدقيق | **حق نقض** لأي خطر أمني حرج |
| **Legal Reviewer** | الترخيص، التوافق، حقوق إعادة التوزيع، البراءات | **حق نقض** لأي مانع قانوني |
| **Clinical Safety Reviewer** | الملاءمة السريرية والمخاطر على المريض (عند الاقتضاء) | **حق نقض** لأي خطر سريري غير معالج |
| **Architecture Authority (GULA)** | قرار الدمج النهائي وADR | الاعتماد النهائي داخل GULA |
| **Program Director** | فضّ النزاعات وتفويض الاستثناءات | الاستثناء النهائي الموثق |

**قاعدة الفصل:** لا يجوز أن يكون مقدّم الطلب هو نفسه المراجع الأمني أو القانوني لنفس السجل. لا مراجعة ذاتية.

## 3. الصلاحيات والقيود

### مسموح
- إنشاء وتحديث سجلات البحث والأدلة.
- تشغيل المدقق والاختبارات محلياً.
- اقتراح قرارات غير ملزمة (`PROPOSED`).
- إعداد تقارير ومراجعات دورية.
- إضافة مصادر عامة مجانية.

### ممنوع دون مراجعة بشرية صريحة
- اعتماد `ADOPT` أو `INTEGRATE` أو `ADAPT`.
- استيراد كود خارجي إلى `backend/` أو `frontend-v3/` أو أي مكوّن تشغيلي.
- تغيير قاعدة بيانات أو migrations أو API أو هوية أو صلاحيات.
- إضافة اعتمادية جديدة إلى ملفات المشروع.
- تفعيل خدمة خارجية أو مفتاح API أو مزوّد مدفوع.
- تعديل `Platform-Core` أو GULA Core.
- إصدار قرار قانوني أو أمني نهائي.

### صلاحيات الوكلاء الآليين
- يجوز للوكيل جمع الأدلة وتشغيل التحقق المحلي وتحديث ملفات GLOSI.
- لا يجوز للوكيل إصدار قرار اعتماد نهائي أو تجاوز مراجع بشري.
- كل ادعاء يحتاج تاريخ تحقق ومرجعاً قابلاً للنقر.
- أي `UNKNOWN` يبقى `UNKNOWN`؛ لا يُملأ بالتخمين.

## 4. دورة حياة السجل

```
DRAFT → SOURCE VERIFIED → UNDER REVIEW → EVALUATED → DECISION PROPOSED → APPROVED / REJECTED / DEFERRED → RE-EVALUATE
```

| الحالة | المعنى |
|---|---|
| `DRAFT` | سجل غير مكتمل، لا يُستخدم كدليل |
| `SOURCE_VERIFIED` | المصدر الرسمي والإصدار والترخيص تم التحقق منه |
| `UNDER_REVIEW` | مراجعة فنية/أمنية/قانونية جارية |
| `EVALUATED` | تقييم مكتمل بالأدلة والثقة |
| `DECISION_PROPOSED` | قرار مقترح غير ملزم |
| `APPROVED` | قرار ملزم بعد مراجعة بشرية وADR |
| `REJECTED` | مرفوض مع سبب موثق |
| `DEFERRED` | مؤجل مع شرط إعادة التقييم |

## 5. قواعد الاعتماد

1. لا انتقال إلى `APPROVED` دون مكتمل: المصدر، الترخيص، الأمن، البنية، الوظائف، التكلفة، والسياق العراقي.
2. لا اعتماد بترخيص مجهول أو غير متوافق.
3. لا اعتماد مع خطر أمني حرج غير معالج.
4. لا اعتماد على شهرة المشروع أو عدد النجوم.
5. يجب ربط كل اعتماد بـADR أو قرار GLOSI مرقم.
6. يجب أن يكون الدمج قابلاً للتتبع والتراجع، ومكوّن خارجي قابل للاستبدال.
7. يجب توثيق البدائل التي رُفضت وسبب الرفض.
8. يجب إعادة التقييم عند تغيّر الإصدار أو الترخيص أو حالة الصيانة أو ظهور CVE حرج.

## 6. إدارة التعارض والاستثناءات

- أي تعارض بين GLOSI وسياسة GULA يُحل لصالح سياسة GULA والـADR المعتمد.
- أي استثناء لسياسة الترخيص أو الأمن يتطلب قراراً موثقاً من Program Director مع تحليل مخاطر وخطة رجوع.
- الاستثناء لا يغيّر تصنيف المخاطر في السجل؛ يبقى موثقاً.

## 7. المراجعة الدورية

| النوع | التكرار المقترح | الحدث المؤدي |
|---|---|---|
| مراجعة إصدار | عند كل إصدار جديد | Release feed (يدوي الآن) |
| مراجعة أمنية | ربع سنوية أو عند CVE حرج | نشرية أمنية |
| مراجعة ترخيص | عند تغيّر الترخيص | LICENSE / NOTICE |
| مراجعة صيانة | نصف سنوية | توقف commits/releases |
| مراجعة اكتمال | قبل كل مرحلة GULA | طلب معماري |

لا تشغّل GLOSI مراقبة آلية أو خدمات خارجية في هذه المرحلة. آلية التحديث اليدوي والأدلة موثقة في `ROADMAP.md`.

## 8. الاحتفاظ بالأدلة

- الأدلة المستخرجة من واجهات GitHub API أو المواقع الرسمية تُحفظ كملخصات في `REPORTS/evidence/` مع التاريخ وطريقة الاستخراج.
- لا تُحفظ أسرار أو رموز وصول أو بيانات مرضى.
- لا يُحذف تقييم سابق؛ تُضاف نسخة جديدة إلى `evaluation_history`.
- قرارات الاعتماد والرفض لا تُحذف؛ تُستبدل بحالة `SUPERSEDED` عند الحاجة.
