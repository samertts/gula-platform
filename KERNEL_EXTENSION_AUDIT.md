## 0. Executive Summary

This audit examines the current Enterprise AI Kernel and the surrounding
governance, knowledge, registry, deployment, and interface infrastructure to
scope the eight extension systems of GULA-KERNEL-EXT-001: Plugin SDK, Policy
Engine, Compatibility Framework, Migration Framework, Enterprise Event Bus,
Workflow Engine, AI Marketplace, and Continuous Evolution System.

**Verdict:** The Kernel (GULA-KERNEL-001) is healthy and all 19 phases pass.
All 8 extension systems are **new responsibilities** — none exist today.
Four dormant constitutions already define the required behavior and MUST be
used as authoritative policy input: `16_EVENT_CONSTITUTION.md`,
`17_PLUGIN_CONSTITUTION.md`, `18_WORKFLOW_CONSTITUTION.md`, and
`docs/constitution/23_BACKWARD_COMPATIBILITY.md`. The extensions therefore
compose existing policy, never duplicate it.

**Findings:** 8 gaps (one per extension) + 4 structural reuse anchors.
**Recommended approval:** PROCEED to Phase 1 (Plugin SDK).

## 5. Engine Interfaces Audit

The interface contract is centralized in `scripts/kernel/core.py`:

| Interface | Location | Coverage |
|---|---|---|
| Kernel 16-field contract | `scripts/kernel/contract.py` | inputs, outputs, events, errors, artifacts, ownership, dependencies, health, progress, checkpoint, capabilities, resources, timeout, retry, version, status |
| Engine registry | `scripts/kernel/core.py::ENGINE_REGISTRY` | 7 engines, full contract each |
| Governor contract | `scripts/governor/engine_contract.py` | 10-field governance contract |
| Ownership | `scripts/governor/authority.py` | authority chain + single-owner resolution |
| Matrices | `scripts/kernel/registry.py` | 7 matrices derived from ENGINE_REGISTRY |

**Gap:** there is **no Plugin Manifest / Plugin interface** in the registry.
Engines are static dict entries, not installable artifacts. Phase 1 (Plugin
SDK) must define a manifest schema (name, version, lifecycle, permissions,
capabilities, dependencies, resources, health) that is a **superset of the
existing contract fields** so existing engines become plugins without
rewriting the registry.

| Phase | System | Location | Reuses |

| 1 | Plugin SDK | `.ai/core/sdk/` + `scripts/kernel/ext/plugin.py` | `kernel/core.py`, `governor/authority.py` |

| 5 | Event Bus | `scripts/kernel/ext/event_bus.py` | `kernel/observability.py`, `16_EVENT_CONSTITUTION.md` |
| 6 | Workflow | `scripts/kernel/ext/workflow.py` | `kernel/scheduler.py`, `governor/decision_governance.py`, `18_*` |
| 7 | Marketplace | `scripts/kernel/ext/marketplace.py` | `.ai/core/**`, `auto_registry.py` |

**Architecture decision:** extensions live under `scripts/kernel/ext/`
as a new Kernel package `scripts/kernel/ext/__init__.py`, plus knowledge
artifacts under `.ai/core/sdk/` and `.ai/core/policies/`. The Kernel CLI
gains commands via a new `scripts/kernel/ext/cli.py` integrated into
`scripts/kernel.py` (or a dedicated `kernel-ext` command) — no bypass, no
separate ad-hoc scripts.

|---|---|---|

| Auto-evolution violating approval rules | HIGH | Phase 8 NEVER auto-modifies; always produces RFC only |
