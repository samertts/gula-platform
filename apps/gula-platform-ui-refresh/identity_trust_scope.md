# نطاق الهوية السيادية والثقة في GULA

## القرار المعماري

لا تُبنى GULA كنسخة بديلة من قواعد بيانات الدولة أو كخزان موحّد لكل معلومات المواطن. تُعامل المنصة بوصفها **طبقة هوية وثقة** تربط معرف GULA بسجل أدلة ومصادر تحقق وقرارات تفويض وموافقة، مع فصل واضح عن البيانات السريرية والمالية والتحليلية.

## المبادئ الملزمة

| المبدأ | القاعدة التطبيقية |
|---|---|
| تقليل البيانات | لا يطلب أو يشارك أو يحتفظ إلا بالبيانات اللازمة لغرض محدد ومصرح به. |
| مصدر قابل للتتبع | لكل سمة هوية مصدر وطريقة إثبات وتاريخ تحقق ودرجة ثقة وصلاحية ومدة احتفاظ وسياسة وصول. |
| OCR ليس تحققًا | القراءة الآلية للوثيقة تنتج بيانات مستخرجة فقط ولا تمنح حالة تحقق رسمي. |
| لا افتراض لـNFC | لا يُفترض شكل شريحة أو مفاتيح أو API للبطاقة الوطنية؛ يظل ذلك خلف موصل رسمي معتمد عند توفره. |
| عزل البيانات الحساسة | لا تُخزن البيانات البيومترية والوثائق الخام والحالة الصحية في كيان مواطن شامل؛ تفصل حسب المجال والسياسة. |
| لا تكامل حكومي بلا تخويل | لا سحب أو نسخ أو تجميع من مصدر حكومي إلا عبر تكامل مصرح به ومعزول خلف بوابة أو موصل. |
| تفويض خلفي | الموافقة والغرض وسبب الوصول والسجل التدقيقي عوامل تحددها خدمات وسياسات قابلة للتدقيق، لا عناصر واجهة فقط. |

## نموذج واجهة مطلوب عند وجود العقد الداعم

يمكن لواجهة الهوية أن تعرض حالة التحقق ودرجة الثقة وتاريخها وانتهاءها، ومصدر السمة وسبب الوصول الممنوح، وسجل الوصول، والموافقات، والتفويضات، وطلبات التصحيح أو التصدير. ولا تظهر واجهة تحقق وطنية أو OCR أو NFC أو مطابقة حيوية أو ادعاء اتصال حكومي قبل ربطها بعقد خدمة مصرح ومختبر.

## حدود التنفيذ الحالي

يقتصر هذا العمل في مرحلته الحالية على التدقيق والتصميم المدعوم بالدليل. أي تنفيذ لاحق يجب أن يميّز بوضوح بين: بيانات أدخلها المستخدم، وبيانات مستخرجة من وثيقة، وبيانات تم التحقق منها من مصدر موثوق، وبيانات تتطلب إعادة تحقق أو انتهت صلاحيتها.
