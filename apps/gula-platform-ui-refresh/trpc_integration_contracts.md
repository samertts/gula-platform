# طبقة tRPC لعقود GULA ذات الأولوية

## نطاق الربط النطاقي

يربط هذا الإصدار طبقة tRPC بعقد **سياق التفويض** `authorization.context.read` وبعقدي القراءة `patients.read` و`orders.read`. لا يصبح أي عقد نطاقي متاحًا لمجرد وجود رمز خدمة؛ يلزم أولًا وجود سجل خادمي نشط يربط مستخدم الواجهة بمعرّف موضوع GULA، و`lab_id`، وأي منشأة أو منظمة وتعيين مرتبطين به. لا تقبل الطبقة معرف مختبر من المتصفح ولا تستنتجه من دور محلي.

قبل استدعاء المرضى أو الطلبات، تقارن الطبقة هوية `GET /authz/me` بسجل الربط، ثم تتحقق من `GET /authz/me/permissions`. لا ينفذ طلب البيانات إن اختلف المستخدم أو المختبر أو المنشأة، أو إذا غابت `patients:read` أو `orders:read`. يجب أن يكون رمز الخدمة مستخدمًا مفوضًا ومطابقًا لمعرّف GULA الموثق في الربط؛ الرمز التقني المشترك غير المناسب للهوية لا يمر بهذه الحماية.

| إجراء tRPC | العقد الخلفي | الحماية في تطبيق العرض | ما يعيده للواجهة |
|---|---|---|---|
| `integration.connectionStatus` | `authorization.context.read` | عام؛ لا يتصل بالشبكة ولا يكشف أي إعداد | حالة تهيئة آمنة فقط |
| `integration.verifyAuthorizationContext` | `authorization.context.read` | مدير التطبيق فقط | نتيجة تحقق خادمية مجردة دون محتوى الاستجابة |
| `workspace.status` | سجل الربط المحلي الموثق | مستخدم مسجل | حالة الربط فقط، دون معرفات مختبر أو منشأة |
| `patients.list` | `patients.read` (`GET /patients`) | جلسة مستخدم + ربط نطاقي + `patients:read` | حقول عرض دنيا فقط بعد التحقق |
| `orders.list` | `orders.read` (`GET /lims/orders`) | جلسة مستخدم + ربط نطاقي + `orders:read` | حقول عرض دنيا فقط بعد التحقق |

## إعداد النشر

تحتاج بيئة الخادم إلى المتغيرين التاليين لتصبح عملية التحقق متاحة. لا يُضاف أي منهما إلى العميل أو إلى المستودع.

| المتغير | الغرض | شرط الاستخدام |
|---|---|---|
| `GULA_BACKEND_BASE_URL` | عنوان API الخلفية المعتمدة | رابط HTTP/HTTPS صالح |
| `GULA_BACKEND_SERVICE_TOKEN` | رمز Bearer لخدمة خادمية | محدود الصلاحيات ومخصص لبيئة اختبار |

عند غياب أي متغير، ترجع الطبقة حالة **غير مُعدّ** ولا تنفذ أي طلب خارجي. وعند غياب سجل `gula_workspace_bindings` النشط، تعيد حالة **سياق المنشأة غير موثق** ولا تحاول التحقق أو قراءة بيانات المرضى والطلبات. لا تُنشأ سجلات الربط تلقائيًا ولا تُزرع بيانات اختبار؛ يجب أن يسجل مسؤول مختص دليلًا من `authz/me` وتعيينًا نشطًا قبل التفعيل. وحتى بعد اكتمال التحقق، تبقى نتيجة التحقق دليل اتصال خادمي فقط؛ لا تحل محل تفويض الخادم النهائي أو سجل المراجعة في GULA.
