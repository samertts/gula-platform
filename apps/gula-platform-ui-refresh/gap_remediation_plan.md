# خطة معالجة فجوات واجهة GULA

## ملخص القرار

يضم مسار واجهة v3 المفهرس **77 مسارًا**. تُظهر الفهرسة أن بعض أسطح المختبر الأساسية مرتبطة باستدعاءات قراءة حقيقية، في حين أن نسبة كبيرة من صفحات المنصات والقدرات والنطاق الوطني تتضمن إجراءات مرئية بلا مرجع API محلي في ملف الصفحة. كما توجد واجهات للهوية والأمان والامتثال والموافقة قد توحي بقدرات حساسة غير متاحة أو غير مربوطة بالكامل. وعليه، لا تُوسّع هذه الأسطح ببطاقات أو أزرار تجميلية؛ تُعالج أولًا بصراحة حالة القدرة وربطها بعقد تفويض وخطأ وتحميل قابل للاختبار.

## أولويات الإصلاح

| الأولوية | الفجوة | الدليل | الإجراء المسموح | معيار القبول |
|---|---|---|---|---|
| P0 | الإيحاء بتحقق هوية أو إدارة أمن أو تقارير امتثال غير موصولة | `/identity` و`/security` و`/compliance`، وعناصر تحكم بلا mutations | إخفاء الإجراء أو تعطيله بتفسير عربي واضح إلى أن يوجد عقد محدد؛ لا تُعرض حالة «موثقة» أو «تم التحقق» بلا دليل. | لا يستطيع المستخدم بدء أو افتراض تحقق/تصدير/إدارة جلسة غير مدعومة. |
| P0 | تباين إخفاء الواجهة وحماية المسار مع تفويض الخلفية | `NAV_ITEMS` و`RoleGuard` ومصفوفات دور محلية منفصلة | تعريف طبقة capabilities صريحة ذات مصدر واحد؛ الخادم يبقى جهة القرار النهائية. | المسار والإجراء يعرضان حالة منع مفهومة، والخادم يرفض الوصول المخالف. |
| P0 | غياب سجل وصول خصوصي قابل للغرض والسياق | عقد الامتثال الإداري محدود ولا يوجد عقد شخصي مؤكد | عدم تقديم «سجل وصولي» أو مركز خصوصية نهائي؛ توثيق متطلبات عقدها (subject، purpose، actor، policy، time، evidence). | لا تُعرض بيانات وصول أو خصوصية مختلقة. |
| P1 | أزرار وتقارير وإضافات ظاهرة بلا مسار تنفيذ مؤكد | الامتثال، الإدارة، والكتالوج الآلي للمسارات | ربطها بالعقد أو تحويلها إلى حالة «غير متاح في هذه النسخة»؛ لا handler صامت. | كل زر تفاعلي يملك mutation/تنقلًا/تعطيلًا مفسرًا. |
| P1 | عرض حالات تشغيلية خام | `OrdersPage` يطبع قيمة `status` كما وصلت | توحيد mapper عربي للحالات مع لون وإشارة نصية؛ يحتفظ بالقيمة الخام للتشخيص فقط. | تظهر الحالات المتفق عليها بالعربية، وتغطي القيمة غير المعروفة بحالة محايدة. |
| P1 | حالات تحميل وفراغ وخطأ غير متسقة | بعض صفحات القراءة تعالج التحميل فقط | مكوّن حالات موحد: تحميل، فارغ، خطأ، ممنوع، غير متاح، نجاح. | لكل استدعاء تجربة مرئية ومعاد محاولة آمنة عند الإمكان. |
| P2 | كثافة مسارات منصة قابلة للإيحاء بلا ربط مباشر | 77 مسارًا، وكتالوج الأسطح غير الموصولة | إخفاء من التنقل الافتراضي أو تجميع تحت «قدرات قيد التكامل» دون عمليات مزيّفة. | لا يرى الدور التشغيلي قائمة ضخمة لا تدعمه تعاقديًا. |
| P2 | خريطة الأيقونات لا تغطي كل رموز التنقل | مراجع أيقونات متعددة خارج `iconMap` | استكمال الخريطة أو اعتماد fallback موصوف باختبار مرئي. | لا توجد أيقونات بديلة مبهمة في التنقل الحساس. |

## مصفوفة الإجراءات الحساسة

| المجال | الإجراء الذي قد يتوقعه المستخدم | العقد المؤكد | وضع الواجهة الآن | القرار |
|---|---|---|---|---|
| الهوية | تحقق وطني، OCR، NFC، قياسات حيوية | لا يوجد تحقق رسمي مكتمل قابل للعرض | صفحة هوية ساكنة | منع الادعاء وإظهار حالة عدم الإتاحة فقط. |
| الموافقة | منح/سحب/فحص موافقة | `grant` و`revoke` و`check` ضمن نطاق العقد | سطح عرض عام غير متوافق | لا تُبنى شاشة كاملة قبل تثبيت subject والنطاق والمتلقي والانتهاء وسجل التدقيق. |
| الخصوصية | سجل الوصول، تصحيح، تصدير | لا يوجد عقد شخصي كامل مؤكد | غير موجود | عنصر خارطة طريق، لا واجهة نهائية. |
| الامتثال | تقرير تدقيق/أمان/FHIR وتصديره | حالة النظام وبعض عقود الخلفية الإدارية | أزرار ثابتة | ربط كل تقرير بعقد وpolicy أو تعطيله بتفسير. |
| الأمان | كلمة المرور، MFA، الجلسات، سجل الأمان | حالة أمان فقط في الصفحة المرصودة | بطاقات ثابتة | فصل كل عملية عن الحالة وربطها بعقد مستقل قبل إظهارها. |

## ترتيب التنفيذ المقترح

1. **توحيد مصدر القدرات وحالات عدم الإتاحة** قبل أي إعادة تصميم واسعة.
2. **إصلاح أسطح الثقة عالية المخاطر**: الهوية، الأمان، الموافقة، الامتثال.
3. **ترجمة وتطبيع الحالات التشغيلية** وتوحيد loading/empty/error/forbidden.
4. **ربط إجراءات المختبر الفعلية** بالقراءة ثم mutations المؤكدة واختبارات المسار.
5. **تضييق التنقل** إلى قدرات الدور والجهة والسياق، مع إبقاء صفحات المنصة في فئات إدارية فقط عند توفر الحماية.

## شروط تمنع التنفيذ

لا يُنفذ أي عمل واجهة نهائي لصفحات الهوية أو الخصوصية أو التحقق الوطني إذا لم يحدد عقد الخلفية صراحةً: حقل الموضوع، الجهة المعتمدة، مصدر الثقة، درجة الثقة أو حالة الفشل، غرض الوصول، مدة الاحتفاظ، وقاعدة التفويض. كما لا يضاف زر تصدير أو تصحيح أو موافقة أو اعتماد إلا عند وجود عملية خلفية قابلة للتدقيق واختبار رفض الوصول.
