# أساس نظام معلومات المختبر الطبي

## الهدف التشغيلي

يُبنى نظام GULA LIS كمنصة تشغيل سريري، لا كواجهة إدخال بيانات فقط. لذلك تخضع كل عملية تخص المرضى أو الطلبات أو العينات أو النتائج إلى **تفويض خادمي**، و**تحقق من الحالة الحالية**، و**سجل تدقيق ملحق فقط**. لا يجوز للواجهة اعتبار نفسها مصدر قرار الصلاحية أو الحالة.

## الأدوار الأساسية

تُختزل أدوار الإصدار الأول في خمس فئات تشغيلية واضحة، مع إمكان ربطها لاحقًا بالتفصيل الأوسع للأدوار في المستودع المرجعي. لا يمنح الدور قدرة شاملة على كل البيانات؛ ويُقيّد كذلك بنطاق المؤسسة أو المختبر المعين للمستخدم.

| الدور | نطاق البيانات | الإجراءات المصرح بها | الإجراءات المحظورة صراحة |
|---|---|---|---|
| `patient` المريض | بطاقته وطلباته ونتائجه الصادرة فقط | عرض الملف والنتائج المنشورة والتنبيهات الموجهة إليه | رؤية بيانات أي مريض آخر، إنشاء أو اعتماد طلبات أو نتائج |
| `lab_staff` طاقم المختبر | الطلبات والعينات المكلفة ضمن المختبر | تسجيل الاستلام، ربط الباركود، تحديث حالات العينة، إدخال نتيجة أولية | اعتماد النتائج أو تعديل نتيجة صادرة أو إدارة المستخدمين |
| `physician` الطبيب | المرضى والطلبات المرتبطة بنطاق مؤسسته | إنشاء الطلبات، مراجعة النتائج، اعتماد أو رفض نتيجة قيد المراجعة، الاطلاع على التنبيهات | استلام العينات أو إدارة الحسابات والصلاحيات |
| `institution_admin` مدير المؤسسة | المستخدمون والمختبرات ضمن المؤسسة | إدارة الحسابات والتعيينات، عرض التقارير، مراجعة السجل التدقيقي ضمن مؤسسته | تغيير أدوار النظام العامة أو الوصول إلى مؤسسات أخرى |
| `system_admin` مدير النظام | نطاق المنصة وفق تفويض صريح | إدارة المؤسسات، الأدوار، الإعدادات المركزية، التحقيق في سجل التدقيق | اعتماد نتيجة سريرية بصفته مديرًا، إلا إذا حُدد له دور سريري منفصل ومعتمد |

## آلة حالات الطلب والعينة والنتيجة

تُدار الحالة في الخادم وفق انتقالات محددة. عند طلب انتقال غير مسموح، يستجيب الخادم بخطأ تفويض أو تعارض، ولا يحدّث السجل، ويضيف محاولة الانتهاك إلى سجل التدقيق.

| الكيان | الحالات | الانتقالات المسموح بها | صاحب الإجراء الأساسي |
|---|---|---|---|
| الطلب | `draft`، `submitted`، `sample_pending`، `in_progress`، `result_pending_review`، `completed`، `cancelled` | مسودة ← مُرسل ← بانتظار عينة ← قيد التنفيذ ← بانتظار المراجعة ← مكتمل؛ الإلغاء قبل الاكتمال فقط وبصلاحية | الطبيب أو طاقم مُخوّل بحسب المرحلة |
| العينة | `expected`، `received`، `verified`، `processing`، `rejected`، `completed` | متوقعة ← مستلمة ← متحققة ← قيد المعالجة ← مكتملة؛ أو متوقعة/مستلمة ← مرفوضة مع سبب | طاقم المختبر |
| النتيجة | `not_started`، `entered`، `pending_review`، `approved`، `released`، `rejected` | غير مبدوءة ← مُدخلة ← بانتظار المراجعة ← معتمدة ← صادرة؛ يمكن إرجاع المُدخلة أو المراجعة للتصحيح مع سبب | طاقم المختبر للإدخال، وطبيب مُفوّض للاعتماد |

> **قاعدة سريرية حاكمة:** لا يمكن إدخال نتيجة قبل أن تصبح العينة `verified`، ولا يمكن اعتمادها إلا من دور طبيب مخول، ولا يمكن إصدارها إلا بعد اعتمادها. لا تُتجاوز هذه القواعد من الواجهة أو من حساب إداري غير سريري.

## نموذج البيانات الأولي

يبدأ الإصدار الأول بالجداول التالية. كل سجل سريري قابل للتحديث يحتوي رقم إصدار لتجنب الكتابة فوق تعديل متزامن. عمليات التعديل تقارن الإصدار المرسل بالإصدار الحالي؛ وعند اختلافهما تفشل العملية صراحة.

| المجموعة | الكيانات الأساسية | ضوابط النزاهة |
|---|---|---|
| الهوية والهيكل | `users`، `institutions`، `laboratories`، `user_role_assignments` | المعرّفات فريدة، وتقييد عضوية المستخدم بالمؤسسة والمختبر |
| السجل السريري | `patients`، `patient_medical_records` | رقم ملف داخلي فريد لكل مؤسسة، ورقم إصدار وتواريخ إنشاء وتحديث |
| سير العمل | `lab_orders`، `lab_order_tests`، `samples`، `sample_status_events` | علاقات خارجية، وقيود حالة وباركود فريد في حدود المؤسسة |
| النتائج | `test_results`، `result_review_events` | ربط نتيجة واحدة بوحدة اختبار، ومراجع إدخال ومراجعة وإصدار منفصلة |
| الإشعار والحوكمة | `critical_alerts`، `notifications`، `audit_log` | التنبيهات موجهة، والسجل التدقيقي ملحق فقط ولا تُوفّر له واجهة حذف أو تحديث |

## الخصوصية والتدقيق

كل إنشاء أو تعديل أو انتقال حالة أو محاولة وصول مرفوضة يسجل المستخدم والوقت ونوع العملية والكيان والحالة السابقة والحالة اللاحقة وسبب الرفض عند وجوده. لا تحفظ كلمات المرور أو الرموز السرية أو قيم المصادقة في السجل. تُعرض تفاصيل السجل للمديرين المخولين فقط، وتُفلتر بنطاق المؤسسة.

## تجربة اللغة والوصولية

تستخدم الواجهة العربية كلغة افتراضية مع اتجاه `rtl` كامل، وتتبدل إلى الإنجليزية واتجاه `ltr` من داخل التطبيق دون مسح حالة التنقل أو الجلسة. تسميات الحقول، حالات سير العمل، نصوص التحقق، والعناصر الرسومية يجب أن تعتمد قاموس ترجمة موحدًا، لا نصوصًا مبعثرة داخل الصفحات.

## حدود الإصدار الأول

النسخة الأولى تنفذ تدفقات المختبر المطلوبة داخل منصة الويب. الربط مع أجهزة المختبر، التبادل مع أنظمة خارجية، واستيراد النتيجة آليًا تبقى نقاط توسعة وتُبنى فقط بعد اعتماد عقود التكامل، مخطط معالجة الأخطاء، وسياسة المفاتيح.
